一、通用約定 #

本文檔定義所有和 Native 互動相關的介面，僅涵蓋主程序 yyzTools.exe 註冊的介面（src/yyztools/NativeApi.cpp 的 SetupBindings()）。

呼叫方式 #

  • 前端透過 window.Zen 物件呼叫介面函數，建議統一走 ZenAPI 封裝類別：web/lib/zen_api.js，不要在業務程式碼裡直連 window.Zen，方便升級調整介面時作為介面相容層處理。

  • 輸入：採用位置參數方式傳遞，具體參數個數和類型參考具體介面

  • 輸出：透過回傳值傳遞，值為 json 物件，包含以下內容

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error：0 正確，非 0 錯誤

    • errorMsg（可選）：錯誤訊息

    • 其他（可選）：參考具體介面

判錯方式 #

error 恆為數字：0 正確，非 0 錯誤（呼叫異常時為 -1）。

同步 / 非同步綁定 #

絕大多數介面為同步綁定（BindSync），呼叫即返回。以下 7 個介面為非同步綁定（BindAsync），在背景執行緒執行，透過 Promise 回撲，不阻塞 UI 執行緒：

getAppInfo、searchFile、imageRun、ffmpegRun、pdfRun、gsRun、ocrRecognition

非同步介面同一時刻的行為約束參考具體條目（如媒體五件套為串列執行，共用 cancelRun 取消）。

二、公用介面 #

1、取得用戶端版本 #

function Zen.getVersion() : object

  • 輸入：無

  • 輸出

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion：用戶端API版本資訊。每一次涉及到介面更新，版本號都加1；數字從0到9，9以後從0開始，比如1.0.0，1.0.1，1.0.2... 1.0.9，1.1.0等

    • appVersion：用戶端版本資訊

    • usageTime：使用時間（單位：s）

    • usageTimes：啟用次數

    • firstUseTime：首次使用時間，格式：yyyymmdd

2、取得設定 #

function Zen.getConfig(key?: string) : object

  • 輸入

    • key（可選）：只取該鍵，支援 a.b 點路徑。缺省返回全量設定。

      • 命中：返回 {"error":0, "<key>": <值>}，如 getConfig("language") → {"error":0,"language":"zh_cn"}；getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • 未命中：返回 {"error":0}（不報錯，讀取方自行兜底）

  • 輸出（示例，欄位以實際設定為準）

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel：日誌等級（0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal）

    • wallpaperEnabled：啟用動態桌布

    • overlayEnabled：啟用桌面特效

    • gameMode：遊戲模式

    • clipboardHistoryMaxCount：剪貼簿最大歷史記錄個數

    • autoStart：開機自啟動

    • shortcutKeys：全域快捷鍵

      • main：主介面

        • doubleCtrlEnabled：雙擊Ctrl喚醒

        • doubleAltEnabled：雙擊Alt喚醒

        • modifier：修飾鍵

        • virtualCode：主鍵

      • apps：應用

        • appId：應用id

        • modifier：修飾鍵

        • virtualCode：主鍵

    • quickOpen：快開

      • name：名稱

      • type：類型（normal：通用搜尋 / spec：垂直搜尋）

      • index：序號

      • url：url模板

      • enabled：是否啟用

    • customApps：自訂app

      • filePath：app對應exe的所在路徑

      • enabled：是否啟用

    • dock：程序塢（類目 + 內容）

      • 通用約定：缺 name/icon 表示「用內建預設值」（由 i18n 或 appId 對應的 .zenmod 執行時派生，隨介面語言變化）；有該欄位表示使用者自訂過，原樣顯示不再翻譯。

      • categories：類目

        • id：內建類目為語義 id（folder/tools/ai/game/system），用戶新建為 category_<時間戳>

        • name：可選，使用者改名後才有

        • icon：FontAwesome class

        • color：主題色

        • order：排序序號

      • contents：內容項

        • id：內建目錄項為語義 id（desktop/documents/downloads/music/videos），其餘為 content_<時間戳>

        • categoryId：所屬類目 id

        • type：app | folder | url

        • appId：type=app 時必填，對應 .zenmod 的 id；名稱與圖示全部由它派生，不要落盤

        • folderPath：type=folder 時必填，支援 %USERPROFILE% 等環境變數

        • url：type=url 時必填，規範化後的完整網址（無協定前綴自動補 https://）；點選用系統預設瀏覽器開啟。名稱由使用者填寫，圖示執行時抓取網站 favicon（失敗兜底 fas fa-globe），不落盤

        • name / icon：可選，語義同上（type=folder 的使用者自選目錄必填）

        • color：圖示著色

        • order：同類目內的排序序號

3、修改設定 #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • 輸入

    • config：同getConfig

      • 修改什麼就傳什麼，無需傳全部內容

      • 同一鍵值下的內容需要傳完整

      {
    "logLevel": "1"
}

    • replace（可選，預設 false）：false=增量合併到現有設定，true=整體替換（匯入備份用，能清掉已刪除的清單項）。傳入 "true" 或 "false" 字串，缺省等同 "false"。

  • 注意：不要「讀全量 getConfig 再整份 setConfig 回寫」——getConfig 回傳值帶 error 欄位，整份回寫會把它存進設定檔。一律窄粒度寫，如 setConfig({ dock: { categories } })。

  • 輸出

    {
    "error": 0,
    "errorMsg": ""
}

2、按 id 批次取應用資訊（非同步） #

function Zen.getAppInfo(appIds: string[]) : object

設定裡只存 appId，名稱與圖示一律執行時派生（.zenmod 的 name 是多語言的，快照進設定會在切語言後過期）。這個介面就是給這個場景用的。

⚠️ 不要用循環 searchApp(appId, 1) 代替它：searchApp 每次都是對整個應用索引做全表掃描 + 拼音匹配 + 打分排序，還會並發起兩個執行緒、返回多條帶 base64 圖示的結果。程序塢加上快捷鍵有幾十個 appId，逐個查會明顯拖慢啟動。本介面一次收全，native 側走 map::find 精確命中。

內部會等應用索引就緒（索引由背景執行緒生成），故是非同步綁定，冷啟動早期呼叫不會拿到空結果。

  • 輸入

    • appIds：appId 陣列，如 ["calculator", "Microsoft.WindowsCamera"]

  • 輸出

    格式與 searchApp 完全一致（同一個 BuildAppResult），但：

    • 只返回精確命中的項，查不到的 id 會被靜默跳過，故 apps.length 可能小於入參長度（用來檢出設定裡的失效 appId）

    • 順序按入參順序，score 恆為 0（未參與打分）

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

七、媒體處理 #

媒體五件套由 C++ 側呼起 bin64\Platform\ 下的第三方 CLI 工具執行。除 ffprobeRun 外均為非同步綁定（背景執行緒執行，不阻塞 UI 執行緒）；批次處理為串列，同一時刻僅有一個子處理程序在執行，可用 Zen.cancelRun() 終止目前執行（被取消時返回 errorMsg: "cancelled"）。

1、執行 magick 命令（非同步） #

function Zen.imageRun(args: string) : object

  • 輸入

    • args：完整的 magick 命令列參數（不含 magick.exe 本身），由前端拼接。路徑需自行加雙引號，例如 "D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • 輸出

    {
  "error": 0,
  "stdout": "..."
}

  • 注：C++ 端不拼接參數，只執行 magick.exe <args> 並擷取結果。error 非 0 時 errorMsg 透傳 magick stderr；stdout 為 magick 標準輸出（identify 等命令的結果）

2、執行 ffmpeg 命令（非同步） #

function Zen.ffmpegRun(args: string) : object

  • 輸入

    • args：完整的 ffmpeg 命令列參數（不含 ffmpeg.exe 本身），由前端拼接。路徑需自行加雙引號，例如 -i "D:\in.mp4" -vf "scale=1280:720" -c:v libx264 -crf 23 "D:\out.mp4"

  • 輸出

    {
  "error": 0,
  "stdout": "..."
}

  • 注：C++ 端不拼接參數，只執行 ffmpeg.exe <args> 並擷取結果。error 非 0 時 errorMsg 透傳 ffmpeg stderr；stdout 為 ffmpeg 標準輸出。影片處理耗時較長，C++ 預設逾時 1800s

九、加密解密 #

1、加密資料 #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • 輸入

    • target：要加密的資料

      • type="text" 時為文字字串

      • type="data" 時為 Base64 編碼的二進位資料

      • type="hex" 時為十六進位字串

      • type="file" 時為檔案路徑

    • algorithm：加密演算法

      • 對稱加密："aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • 非對稱加密："rsa-pkcs1", "rsa-oaep"（RSA，公鑰加密、私鑰解密）、"sm2"（國密橢圓曲線 sm2p256v1，公鑰加密、私鑰解密；單次可處理任意長度，無需分塊）

      • key/iv 為 Base64；內部轉十六進位後以 enc -K <hex> -iv <hex> 形式傳遞，金鑰長度需精確匹配演算法

    • type：輸入類型（預設 "text"）

      • "text"：文字資料

      • "data"：Base64 編碼的二進位資料

      • "hex"：十六進位字串

      • "file"：檔案路徑

    • key：對稱為 Base64 編碼的金鑰；非對稱(rsa-*、sm2)為 PEM 文字（加密傳公鑰、解密傳私鑰，原樣透傳不 Base64 解碼）

    • iv：Base64 編碼的初始化向量（可選，某些演算法需要；非對稱忽略）

  • 輸出

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

3、產生金鑰 #

function Zen.generateKey(algorithm: string, bits: string = '') : object

統一金鑰產生入口（由內建 openssl.exe 產生，前端無需依賴瀏覽器 WebCrypto）。

  • 輸入

    • algorithm：演算法名

      • 對稱：aes-128-cbc / aes-256-cbc / des-cbc / des-ede3-cbc / sm4-cbc / sm4-ecb / sm4-ctr / rc2-cbc / rc4 / bf-ecb 等（金鑰長度由演算法名解析）

      • 非對稱："rsa"（bits 生效）/ "sm2"（固定曲線 sm2p256v1）

    • bits：RSA 金鑰位元數（"2048"/"4096"，預設 2048）；對稱演算法與 SM2 忽略

  • 輸出

    // 对称算法
{ "error": 0, "algorithm": "aes-256-cbc", "key": "Base64编码的密钥" }
// 非对称算法
{ "error": 0, "algorithm": "sm2", "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n", "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n" }

4、產生IV #

function Zen.generateIv(algorithm: string) : object

按對稱演算法塊大小產生隨機 IV（由內建 openssl.exe 產生）。

  • 輸入

    • algorithm：對稱演算法名（同 encrypt 的對稱演算法清單）

  • 輸出

    注：AES/SM4 塊大小 16 位元組；DES/3DES/RC2 為 8 位元組；ECB 模式與流密碼(rc4)無需 IV，iv 返回空字串。

5、計算雜湊 #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • 輸入

    • target：計算目標，含義隨 type 變化

      • type="file" 時為檔案路徑

      • type="text" 時為文字字串（按 UTF-8 計算摘要）

      • type="data" 時為 Base64 編碼的二進位資料

      • type="hex" 時為十六進位字串

    • algorithm：雜湊演算法

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3"（國密 SM3 摘要，256 位元 / 64 位十六進位）

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512"（SHA-3 / Keccak，NIST FIPS 202）

      • "blake2b512" / "blake2s256"（BLAKE2，現代高效能摘要）

      • "crc32"（CRC32 校驗和，8 位十六進位）

      • "crc16"（CRC16 校驗和，4 位十六進位）

      • "checksum"（位元組累加和，8 位十六進位）

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512"（HMAC，第 4 參 key 為金鑰，輸出十六進位 MAC）

    • type：輸入類型（可選，預設 "file"）

      • "file"：計算檔案雜湊

      • "text"：計算文字雜湊

      • "data"：計算二進位資料雜湊（target 需為 Base64 字串）

      • "hex"：計算十六進位字串雜湊（target 為 hex 字串，解碼後按位元組計算）

  • 輸出

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

十三、更新 #

更新由獨立程序 yyzUpdater.exe 完成，主程序僅負責拉起與狀態探測。

1、檢查更新 #

function Zen.checkUpdate() : object

拉起 yyzUpdater.exe --check-and-apply（檢測 + 下載 + 套用一條龍）。

  • 輸入：無

  • 輸出

    { "error": 0, "errorMsg": "success" }

    注：error:0 僅表示成功拉起更新器，不代表更新結果。更新進行中/已就緒的狀態用 getUpdateState 查詢。

2、取得更新狀態 #

function Zen.getUpdateState() : object

即時探測更新狀態（供系統匣輪詢）：

  • updater 是否在執行 → 單一實例互斥體 Local\yyzUpdater_SingleInstance

  • 是否已下載待套用 → %APPDATA%\yyzTools\Update\update.ready 是否存在（存在則解析其中 main 包 version）

  • 手動檢查是否已結束且無更新 → %APPDATA%\yyzTools\Update\update.result 標記（讀到即刪）

  • 輸入：無

  • 輸出

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status：idle（無更新活動）/ checking（更新器執行中）/ ready（已下載完畢可升級）

    • version：僅 ready 態有值，為待套用的新版本號（取 main 包），其餘為空字串

    • lastResult：僅 idle 態可能有值，為上一次手動檢查（--check-and-apply）的結果：uptodate（已是最新）/ error（檢查失敗），無標記時為空字串。該標記由 updater 寫入、本介面讀取後立即刪除，因此只會返回一次，供前端彈一次 Toast；靜默的 --check 不寫標記，不會產生打擾。

    • 狀態優先級：checking > ready > idle

3、套用已下載完畢的更新 #

function Zen.applyUpdate() : object

拉起 yyzUpdater.exe --apply：讀 update.ready → 等主程序結束 → 替換檔案 → 重啟主程序。僅在 getUpdateState 返回 ready 時呼叫。

  • 輸入：無

  • 輸出

    { "error": 0, "errorMsg": "success" }
