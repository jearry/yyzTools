1. 共通の規約 #

本ドキュメントは Native との対話に関わるすべてのインターフェースを定義し、メインプロセス yyzTools.exe が登録したインターフェースのみを対象とします（src/yyztools/NativeApi.cpp の SetupBindings()）。

呼び出し方法 #

  • フロントエンドは window.Zen オブジェクト経由でインターフェース関数を呼び出します。統一して ZenAPI ラッパークラス（web/lib/zen_api.js）を使うことを推奨します。業務コードで window.Zen を直結せず、インターフェースのアップグレード・調整時に互換レイヤーとして扱えるようにしてください。

  • 入力：位置パラメータで渡します。パラメータの個数と型は各インターフェースの説明を参照

  • 出力：戻り値で渡し、値は json オブジェクトで、以下の内容を含みます

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error：0 が正解、0 以外がエラー

    • errorMsg（任意）：エラー情報

    • その他（任意）：各インターフェースの説明を参照

エラー判定方法 #

error は常に数値です：0 が正解、0 以外がエラー（呼び出し例外時は -1）。

同期 / 非同期バインド #

大多数のインターフェースは同期バインド（BindSync）で、呼び出すと即返ります。以下の 7 つのインターフェースは非同期バインド（BindAsync）で、バックグラウンドスレッドで実行され、Promise で結果が返り、UI スレッドをブロックしません：

getAppInfo、searchFile、imageRun、ffmpegRun、pdfRun、gsRun、ocrRecognition

非同期インターフェースの同一時刻における動作制約は各項目を参照（たとえばメディア 5 種は逐次実行で、共通の cancelRun でキャンセル）。

2. 共通インターフェース #

1. クライアントバージョンの取得 #

function Zen.getVersion() : object

  • 入力：なし

  • 出力

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion：クライアント API バージョン情報。インターフェース更新に関わるたびにバージョン番号を 1 増やす。数字は 0 から 9 で、9 の後は 0 に戻る。例：1.0.0、1.0.1、1.0.2... 1.0.9、1.1.0 など

    • appVersion：クライアントバージョン情報

    • usageTime：使用時間（単位：s）

    • usageTimes：起動回数

    • firstUseTime：初回使用時刻。形式：yyyymmdd

2. 設定の取得 #

function Zen.getConfig(key?: string) : object

  • 入力

    • key（任意）：そのキーのみ取得。a.b のドットパス対応。省略時は全量の設定を返す。

      • ヒット：{"error":0, "<key>": <値>} を返す。例：getConfig("language") → {"error":0,"language":"zh_cn"}；getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • 未ヒット：{"error":0} を返す（エラーにはせず、読み取り側でフォールバックする）

  • 出力（例、フィールドは実際の設定による）

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel：ログレベル（0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal）

    • wallpaperEnabled：ダイナミック壁紙の有効化

    • overlayEnabled：デスクトップエフェクトの有効化

    • gameMode：ゲームモード

    • clipboardHistoryMaxCount：クリップボードの最大履歴件数

    • autoStart：起動時の自動開始

    • shortcutKeys：グローバルショートカットキー

      • main：メイン画面

        • doubleCtrlEnabled：Ctrl ダブルクリックで呼び出し

        • doubleAltEnabled：Alt ダブルクリックで呼び出し

        • modifier：修飾キー

        • virtualCode：主キー

      • apps：アプリ

        • appId：アプリ id

        • modifier：修飾キー

        • virtualCode：主キー

    • quickOpen：クイックオープン

      • name：名称

      • type：タイプ（normal：汎用検索 / spec：垂直検索）

      • index：連番

      • url：url テンプレート

      • enabled：有効かどうか

    • customApps：カスタム app

      • filePath：app に対応する exe の所在パス

      • enabled：有効かどうか

    • dock：ドック（カテゴリ + コンテンツ）

      • 共通の規約： name/icon が欠けている場合は「内蔵デフォルト値を使う」ことを意味する（i18n または appId に対応する .zenmod から実行時に派生し、画面言語に応じて変化）。このフィールドがあればユーザーがカスタマイズ済みを意味し、原文のまま表示して翻訳しない。

      • categories：カテゴリ

        • id：内蔵カテゴリはセマンティック id（folder/tools/ai/game/system）。ユーザー新規作成は category_<タイムスタンプ>

        • name：任意。ユーザーが改名した場合のみ存在

        • icon：FontAwesome class

        • color：テーマカラー

        • order：ソート順

      • contents：コンテンツ項目

        • id：内蔵ディレクトリ項目はセマンティック id（desktop/documents/downloads/music/videos）。その他は content_<タイムスタンプ>

        • categoryId：所属カテゴリの id

        • type：app | folder | url

        • appId：type=app のとき必須。.zenmod の id に対応。名称とアイコンはすべてここから派生し、ディスクに書き込まない

        • folderPath：type=folder のとき必須。%USERPROFILE% などの環境変数対応

        • url：type=url のとき必須。正規化済みの完全な URL（プロトコル接頭辞がなければ自動で https:// を補完）。クリックするとシステムデフォルトのブラウザで開く。名称はユーザーが入力し、アイコンは実行時にサイトの favicon を取得（失敗時は fas fa-globe にフォールバック）。ディスクに書き込まない

        • name / icon：任意。意味は上記のとおり（type=folder のユーザー選択ディレクトリでは必須）

        • color：アイコンの着色

        • order：同じカテゴリ内のソート順

3. 設定の変更 #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • 入力

    • config：getConfig と同じ

      • 変更する内容だけを渡し、全内容を渡す必要はない

      • 同じキーの下の内容は完全な形で渡す必要がある

      {
    "logLevel": "1"
}

    • replace（任意、デフォルト false）：false=既存設定への増分マージ、true=全体置換（バックアップインポート用。削除済みリスト項目を消せる）。"true" または "false" の文字列を渡し、省略時は "false" と同等。

  • 注意：「全量の getConfig を読んでから丸ごと setConfig で書き戻す」ことの禁止——getConfig の戻り値には error フィールドが含まれ、丸ごと書き戻すとそれが設定ファイルに保存されてしまう。必ず狭粒度で書くこと。例：setConfig({ dock: { categories } })。

  • 出力

    {
    "error": 0,
    "errorMsg": ""
}

3. ウィンドウ状態の取得 #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • 入力

    • window：Name または HWND の string 形式。ウィンドウコントロールを参照

    • can_suspend（任意）：そのウィンドウの WebView のサスペンドを許可するか（リソース管理スイッチ。省略時 false）

  • 説明：本インターフェースには副作用があります——状態を照会した後、ウィンドウが show/max 状態なら WebView の描画を復元し、そうでなければリソース節約のため WebView をサスペンドします（サスペンドは can_suspend が true のときのみ許可）。フロントエンドの常駐ページが自分の状態をポーリングする場合は true を渡し、通常の照会では false を渡す。

  • 出力

    {
    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state：状態（show：通常表示 / min：最小化 / max：最大化 / close：閉じる）

    • topmost：最前面かどうか

2. id によるアプリ情報の一括取得（非同期） #

function Zen.getAppInfo(appIds: string[]) : object

設定には appId のみを保存し、名称とアイコンは一律実行時に派生させます（.zenmod の name は多言語であり、スナップショットを設定に保存すると言語切替後に陳腐化する）。このインターフェースはまさにこのユースケースのためのものです。

⚠️ ループで searchApp(appId, 1) を呼んで代用しないこと：searchApp は毎回アプリインデックス全体に対する全表スキャン + ピンインマッチング + スコアリング・ソートを行い、さらに 2 つのスレッドを並行して起動し、base64 アイコン付きの結果を複数件返します。ドックにショートカットキーを加えると数十個の appId があり、1 件ずつ照会すると起動が明らかに遅くなります。本インターフェースは 1 回で全部を受け取り、native 側は map::find で正確にヒットします。

内部でアプリインデックスの準備完了を待つため（インデックスはバックグラウンドスレッドで生成される）、非同期バインドであり、コールドスタートの早期に呼んでも空の結果にはなりません。

  • 入力

    • appIds：appId の配列。例：["calculator", "Microsoft.WindowsCamera"]

  • 出力

    形式は searchApp と完全に同一（同じ BuildAppResult）ですが：

    • 正確にヒットした項目のみを返し、見つからない id はサイレントにスキップされるため、apps.length が入力の長さより小さくなることがある（設定内の無効な appId の検出に使える）

    • 順序は入力順で、score は常に 0（スコアリングに未参加）

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",

7. メディア処理 #

メディア 5 種は C++ 側が bin64\Platform\ 配下のサードパーティ CLI ツールを呼び出して実行します。ffprobeRun 以外はすべて非同期バインド（バックグラウンドスレッドで実行、UI スレッドをブロックしない）。バッチ処理は逐次で、同一時刻に実行されるサブプロセスは 1 つだけで、Zen.cancelRun() で現在の実行を中断できます（キャンセル時は errorMsg: "cancelled" を返す）。

1. magick コマンドの実行（非同期） #

function Zen.imageRun(args: string) : object

  • 入力

    • args：完全な magick コマンドライン引数（magick.exe 本体を除く）。フロントエンドが組み立てる。パスは自分でダブルクォートで囲むこと。例："D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • 出力

    {
  "error": 0,
  "stdout": "..."
}

  • 注：C++ 側は引数を組み立てず、magick.exe <args> を実行して結果をキャプチャするだけです。error が 0 以外のとき errorMsg は magick の stderr を透過し、stdout は magick の標準出力（identify などのコマンドの結果）

9. 暗号化・復号 #

1. データの暗号化 #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • 入力

    • target：暗号化するデータ

      • type="text" の場合はテキスト文字列

      • type="data" の場合は Base64 エンコードされたバイナリデータ

      • type="hex" の場合は 16 進文字列

      • type="file" の場合はファイルパス

    • algorithm：暗号化アルゴリズム

      • 対称暗号："aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • 非対称暗号："rsa-pkcs1", "rsa-oaep"（RSA。公開鍵で暗号化、秘密鍵で復号）、"sm2"（中国国標の楕円曲線 sm2p256v1。公開鍵で暗号化、秘密鍵で復号。1 回で任意長を処理でき、分割不要）

      • key/iv は Base64。内部で 16 進に変換したうえで enc -K <hex> -iv <hex> の形式で渡され、鍵長はアルゴリズムに正確に一致する必要がある

    • type：入力タイプ（デフォルト "text"）

      • "text"：テキストデータ

      • "data"：Base64 エンコードされたバイナリデータ

      • "hex"：16 進文字列

      • "file"：ファイルパス

    • key：対称は Base64 エンコードされた鍵。非対称（rsa-*、sm2）は PEM テキスト（暗号化では公開鍵、復号では秘密鍵を渡す。そのまま透過し Base64 デコードしない）

    • iv：Base64 エンコードされた初期化ベクトル（任意。一部のアルゴリズムで必要。非対称では無視）

  • 出力

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",

2. データの復号 #

function Zen.decrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • 入力

    • target：復号するデータ

      • type="data" の場合は Base64 エンコードされた暗号文

      • type="file" の場合は暗号文ファイルのパス

    • algorithm：暗号化アルゴリズム（encrypt と同じ）

    • type：入力タイプ（デフォルト "data"）

      • "data"：Base64 エンコードされた暗号文

      • "file"：暗号文ファイルのパス

    • key：対称は Base64 エンコードされた鍵。非対称（rsa-*、sm2）は PEM テキスト（暗号化では公開鍵、復号では秘密鍵を渡す。そのまま透過し Base64 デコードしない）

    • iv：Base64 エンコードされた初期化ベクトル（任意。非対称では無視）

  • 出力

    {
  "error": 0,
  "result": "Base64编码的解密数据",
  "algorithm": "aes-256-cbc",
  "type": "data",
  "inputSize": 1040,
  "outputSize": 1024
}

3. 鍵の生成 #

function Zen.generateKey(algorithm: string, bits: string = '') : object

鍵生成の統一入口（内蔵の openssl.exe で生成するため、フロントエンドはブラウザの WebCrypto に依存しない）。

  • 入力

    • algorithm：アルゴリズム名

      • 対称：aes-128-cbc / aes-256-cbc / des-cbc / des-ede3-cbc / sm4-cbc / sm4-ecb / sm4-ctr / rc2-cbc / rc4 / bf-ecb など（鍵長はアルゴリズム名から解析）

      • 非対称："rsa"（bits が有効）/ "sm2"（固定曲線 sm2p256v1）

    • bits：RSA 鍵長（"2048"/"4096"、デフォルト 2048）。対称アルゴリズムと SM2 では無視

  • 出力

    // 対称アルゴリズム
{ "error": 0, "algorithm": "aes-256-cbc", "key": "Base64编码的密钥" }
// 非対称アルゴリズム
{ "error": 0, "algorithm": "sm2", "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n", "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n" }

4. IV の生成 #

function Zen.generateIv(algorithm: string) : object

対称アルゴリズムのブロックサイズに応じてランダムな IV を生成（内蔵の openssl.exe で生成）。

  • 入力

    • algorithm：対称アルゴリズム名（encrypt の対称アルゴリズム一覧と同じ）

  • 出力

    { "error": 0, "algorithm": "aes-256-cbc", "iv": "Base64编码的IV" }

    注：AES/SM4 のブロックサイズは 16 バイト。DES/3DES/RC2 は 8 バイト。ECB モードとストリーム暗号（rc4）は IV 不要で、iv は空文字列を返す。

5. ハッシュの計算 #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • 入力

    • target：計算対象。意味は type により変わる

      • type="file" の場合はファイルパス

      • type="text" の場合はテキスト文字列（UTF-8 でダイジェストを計算）

      • type="data" の場合は Base64 エンコードされたバイナリデータ

      • type="hex" の場合は 16 進文字列

    • algorithm：ハッシュアルゴリズム

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3"（中国国標 SM3 ダイジェスト。256 ビット / 64 桁の 16 進）

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512"（SHA-3 / Keccak、NIST FIPS 202）

      • "blake2b512" / "blake2s256"（BLAKE2。モダンな高性能ダイジェスト）

      • "crc32"（CRC32 チェックサム。8 桁の 16 進）

      • "crc16"（CRC16 チェックサム。4 桁の 16 進）

      • "checksum"（バイト累積和。8 桁の 16 進）

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512"（HMAC。第 4 引数 key が鍵で、出力は 16 進の MAC）

    • type：入力タイプ（任意、デフォルト "file"）

      • "file"：ファイルのハッシュを計算

      • "text"：テキストのハッシュを計算

      • "data"：バイナリデータのハッシュを計算（target は Base64 文字列であること）

      • "hex"：16 進文字列のハッシュを計算（target は hex 文字列。デコード後にバイト単位で計算）

  • 出力

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

13. アップデート #

アップデートは独立したプロセス yyzUpdater.exe が行い、メインプロセスは起動と状態の検出のみを担います。

1. アップデートのチェック #

function Zen.checkUpdate() : object

yyzUpdater.exe --check-and-apply を起動します（検出 + ダウンロード + 適用を一括で行う）。

  • 入力：なし

  • 出力

    { "error": 0, "errorMsg": "success" }

    注：error:0 はアップデータの起動に成功したことのみを表し、アップデートの結果を表さない。アップデートの進行中/準備完了の状態は getUpdateState で照会する。

2. アップデート状態の取得 #

function Zen.getUpdateState() : object

アップデート状態をリアルタイムで検出します（トレイのポーリング用）：

  • updater が実行中か → シングルトンミューテックス Local\yyzUpdater_SingleInstance

  • ダウンロード済みで適用待ちか → %APPDATA%\yyzTools\Update\update.ready が存在するか（存在すればその中の main パッケージの version を解析）

  • 手動チェックが終了し更新なしか → %APPDATA%\yyzTools\Update\update.result マーカー（読んだら削除）

  • 入力：なし

  • 出力

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status：idle（アップデート活動なし）/ checking（アップデータ実行中）/ ready（ダウンロード済みでアップグレード可能）

    • version：ready 状態のみ値を持ち、適用待ちの新バージョン番号（main パッケージから取得）。それ以外は空文字列

    • lastResult：idle 状態のみ値を持つことがあり、前回の手動チェック（--check-and-apply）の結果：uptodate（最新済み）/ error（チェック失敗）。マーカーがなければ空文字列。このマーカーは updater が書き込み、本インターフェースが読んだ直後に削除するため、1 回しか返らない。フロントエンドが 1 度 Toast を出すためのもの。サイレントの --check はマーカーを書かず、邪魔が入りません。

    • 状態の優先度：checking > ready > idle

3. ダウンロード済みのアップデートの適用 #

function Zen.applyUpdate() : object

yyzUpdater.exe --apply を起動します：update.ready を読む → メインプロセスの終了を待つ → ファイルを置換 → メインプロセスを再起動。getUpdateState が ready を返したときのみ呼び出すこと。

  • 入力：なし

  • 出力

    { "error": 0, "errorMsg": "success" }
