クイックスタート

ビルドツール不要で最初のモジュールを作る

API リファレンス サンプルプロジェクトをダウンロード

本ドキュメントはモジュール開発者向けに、yyzTools メインプロセス内で動作する Web アプリをゼロから作成する方法を解説します（SDK サンプルプロジェクト SDK_Sample——高速ファイル検索ツール——を例に）。対象は以下のとおりです：ページのディレクトリ構成、ウィンドウホスト、i18n、非同期 Native API（全ディスクファイル検索）、ファイルを開く操作、設定の永続化、そして C++ の能力を拡張したい場合の native メソッド追加テンプレート。

サンプルは純ネイティブ JS・サードパーティ依存ゼロ・ビルド不要です。Vite / Alpine / FontAwesome は不要で、Web と Modules の 2 つのディレクトリを yyzTools.exe のあるディレクトリにコピーするだけで動作します。

1. サンプルのディレクトリ構成とデプロイ方法 #

sdk/sample/
  Web/                        ← <yyzTools.exe のあるディレクトリ>\Web\ へコピー      （既存の Web ディレクトリとマージ）
    SDK_Sample/               ← サンプルの自己完結ディレクトリ。このフォルダ全体が 1 つの完全なモジュール
      index.html              # ページ構造（ネイティブ DOM、data-i18n で文言位置をマーキング）
      filefinder.js           # 全ロジック：検索 / 開く / 履歴 / Esc
      filefinder.css          # ページスタイル（すべて --zen-* 変数を使用、ダーク/ライト両対応）
      i18n.js                 # 文言辞書（zh_cn / en）
      lib/
        zen_api.js            # ZenAPI ラッパークラス（Native API の JS ラッパー、唯一の lib 依存）
        window_controls.css   # テーマ変数（--zen-*）+ ウィンドウコントロールバーのスタイル
  Modules/                   ← <yyzTools.exe のあるディレクトリ>\Modules\ へコピー    （既存の Modules ディレクトリとマージ）
    SDK_Sample.zenmod         # type:"web" モジュール宣言。ModuleManager が自動でホストウィンドウを作成

デプロイ：

sdk/sample/Web     を bin64\Web\     へコピー/マージ
sdk/sample/Modules を bin64\Modules\ へコピー/マージ
yyzTools.exe を再起動し、コマンドパレットで「SDK样例工程」を検索して起動

メインプログラムの読み込み位置の規約：

リソース 位置
ページ <exeディレクトリ>\Web\{page}\index.html
モジュール <exeディレクトリ>\Modules\<分類>\*.zenmod（サブディレクトリは 1 階層のみスキャン）

2. アーキテクチャ概観：Web アプリはどのように動くのか #

Modules/SDK_Sample.zenmod   ← type:"web" を宣言するモジュールファイル（データ駆動、C++ の記述不要）
        │  メインプログラム起動時に .zenmod をスキャン
        ▼
WebModule ホストウィンドウ（ネイティブウィンドウ + WebView2）
        │  Web\SDK_Sample\index.html を読み込む
        ▼
Web/SDK_Sample/             ← フロントエンドコードのすべて（ネイティブ JS、依存ゼロ）
        │  window.Zen.xxx(...)  ←→  メインプログラムが登録したネイティブインターフェース
        ▼
C++ 各 Manager（ファイル/プロセス/ウィンドウ/クリップボード/OCR...）

重要な結論：

  • C++ コードは一切書く必要がありません。type: "web" の .zenmod はメインプログラムが自動的に WebModule ホストウィンドウとして作成し、ウィンドウサイズ・アイコン・多言語名称はすべてモジュールファイルで宣言します。

  • モジュールは自動的に以下を獲得します：コマンドパレット検索（ピンインインデックス含む）、グローバルショートカットキーのバインド、ドックへのマウント、windowControl 名称テーブルへの登録。

  • フロントエンドと C++ の唯一のチャネルは window.Zen です。統一して ZenAPI ラッパークラス経由で呼び出してください（サンプルには lib/zen_api.js が同梱されています）。

  • ビルド不要のページはそのまま静的ファイルなので、編集後にウィンドウを更新すれば即反映されます（windowControl('sdk_sample','hide') の後に show、または exe を再起動）。コンパイル手順は一切不要です。

3. ページ構造（ネイティブ JS、4 ファイル） #

index.html #

サードパーティライブラリは一切読み込みません。ウィンドウコントロールバーの 3 つのボタンは Unicode 文字をアイコンとして使用し（− / □ / ×）、スタイルは lib/window_controls.css が提供します。文言位置は data-i18n / data-i18n-ph でマーキングし、JS 初期化時に一括で埋め込みます。構造は 4 ブロック：検索バー、検索履歴 chips、ステータスバー（結果件数 + 構文ヒント）、結果リスト：

<div class="search-bar">
    <input type="text" id="searchInput" class="search-input" data-i18n-ph="inputPlaceholder"
           spellcheck="false" autocomplete="off">
    <button class="search-btn" id="btnSearch" data-i18n="search"></button>
</div>
<div class="history-chips" id="historyChips"> ... </div>
<div class="status-bar">
    <span id="statusText" data-i18n="empty"></span>
    <span class="syntax-hint" data-i18n="syntaxHint"></span>
</div>
<div class="result-list" id="resultList"></div>

filefinder.js（コアロジック） #

5 つの責務があり、すべてサンプルをそのまま写せばよいです：

  1. ウィンドウコントロール：ZenAPI.windowControl('sdk_sample', 'min'|'max'|'close'|'drag')。タイトルバーのドラッグは変位が 5px を超えた場合のみトリガー。Esc キー——入力ボックスにフォーカスがある場合は先に blur、なければウィンドウを閉じる。
  2. テーマ：window.__applyTheme を登録して C++ からのプッシュを受信（初回の data-theme は C++ が注入するため JS での処理不要）。
  3. i18n：getConfig().language を読み、辞書から文言を取得し、data-i18n 要素を走査して埋め込み。{{count}} プレースホルダー付きの文は補間関数で展開。
  4. 検索：searchFile(keyword, maxResults) は非同期バインドインターフェース（バックグラウンドスレッドで実行、UI をブロックしない）。Enter で即検索、入力のデバウンス 300ms で自動検索。増加するシーケンス番号で順序不正の応答を破棄——native 側には検索スロット機構があり（新しいリクエストが未完了の旧リクエストを差し替え、旧 Promise が受け取るのは空結果）、フロントエンドのシーケンス番号はこの「空結果の遅延到着」が新しい結果の描画を上書きするのを防ぎ、両者が連携します。
  5. 結果操作：openFile(fullPath, false) でファイルを開く（ダブルクリックも同様、第 2 引数は「管理者権限かどうか」）。openFileLocation(fullPath) で所在ディレクトリを開く。完全パスは path + '\\' + name で組み立て。アイコンは結果に含まれる icon フィールド（base64）をそのまま使用。ファイルサイズは size の数値フィールドを整形して表示。

searchFile の戻り値構造（{ error, files[] }） #

files[] の各項目のフィールド：

フィールド 型 説明
name / path 文字列 ファイル名 / 所在ディレクトリ。完全パス = path + '\\' + name
dateModified 文字列 更新時刻（ローカライズされた書式テキスト）
size 数値 ファイルのバイト数。ネイティブ数値をそのまま使用
icon 文字列 base64 アイコン。<img src> に直接渡せ、getFileIcon を再呼び出しする不要
score 数値 関連度スコア（native 側でスコア順にソート済み）
isDir 数値 1/0 の数値でありネイティブブールではない（手組み立て JSON パス）。truthy または === 1 で判定し、=== true は使わない

本サンプルが呼び出すインターフェース一覧 #

インターフェース バインド 用途
searchFile(keyword, maxResults) 非同期 全ディスク MFT インデックス検索。Everything 構文対応（size:>100MB、ext:mp4、!ext:tmp）
openFile(path, admin) 同期 ファイル/ディレクトリを開く（shell のデフォルト動作）。admin=true で管理者権限
openFileLocation(path) 同期 エクスプローラーでそのファイルを定位
getConfig(key?) 同期 設定の読み取り：省略時は全量、key 指定時はそのキーのみ（a.b のドットパス対応）
setConfig(patch, replace?) 同期 狭粒度で検索履歴を書き込む：setConfig({ sdk_sample: { history } })。replace=true で全体置換（バックアップインポート専用）
log(message) 同期 フロントエンドログ。メインプロセスのログに書き込まれ、障害調査に便利
windowControl(name, action) 同步 ウィンドウの最小化/最大化/閉じる/ドラッグ

呼び出し規約（4 つの鉄則） #

import ZenAPI from './lib/zen_api.js';

// 1. エラー判定は isOk() を使う（error は常に数値：0 が成功、-1 は呼び出し例外）
const res = await ZenAPI.searchFile('yyztools', 200);
if (!ZenAPI.isOk(res)) { ... }

// 2. インターフェースが返すブールフィールドはネイティブブール、直接判定できる
//    （例外 1：config の値はフロントエンドが書き込んだ内容で型が決まり、通常は文字列。比較時に正規化に注意）
//    （例外 2：searchFile 結果の isDir は 1/0 の数値——手組み立て JSON パス。truthy または === 1 を使う）
const ex = await ZenAPI.exists(path);
if (ex.exists === true) { ... }

// 3. 設定の書き込みは必ず狭粒度に。全量の書き戻しは禁止
await ZenAPI.setConfig({ sdk_sample: { history } });   // 自分のキーのみ書き込む

// 4. id によるアプリ情報の一括取得は getAppInfo を使い、ループで searchApp を呼ぶことは禁止
const infos = await ZenAPI.getAppInfo(['calculator', 'ocr']);

非同期インターフェース（getAppInfo / searchFile / メディア 5 種 / ocrRecognition）はバックグラウンドスレッドで実行されます。同一時刻に実行されるメディアサブプロセスは 1 つだけなので、長時間タスクには cancelRun() によるキャンセル導線を用意してください。

よく使うインターフェース早見表（サンプル以外のさらなる能力） #

シナリオ インターフェース
自分の設定の読み/書き getConfig / setConfig（狭粒度 patch）/ addConfig（リスト項目の追加）
ファイルを開く/名前を付けて保存 browseFile / browseDir / writeFile / readFile（>50MB は readFileChunk）
システムディレクトリの取得 getKnownDir('download') など
Web ページ/外部プログラムを開く runAny('https://...', '')
クリップボードへコピー フロントエンドの navigator.clipboard（テキスト场景では native 不要）
スクリーンショット/OCR screenCap('fast', ...) → ocrRecognition(base64)（いずれも非同期）
他のモジュールウィンドウの呼び出し windowControl('translate', 'show')

4. .zenmod モジュールファイルの作成（ウィンドウホスト） #

Modules/<分類>/ の下に .zenmod を新規作成します（サンプルファイル：sdk/sample/Modules/SDK_Sample.zenmod）：

{
    "id": "sdk_sample",
    "type": "web",
    "name": { "zh_cn": "SDK样例工程", "en": "SDK Sample Project", "...": "共 12 门语言" },
    "desc": { "zh_cn": "基于 MFT 索引的全盘急速文件搜索，支持 Everything 语法", "en": "..." },
    "icon": "fas fa-search",
    "winClassName": "yyzTools::SdkSampleWindowClass",
    "width": 760,
    "height": 540,
    "layoutType": 34,
    "url": "SDK_Sample/index.html",
    "preCreate": 0
}

フィールド説明（type:"web" のときメインプログラムが読み取る全フィールド）：

フィールド 必須 説明
id はい グローバルで一意。windowControl/windowState のウィンドウ名、ショートカットキーの appId、dock マウント id を兼ねる
type はい 固定で web
name はい 12 言語のオブジェクト。純文字列の書き方も許容（内部テスト用にのみ推奨）。値のフォールバック：現在の言語 → en → 純文字列
desc いいえ 同上
icon いいえ FontAwesome class（上記のとおり）または base64 画像
winClassName いいえ Win32 ウィンドウクラス名。グローバルで一意であればよい
width / height いいえ 初期ウィンドウサイズ。デフォルトは 800x600
layoutType いいえ 初期位置のレイアウトビットマスク。34 = 水平中央 + 垂直中央
url はい Web ルートディレクトリ相対のページパス（SDK_Sample/index.html）。http(s) で始まるオンラインアドレスも対応
preCreate いいえ 1 = 起動時にウィンドウを先行作成（初回オープンを高速化）。デフォルト 0 は必要時に作成
canSuspend いいえ 1 = ウィンドウ非表示時に WebView のサスペンドを許可しリソースを節約（デフォルト 1）

編集後の自己チェック：JSON がパース可能、UTF-8 BOM なし、id がグローバルで一意、12 言語すべて空でない。

これでアプリは完成です——第 1 節のとおり 2 つのディレクトリをコピーすれば、コマンドパレットで「SDK样例工程」や「sdk」を検索して起動できます（ピンインインデックスは自動生成）。windowControl('sdk_sample', 'show') でも呼び出せます。

5. 多言語文言（辞書方式） #

ビルド不要の方式では、通常の ES module の辞書で十分です（i18n.js）：

const messages = {
    zh_cn: { title: 'SDK样例工程', results: '{{count}} 个结果，耗时 {{ms}} ms', ... },
    en:    { title: 'SDK Sample Project', results: '{{count}} results in {{ms}} ms', ... }
};
export function getMessages(lang) { return messages[lang] || messages.en; }
export function interpolate(dict) {
    return (key, params) => { /* {{count}} → params.count */ };
}

初期化時に getConfig().language を読んで言語を選択し、見つからない場合は en にフォールバック。プレースホルダー付きの文は tf('results', { count, ms }) で展開します。

注意点：

  • 言語コードはアンダースコア小文字スタイル（zh_cn）を使用し、.zenmod と一致します。BCP47 ではありません。

  • .zenmod の name/desc は 12 言語すべて必須です。ページ内の文言に強制はなく、サンプルは zh_cn/en のみで、必要に応じて拡張してください。

  • インターフェース言語に即時追従して切り替えたいモジュールは、辞書を必要時に import() で多言語ファイルを遅延読み込みする形に変更できます。仕組みは本文と同じです。

6. デバッグと統合 #

1. ビルド不要でそのまま実行（導入の推奨）：
   sdk/sample/Web、sdk/sample/Modules を bin64\（Release exe のあるディレクトリ）へコピーし、exe を再起動。
   フロントエンド変更後は windowControl('sdk_sample','close') で閉じてから開き直すか、exe を再起動すれば反映。

2. ブラウザで構造を確認：
   Web/SDK_Sample/index.html をダブルクリックしてブラウザで開く。
   ブラウザには window.Zen がないため、ZenAPI.call は例外パスを通り error: -1 を返すが、
   ページ構造 / スタイル / 入力デバウンス / 描画ロジックは（ネイティブインターフェースを除き）通常どおりデバッグ可能。

検索性能のヒント：searchFile は C++ 側の MFT 全ディスクインデックスを経由し、通常はミリ秒レベルで返ります。native には検索スロット機構があり——新しいリクエストが未完了の旧リクエストを差し替え（旧リクエストは空結果を返す）、フロントエンドは 300ms のデバウンス + 増加シーケンス番号で順序不正の応答を破棄するため、連続入力してもバックグラウンドスレッドを圧迫したり旧結果が点滅したりしません。結果のアイコン（base64）は searchFile がついでに返すため、追加で getFileIcon を呼ぶ必要はありません。

インターフェースの能力が足りない場合（新しい C++ 能力が必要な場合など）は、公式サイトのフィードバック窓口から要望を出してください。メインプログラムの今後のバージョンでインターフェースを拡張します。

8. セキュリティ上の注意 #

Native API はモジュール開発者に対してホストプロセスのシステム能力を完全に開放しており、ファイルの読み書きと削除、プロセスの作成と終了、ウィンドウコントロール、クリップボードの読み書き、システム設定の変更、コマンドライン実行などの高リスク操作を含みます。かつ権限ダイアログなし、サンドボックス分離なし、取り消し機構なしです。

呼び出し前に、操作ごとの安全性を必ず自己評価してください。すべての外部入力を検証し、不可逆な操作の前にバックアップを取るかユーザーに確認を求め、機能が本当に必要とする能力のみを使用してください。これによって生じた一切の結果は開発者自身が負担します。
