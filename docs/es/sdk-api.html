1. Convenciones generales #

Este documento define todas las interfaces relacionadas con la interacción con la capa nativa, y cubre únicamente las interfaces registradas por el proceso principal yyzTools.exe (SetupBindings() en src/yyztools/NativeApi.cpp).

Forma de llamada #

  • El frontend llama a las funciones de las interfaces a través del objeto window.Zen; se recomienda hacerlo siempre mediante la clase envolvente ZenAPI: web/lib/zen_api.js. No conectes directamente con window.Zen en el código de negocio, para que sirva como capa de compatibilidad de interfaces cuando haya que ajustarlas en futuras actualizaciones.

  • Entrada: se pasa mediante parámetros posicionales; consulta el número y tipo de parámetros concretos en cada interfaz.

  • Salida: se transmite mediante el valor devuelto, que es un objeto json con el siguiente contenido:

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error: 0 correcto, distinto de 0 error

    • errorMsg (opcional): mensaje de error

    • Otros (opcional): consulta cada interfaz concreta

Detección de errores #

error es siempre un número: 0 correcto, distinto de 0 error (-1 en caso de excepción en la llamada).

Vinculación síncrona / asíncrona #

La gran mayoría de las interfaces son de vinculación síncrona (BindSync): la llamada devuelve al instante. Las 7 interfaces siguientes son de vinculación asíncrona (BindAsync): se ejecutan en un hilo en segundo plano y devuelven mediante Promise, sin bloquear el hilo de la UI:

getAppInfo, searchFile, imageRun, ffmpegRun, pdfRun, gsRun, ocrRecognition

Las restricciones de comportamiento de las interfaces asíncronas en un mismo momento se detallan en cada entrada (por ejemplo, el quinteto de medios se ejecuta en serie y comparte cancelRun para cancelar).

2. Interfaces comunes #

1. Obtener la versión del cliente #

function Zen.getVersion() : object

  • Entrada: ninguna

  • Salida

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion: información de la versión de la API del cliente. Cada actualización que afecte a las interfaces incrementa el número de versión en 1; el dígito va de 0 a 9 y, tras el 9, vuelve a empezar en 0; por ejemplo 1.0.0, 1.0.1, 1.0.2... 1.0.9, 1.1.0, etc.

    • appVersion: información de la versión del cliente

    • usageTime: tiempo de uso (unidad: s)

    • usageTimes: número de activaciones

    • firstUseTime: fecha del primer uso, formato: yyyymmdd

2. Obtener la configuración #

function Zen.getConfig(key?: string) : object

  • Entrada

    • key (opcional): toma solo esa clave; admite rutas con puntos a.b. Si se omite, devuelve la configuración completa.

      • Coincidencia: devuelve {"error":0, "<key>": <valor>}, p. ej. getConfig("language") → {"error":0,"language":"zh_cn"}; getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • Sin coincidencia: devuelve {"error":0} (no es un error; quien lee debe tener su propio valor de respaldo)

  • Salida (ejemplo; los campos reales dependen de la configuración existente)

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel: nivel de log (0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal)

    • wallpaperEnabled: activar el fondo de pantalla dinámico

    • overlayEnabled: activar los efectos de escritorio

    • gameMode: modo de juego

    • clipboardHistoryMaxCount: número máximo de registros del historial del portapapeles

    • autoStart: inicio automático con el sistema

    • shortcutKeys: atajos de teclado globales

      • main: interfaz principal

        • doubleCtrlEnabled: invocar con doble pulsación de Ctrl

        • doubleAltEnabled: invocar con doble pulsación de Alt

        • modifier: tecla modificadora

        • virtualCode: tecla principal

      • apps: aplicaciones

        • appId: id de la aplicación

        • modifier: tecla modificadora

        • virtualCode: tecla principal

    • quickOpen: apertura rápida

      • name: nombre

      • type: tipo (normal: búsqueda general / spec: búsqueda vertical)

      • index: número de orden

      • url: plantilla de url

      • enabled: activado o no

    • customApps: apps personalizadas

      • filePath: ruta del exe correspondiente a la app

      • enabled: activado o no

    • dock: dock (categorías + contenidos)

      • Convención general: la ausencia de name/icon significa "usar los valores internos predeterminados" (derivados en tiempo de ejecución por i18n o por el .zenmod correspondiente al appId, y cambian con el idioma de la interfaz); si el campo existe, significa que el usuario lo personalizó y se muestra tal cual, sin traducir.**

      • categories: categorías

        • id: las categorías internas usan ids semánticos (folder/tools/ai/game/system); las creadas por el usuario usan category_<marca de tiempo>

        • name: opcional, solo existe tras un cambio de nombre por el usuario

        • icon: clase de FontAwesome

        • color: color del tema

        • order: número de orden

      • contents: elementos de contenido

        • id: los elementos de directorio internos usan ids semánticos (desktop/documents/downloads/music/videos); el resto usan content_<marca de tiempo>

        • categoryId: id de la categoría a la que pertenece

        • type: app | folder | url

        • appId: obligatorio cuando type=app, corresponde al id del .zenmod; el nombre y el icono se derivan por completo de él, no se guarda en disco

        • folderPath: obligatorio cuando type=folder; admite variables de entorno como %USERPROFILE%

        • url: obligatorio cuando type=url, URL completa normalizada (si falta el protocolo se añade https:// automáticamente); al hacer clic se abre con el navegador predeterminado del sistema. El nombre lo escribe el usuario y el icono se obtiene en tiempo de ejecución del favicon del sitio (con respaldo fas fa-globe si falla), no se guarda en disco

        • name / icon: opcionales, misma semántica que arriba (obligatorios en type=folder para directorios elegidos por el usuario)

        • color: coloración del icono

        • order: número de orden dentro de su categoría

3. Modificar la configuración #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • Entrada

    • config: igual que getConfig

      • Pasa solo lo que quieras modificar; no hace falta pasar todo el contenido

      • El contenido bajo una misma clave debe pasarse completo

      {
    "logLevel": "1"
}

    • replace (opcional, por defecto false): false=fusión incremental sobre la configuración existente; true=reemplazo total (para importar copias de seguridad; permite limpiar los elementos de lista ya eliminados). Se pasa la cadena "true" o "false"; si se omite equivale a "false".

  • Nota: no hagas "leer toda la configuración con getConfig y reescribirla entera con setConfig"—el valor devuelto por getConfig incluye el campo error, y reescribirlo entero lo guardaría en el archivo de configuración. Escribe siempre con granularidad fina, p. ej. setConfig({ dock: { categories } }).

  • Salida

    {
    "error": 0,
    "errorMsg": ""
}

function Zen.setCountdownCache(data: string) : object

3. Obtener el estado de la ventana #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • Entrada

    • window: Name o el HWND en forma de string; ver Control de ventanas

    • can_suspend (opcional): permite suspender el WebView de esa ventana (interruptor de gestión de recursos; por defecto false)

  • Nota: esta interfaz tiene efectos secundarios—tras consultar el estado, si la ventana está en estado show/max se reanuda el renderizado del WebView; en caso contrario se suspende para ahorrar recursos (la suspensión solo se permite si can_suspend es true).   • Salida

    {
    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state: estado (show: mostrada normalmente / min: minimizada / max: maximizada / close: cerrada)

    • topmost: siempre visible o no

2. Obtener información de aplicaciones en lote por id (asíncrona) #

function Zen.getAppInfo(appIds: string[]) : object

En la configuración solo se guarda el appId; el nombre y el icono se derivan siempre en tiempo de ejecución (el name del .zenmod es multilingüe, y una instantánea guardada en la configuración quedaría obsoleta tras cambiar de idioma). Esta interfaz existe justo para este escenario.

⚠️ No lo sustituyas por un bucle de searchApp(appId, 1): cada llamada a searchApp hace un escaneo completo del índice de aplicaciones + coincidencia de pinyin + puntuación y ordenación, además de lanzar dos hilos en paralelo y devolver varios resultados con iconos en base64. Entre el dock y los atajos hay decenas de appId; consultarlos uno a uno ralentiza notablemente el arranque. Esta interfaz lo recibe todo de una vez y, del lado nativo, acierta de forma exacta mediante map::find.

Internamente espera a que el índice de aplicaciones esté listo (el índice lo genera un hilo en segundo plano), por lo que es de vinculación asíncrona: una llamada en las primeras fases del arranque en frío no devolverá un resultado vacío.

  • Entrada

    • appIds: array de appId, p. ej. ["calculator", "Microsoft.WindowsCamera"]

  • Salida

    Mismo formato que searchApp (usa el mismo BuildAppResult), pero:

    • Solo devuelve los elementos con coincidencia exacta; los id no encontrados se omiten silenciosamente, de modo que apps.length puede ser menor que la longitud de la entrada (útil para detectar appId inválidos en la configuración)

    • El orden sigue el orden de la entrada y score es siempre 0 (no participa en la puntuación)

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

1. Buscar archivos (asíncrona) #

  • Nota: la búsqueda la realiza el servicio propio yyzFileSearch (índice MFT + IPC por tubería con nombre); admite una sintaxis de consulta estilo Everything (p. ej. size:>100MB, !ext:mp4) y los resultados se ordenan por relevancia. La búsqueda se ejecuta en un hilo en segundo plano, por lo que es de vinculación asíncrona.

  • Entrada

    • keyword: palabra clave de búsqueda

    • maxResults: número máximo de registros

  • Salida

    {
  "error": 0,
  "files": [
    {
      "name": "WinMain.cpp",
      "path": "D:\\WorkCodeup\\yyztools\\src\\yyztools",
      "dateModified": "2025/10/18 14:05:00",
      "icon": "data:image/png;base64,",
      "score": 0,
      "isDir": 0
    }
  ]
}

    • files: lista de archivos

      • name: nombre del archivo

      • path: directorio contenedor del archivo (sin el nombre del archivo); ruta completa = path + "\" + name

      • dateModified: fecha de modificación

      • icon: icono del archivo, en formato base64

      • score: puntuación de la búsqueda

      • isDir: 1 indica directorio, 0 indica archivo

7. Procesamiento de medios #

El quinteto de medios lo ejecutan herramientas CLI de terceros de bin64\Platform\, invocadas desde el lado C++. Todas son de vinculación asíncrona (ejecución en un hilo en segundo plano, sin bloquear el hilo de la UI), salvo ffprobeRun; el procesamiento por lotes es serie, en un mismo momento solo hay un subproceso en ejecución y se puede detener la ejecución actual con Zen.cancelRun() (si se cancela, devuelve errorMsg: "cancelled").

1. Ejecutar un comando magick (asíncrona) #

function Zen.imageRun(args: string) : object

  • Entrada

    • args: parámetros completos de la línea de comando de magick (sin incluir el propio magick.exe), ensamblados por el frontend. Las rutas deben ir entre comillas dobles, p. ej. "D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • Salida

    {
  "error": 0,
  "stdout": "..."
}
    • Nota: el lado C++ no ensambla parámetros; solo ejecuta magick.exe <args> y captura el resultado. Si error es distinto de 0, errorMsg transmite el stderr de magick; stdout es la salida estándar de magick (resultado de comandos como identify)

function Zen.ffmpegRun(args: string) : object

  • Entrada

    • args: parámetros completos de la línea de comando de ffmpeg (sin incluir el propio ffmpeg.exe), ensamblados por el frontend. Las rutas deben ir entre comillas dobles, p. ej. -i "D:\in.mp4" -vf "scale=1280:720" -c:v libx264 -crf 23 "D:\out.mp4"

8. Capturas de pantalla y OCR #

1. Captura de pantalla/fijar en el escritorio #

function Zen.screenCap(mode:string, wait:bool, file: string) : object

  • Entrada

    • mode: modo

      • normal: normal

      • long: captura larga

      • fast: captura rápida al portapapeles (sin anotaciones, ideal para OCR)

      • quickocr: tras arrastrar para seleccionar un área, hace OCR + traducción de inmediato y muestra la traducción fijada en pantalla en la posición del texto original de la selección (OCR y traducción rápidos)

      • pinWin: capturar el área cliente de la ventana indicada y fijarla en el escritorio en su lugar (param acepta un HWND decimal)

    • wait: esperar a que termine la captura o no

    • param: ruta del archivo (pinFile); cadena de la región "x,y,w,h" (pinArea); HWND decimal (pinWin)

  • Salida

    {
    "error": 0,
    "errorMsg": ""
}

9. Cifrado y descifrado #

1. Cifrar datos #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • Entrada

    • target: datos a cifrar

      • Con type="text", una cadena de texto

      • Con type="data", datos binarios codificados en Base64

      • Con type="hex", una cadena hexadecimal

      • Con type="file", la ruta de un archivo

    • algorithm: algoritmo de cifrado

      • Cifrado simétrico: "aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • Cifrado asimétrico: "rsa-pkcs1", "rsa-oaep" (RSA, cifrado con clave pública y descifrado con clave privada), "sm2" (curva elíptica nacional sm2p256v1, cifrado con clave pública y descifrado con clave privada; en una sola pasada puede procesar datos de cualquier longitud, sin necesidad de bloques)

      • key/iv van en Base64; internamente se convierten a hexadecimal y se pasan en la forma enc -K <hex> -iv <hex>; la longitud de la clave debe coincidir exactamente con la del algoritmo

    • type: tipo de entrada (predeterminado "text")

      • "text": datos de texto

      • "data": datos binarios codificados en Base64

      • "hex": cadena hexadecimal

      • "file": ruta de archivo

    • key: en simétrico, la clave codificada en Base64; en asimétrico (rsa-*, sm2), texto PEM (para cifrar se pasa la clave pública y para descifrar la privada; se transmite tal cual, sin decodificar de Base64)

    • iv: vector de inicialización codificado en Base64 (opcional; lo requieren ciertos algoritmos; en asimétrico se ignora)

  • Salida

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

3. Generar claves #

function Zen.generateKey(algorithm: string, bits: string = '') : object

Punto de entrada unificado para la generación de claves (lo genera el openssl.exe integrado; el frontend no necesita depender de WebCrypto del navegador).

  • Entrada

    • algorithm: nombre del algoritmo

      • Simétrico: aes-128-cbc / aes-256-cbc / des-cbc / des-ede3-cbc / sm4-cbc / sm4-ecb / sm4-ctr / rc2-cbc / rc4 / bf-ecb, etc. (la longitud de la clave se deduce del nombre del algoritmo)

      • Asimétrico: "rsa" (bits surte efecto) / "sm2" (curva fija sm2p256v1)

    • bits: longitud en bits de la clave RSA ("2048"/"4096", por defecto 2048); se ignora en los algoritmos simétricos y en SM2

  • Salida

    // Simétrico
{ "error": 0, "algorithm": "aes-256-cbc", "key": "Base64编码的密钥" }
// Asimétrico
{ "error": 0, "algorithm": "sm2", "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n", "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n" }

4. Generar un IV #

function Zen.generateIv(algorithm: string) : object

Genera un IV aleatorio según el tamaño de bloque del algoritmo simétrico (lo genera el openssl.exe integrado).

  • Entrada

    • algorithm: nombre del algoritmo simétrico (misma lista de algoritmos simétricos que encrypt)

  • Salida

    { "error": 0, "algorithm": "aes-256-cbc", "iv": "Base64编码的IV" }

    Nota: el tamaño de bloque de AES/SM4 es de 16 bytes; DES/3DES/RC2 usan 8 bytes; el modo ECB y los cifrados de flujo (rc4) no necesitan IV, por lo que iv devuelve una cadena vacía.

5. Calcular un hash #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • Entrada

    • target: objetivo del cálculo; su significado varía según type

      • Con type="file", la ruta de un archivo

      • Con type="text", una cadena de texto (el resumen se calcula en UTF-8)

      • Con type="data", datos binarios codificados en Base64

      • Con type="hex", una cadena hexadecimal

    • algorithm: algoritmo de hash

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3" (resumen nacional SM3, 256 bits / 64 dígitos hexadecimales)

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512" (SHA-3 / Keccak, NIST FIPS 202)

      • "blake2b512" / "blake2s256" (BLAKE2, resúmenes modernos de alto rendimiento)

      • "crc32" (suma de comprobación CRC32, 8 dígitos hexadecimales)

      • "crc16" (suma de comprobación CRC16, 4 dígitos hexadecimales)

      • "checksum" (suma acumulada de bytes, 8 dígitos hexadecimales)

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512" (HMAC; el cuarto parámetro key es la clave y la salida es el MAC en hexadecimal)

    • type: tipo de entrada (opcional, por defecto "file")

      • "file": calcula el hash de un archivo

      • "text": calcula el hash de un texto

      • "data": calcula el hash de datos binarios (target debe ser una cadena Base64)

      • "hex": calcula el hash de una cadena hexadecimal (target es una cadena hex; se decodifica y se calcula por bytes)

  • Salida

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

13. Actualizaciones #

La actualización la realiza un proceso independiente, yyzUpdater.exe; el proceso principal solo se encarga de lanzarlo y sondear su estado.

1. Comprobar actualizaciones #

function Zen.checkUpdate() : object

Lanza yyzUpdater.exe --check-and-apply (comprobación + descarga + aplicación en un solo paso).

  • Entrada: ninguna

  • Salida

    { "error": 0, "errorMsg": "success" }

    Nota: error:0 solo indica que el actualizador se lanzó con éxito, no representa el resultado de la actualización. El estado "en curso / listo para aplicar" se consulta con getUpdateState.

2. Obtener el estado de la actualización #

function Zen.getUpdateState() : object

Sondea en tiempo real el estado de la actualización (para la encuesta de la bandeja):

  • si el updater se está ejecutando → mutex de instancia única Local\yyzUpdater_SingleInstance

  • si ya se descargó y está pendiente de aplicar → existencia de %APPDATA%\yyzTools\Update\update.ready (si existe, se analiza la versión del paquete main que contiene)

  • si una comprobación manual terminó sin actualizaciones → marcador %APPDATA%\yyzTools\Update\update.result (se elimina al leerlo)

  • Entrada: ninguna

  • Salida

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status: idle (sin actividad de actualización) / checking (actualizador en ejecución) / ready (descarga completada, listo para actualizar)

    • version: solo tiene valor en estado ready; es el número de la nueva versión pendiente de aplicar (se toma del paquete main); en los demás casos, cadena vacía

    • lastResult: solo puede tener valor en estado idle; es el resultado de la última comprobación manual (--check-and-apply): uptodate (ya está actualizado) / error (falló la comprobación); cadena vacía si no hay marcador. El marcador lo escribe el updater y esta interfaz lo elimina inmediatamente tras leerlo, por lo que solo se devuelve una vez, para que el frontend muestre un único Toast; la comprobación silenciosa --check no escribe el marcador y no genera molestias.

    • Prioridad de estados: checking > ready > idle

3. Aplicar una actualización ya descargada #

function Zen.applyUpdate() : object

Lanza yyzUpdater.exe --apply: lee update.ready → espera la salida del proceso principal → reemplaza los archivos → reinicia el proceso principal. Llamar solo cuando getUpdateState devuelve ready.

  • Entrada: ninguna

  • Salida

    { "error": 0, "errorMsg": "success" }

⚠️ Advertencias de seguridad #

La API nativa expone a los desarrolladores de módulos de forma completamente abierta las capacidades del sistema del proceso anfitrión, entre ellas operaciones de alto riesgo como la lectura, escritura y eliminación de archivos, la creación y terminación de procesos, el control de ventanas, la lectura y escritura del portapapeles, la modificación del registro y de la configuración del sistema, las descargas por red y la ejecución de líneas de comandos.

Estas interfaces no tienen diálogos de permisos, no aíslan en sandbox ni ofrecen mecanismo de deshacer—la llamada surte efecto directamente con los permisos del usuario actual, y un uso indebido puede provocar la pérdida permanente de datos o un mal funcionamiento del sistema.

Por lo tanto, presta especial atención a lo siguiente:

  • Evalúa la seguridad por ti mismo: antes de llamar a cualquier interfaz, comprueba que los parámetros (especialmente rutas, nombres de procesos y líneas de comando) provienen de una fuente confiable y están debidamente validados; para operaciones irreversibles como eliminar, sobrescribir o terminar procesos, se recomienda hacer antes una copia de seguridad o pedir una doble confirmación al usuario.
  • Desconfía de las entradas no confiables: nunca insertes sin validar la entrada del usuario, las respuestas de red o datos de terceros directamente en los parámetros de las interfaces; guárdate de la path traversal y de la inyección de comandos.
  • Principio de mínimo privilegio: solicita solo las capacidades que la función realmente necesite y evita, por comodidad, interfaces con un impacto mayor.
  • Responsabilidad del desarrollador: el desarrollador debe asumir todas las consecuencias derivadas del uso de esta API, incluidas, entre otras, la pérdida de datos, el daño al sistema y los riesgos de seguridad.
