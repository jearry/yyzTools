1. Allgemeine Konventionen #

Dieses Dokument definiert alle Schnittstellen zur Interaktion mit der nativen Schicht und deckt nur die im Hauptprozess yyzTools.exe registrierten Schnittstellen ab (SetupBindings() in src/yyztools/NativeApi.cpp).

Aufrufweise #

  • Das Frontend ruft Schnittstellenfunktionen über das Objekt window.Zen auf; empfohlen wird die einheitliche Verwendung der Wrapper-Klasse ZenAPI: web/lib/zen_api.js. Rufen Sie in Geschäftscode nicht direkt window.Zen auf – so dient die Wrapper-Klasse bei Upgrade-Anpassungen der Schnittstellen als Kompatibilitätsschicht.

  • Eingabe: Übergabe über Positionsparameter; konkrete Anzahl und Typen siehe jeweilige Schnittstelle

  • Ausgabe: Übergabe über den Rückgabewert, ein JSON-Objekt mit folgendem Aufbau

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error：0 korrekt, ungleich 0 fehlerhaft

    • errorMsg（optional）：Fehlermeldung

    • sonstige（optional）：siehe jeweilige Schnittstelle

Fehlererkennung #

error ist stets eine Zahl: 0 korrekt, ungleich 0 fehlerhaft (bei Aufrufausnahme -1).

Synchrone / asynchrone Bindung #

Die allermeisten Schnittstellen sind synchron gebunden (BindSync) und kehren sofort zurück. Die folgenden 7 Schnittstellen sind asynchron gebunden (BindAsync), laufen im Hintergrundthread und liefern über ein Promise zurück, ohne den UI-Thread zu blockieren:

getAppInfo、searchFile、imageRun、ffmpegRun、pdfRun、gsRun、ocrRecognition

Zum Verhaltensverhalten asynchroner Schnittstellen zu jedem Zeitpunkt siehe den jeweiligen Eintrag (die fünf Medien-Runner laufen z. B. serial und teilen sich cancelRun zum Abbrechen).

2. Konfiguration abrufen #

function Zen.getConfig(key?: string) : object

  • Ausgabe（Beispiel; tatsächliche Felder entsprechend der realen Konfiguration）

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel：Log-Stufe（0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal）

    • wallpaperEnabled：dynamisches Wallpaper aktiviert

    • overlayEnabled：Desktop-Effekte aktiviert

    • gameMode：Spielmodus

    • clipboardHistoryMaxCount：maximale Anzahl Zwischenablage-Verlaufseinträge

    • autoStart：Autostart beim Systemstart

    • shortcutKeys：globale Tastenkürzel

      • main：Hauptoberfläche

        • doubleCtrlEnabled：Doppel-Strg-Aufruf

        • doubleAltEnabled：Doppel-Alt-Aufruf

        • modifier：Modifikatortaste

        • virtualCode：Haupttaste

      • apps：Anwendungen

        • appId：Anwendungs-id

        • modifier：Modifikatortaste

        • virtualCode：Haupttaste

    • quickOpen：Schnellöffnen

      • name：Name

      • type：Typ（normal：universelle Suche / spec：vertikale Suche）

      • index：Indexnummer

      • url：url-Vorlage

      • enabled：aktiviert

    • customApps：eigene Apps

      • filePath：Pfad zur exe der App

      • enabled：aktiviert

    • dock：Dock（Kategorien + Inhalte）

      • Allgemeine Konvention: Fehlen name/icon bedeutet „eingebauten Standardwert verwenden"（wird von i18n bzw. der zur appId gehörigen .zenmod zur Laufzeit abgeleitet und folgt der Oberflächensprache）；ist das Feld vorhanden, hat der Benutzer es angepasst – es wird unverändert angezeigt und nicht mehr übersetzt.

      • categories：Kategorien

        • id：eingebaute Kategorien haben semantische ids（folder/tools/ai/game/system），vom Benutzer erstellte sind category_<Zeitstempel>

        • name：optional, erst nach Umbenennung durch den Benutzer vorhanden

        • icon：FontAwesome-Klasse

        • color：Designfarbe

        • order：Sortierreihenfolge

      • contents：Inhaltselemente

        • id：eingebaute Verzeichniselemente haben semantische ids（desktop/documents/downloads/music/videos），sonstige sind content_<Zeitstempel>

        • categoryId：id der zugehörigen Kategorie

        • type：app | folder | url

        • appId：bei type=app Pflichtfeld, entspricht der id der .zenmod；Name und Icon werden vollständig daraus abgeleitet, nicht auf der Platte speichern

        • folderPath：bei type=folder Pflichtfeld, unterstützt Umgebungsvariablen wie %USERPROFILE%

        • url：bei type=url Pflichtfeld, normalisierte vollständige Adresse（fehlendes Protokollpräfix wird automatisch um https:// ergänzt）；Klick öffnet im Standardbrowser des Systems. Der Name wird vom Benutzer eingegeben, das Icon wird zur Laufzeit als Favicon der Website abgerufen（Rückfall bei Fehlschlag fas fa-globe），nicht auf der Platte speichern

        • name / icon：optional, gleiche Semantik wie oben（bei type=folder für Benutzer-Verzeichnisse Pflichtfeld）

        • color：Icon-Färbung

        • order：Sortierreihenfolge innerhalb der Kategorie

3. Konfiguration ändern #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • Eingabe

    • config：wie getConfig

      • Nur übergeben, was geändert werden soll; nicht der gesamte Inhalt nötig

      • Inhalt unter demselben Schlüssel muss vollständig übergeben werden

      {
    "logLevel": "1"
}

    • replace（optional, Standard false）：false=inkrementell in die bestehende Konfiguration zusammenführen, true=gesamte Ersetzung（für Backup-Import, entfernt auch gelöschte Listeneinträge）。Als Zeichenkette "true" oder "false" übergeben; fehlend entspricht "false"。

  • Hinweis：Nicht „erst die gesamte Konfiguration mit getConfig lesen und sie dann komplett mit setConfig zurückschreiben"——der Rückgabewert von getConfig enthält das Feld error; schreibt man alles zurück, landet es in der Konfigurationsdatei. Immer schmal granular schreiben, z. B. setConfig({ dock: { categories } })。

  • Ausgabe

    {
    "error": 0,
    "errorMsg": ""
}

3. Fensterstatus abrufen #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • Eingabe

    • window：Name oder HWND als string, siehe Fenstersteuerung

2. App-Informationen per id im Batch abrufen（asynchron） #

function Zen.getAppInfo(appIds: string[]) : object

In der Konfiguration wird nur die appId gespeichert; Name und Icon werden stets zur Laufzeit abgeleitet（der name einer .zenmod ist mehrsprachig – in die Konfiguration eingefrorene Snapshots wären nach einem Sprachwechsel veraltet）. Genau für diesen Szenario ist dieser Aufruf gedacht.

⚠️ Nicht mit einer Schleife über searchApp(appId, 1) ersetzen：searchApp macht bei jedem Aufruf einen vollständigen Tabellenscan über den gesamten App-Index + Pinyin-Abgleich + Score-Sortierung, startet zusätzlich zwei Threads parallel und liefert mehrere Ergebnisse mit base64-Icons. Dock plus Tastenkürzel umfassen Dutzende appIds; einzeln abgefragt verlangsamt das den Start spürbar. Dieser Aufruf holt alles auf einmal; die native Seite trifft exakt über map::find.

Intern wird gewartet, bis der App-Index bereit ist（der Index wird von einem Hintergrundthread erzeugt）; daher ist es asynchron gebunden und ein früher Aufruf im Kaltstart liefert kein leeres Ergebnis.

  • Eingabe

    • appIds：Array von appIds, z. B. ["calculator", "Microsoft.WindowsCamera"]

  • Ausgabe

    Format identisch zu searchApp（dasselbe BuildAppResult），aber：

    • nur exakt getroffene Einträge werden zurückgegeben, nicht gefundene ids werden stillschweigend übersprungen; daher kann apps.length kleiner als die Länge der Eingabe sein（damit lassen sich ungültige appIds in der Konfiguration aufspüren）

    • Reihenfolge folgt der Eingabereihenfolge, score ist stets 0（nicht am Scoring beteiligt）

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

7. Medienverarbeitung #

Die fünf Medien-Runner werden von der C++-Seite über die CLI-Tools von Drittanbietern unter bin64\Platform\ ausgeführt. Alle außer ffprobeRun sind asynchron gebunden（Ausführung im Hintergrundthread, blockiert den UI-Thread nicht）；die Stapelverarbeitung ist serial – zu jedem Zeitpunkt läuft nur ein Unterprozess; mit Zen.cancelRun() kann die aktuelle Ausführung abgebrochen werden（bei Abbruch wird errorMsg: "cancelled" zurückgegeben）.

1. magick-Befehl ausführen（asynchron） #

  • Eingabe

    • args：vollständige magick-Kommandozeilenargumente（ohne magick.exe selbst）, vom Frontend zusammengebaut. Pfade müssen selbst in doppelte Anführungszeichen gesetzt werden, z. B. "D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • Ausgabe

  "error": 0,
  "stdout": "..."
}

  • Hinweis：die C++-Seite baut keine Argumente zusammen, sie führt nur magick.exe <args> aus und fängt das Ergebnis ab. Bei error ungleich 0 wird das magick-stderr über errorMsg durchgereicht; stdout ist die Standardausgabe von magick（Ergebnis von identify u. a.）

9. Verschlüsselung und Entschlüsselung #

1. Daten verschlüsseln #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • Eingabe

    • target：die zu verschlüsselnden Daten

      • bei type="text" eine Textzeichenkette

      • bei type="data" base64-kodierte Binärdaten

      • bei type="hex" eine Hexadezimalzeichenkette

      • bei type="file" ein Dateipfad

    • algorithm：Verschlüsselungsalgorithmus

      • symmetrische Verschlüsselung："aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • asymmetrische Verschlüsselung："rsa-pkcs1", "rsa-oaep"（RSA, Verschlüsselung mit öffentlichem Schlüssel, Entschlüsselung mit privatem Schlüssel）、"sm2"（chinesischer Standard, elliptische Kurve sm2p256v1, Verschlüsselung mit öffentlichem Schlüssel, Entschlüsselung mit privatem Schlüssel; verarbeitet in einem Durchgang beliebige Längen, ohne Blockaufteilung）

      • key/iv sind Base64; intern in Hexadezimal konvertiert und in der Form enc -K <hex> -iv <hex> übergeben; die Schlüssellänge muss exakt zum Algorithmus passen

    • type：Eingabetyp（Standard "text"）

      • "text"：Textdaten

      • "data"：base64-kodierte Binärdaten

      • "hex"：Hexadezimalzeichenkette

      • "file"：Dateipfad

    • key：bei symmetrischer Verschlüsselung der base64-kodierte Schlüssel; bei asymmetrischer（rsa-*, sm2）PEM-Text（zum Verschlüsseln den öffentlichen, zum Entschlüsseln den privaten Schlüssel übergeben; unverändert durchgereicht, ohne Base64-Dekodierung）

    • iv：base64-kodierter Initialisierungsvektor（optional, manche Algorithmen benötigen ihn; bei asymmetrischen ignoriert）

  • Ausgabe

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

5. Einen Hash berechnen #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • Eingabe

    • target：Berechnungsziel, Bedeutung hängt von type ab

      • bei type="file" ein Dateipfad

      • bei type="text" eine Textzeichenkette（Digest wird als UTF-8 berechnet）

      • bei type="data" base64-kodierte Binärdaten

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512"（SHA-3 / Keccak, NIST FIPS 202）

      • "blake2b512" / "blake2s256"（BLAKE2, moderner leistungsstarker Digest）

      • "crc32"（CRC32-Prüfsumme, 8 Hexadezimalstellen）

      • "crc16"（CRC16-Prüfsumme, 4 Hexadezimalstellen）

      • "checksum"（aufsummierte Byte-Summe, 8 Hexadezimalstellen）

      • "data"：Hash der Binärdaten berechnen（target muss eine Base64-Zeichenkette sein）

      • "hex"：Hash der Hexadezimalzeichenkette berechnen（target ist eine hex-Zeichenkette, nach Dekodierung byteweise berechnet）

  • Ausgabe

13. Aktualisierung #

Die Aktualisierung erfolgt durch einen eigenen Prozess yyzUpdater.exe; der Hauptprozess ist nur für den Start und die Statusabfrage zuständig.

1. Nach Updates suchen #

function Zen.checkUpdate() : object

Startet yyzUpdater.exe --check-and-apply（Prüfung + Download + Anwendung in einem Durchgang）.

  • Eingabe：keine

  • Ausgabe

    { "error": 0, "errorMsg": "success" }

    Hinweis：error:0 bedeutet nur, dass der Updater erfolgreich gestartet wurde, nicht das Ergebnis der Aktualisierung. Den Status „Aktualisierung läuft"/„bereit" mit getUpdateState abfragen.

2. Update-Status abrufen #

function Zen.getUpdateState() : object

Erkennt den Update-Status in Echtzeit（für das Polling des Taskleisten-Trays）：

  • läuft der updater → Singleton-Mutex Local\yyzUpdater_SingleInstance

  • wurde bereits heruntergeladen und wartet auf Anwendung → Existenz von %APPDATA%\yyzTools\Update\update.ready（falls vorhanden, wird die Version des main-Pakets daraus geparst）

  • manuelle Prüfung beendet und kein Update → Marker %APPDATA%\yyzTools\Update\update.result（beim Lesen sofort gelöscht）

  • Eingabe：keine

  • Ausgabe

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status：idle（keine Update-Aktivität）/ checking（Updater läuft）/ ready（Download abgeschlossen, Upgrade möglich）

    • version：nur im Zustand ready belegt, mit der neuen anzuwendenden Versionsnummer（aus dem main-Paket）, sonst leere Zeichenkette

    • lastResult：nur im Zustand idle möglicherweise belegt, mit dem Ergebnis der letzten manuellen Prüfung（--check-and-apply）：uptodate（bereits aktuell）/ error（Prüfung fehlgeschlagen）; ohne Marker leere Zeichenkette. Der Marker wird vom updater geschrieben und von diesem Aufruf unmittelbar nach dem Lesen gelöscht, daher wird er nur einmal zurückgegeben – das Frontend kann einmalig einen Toast anzeigen; das stille --check schreibt keinen Marker und verursacht keine Störung.

    • Statuspriorität：checking > ready > idle

3. Bereits heruntergeladenes Update anwenden #

function Zen.applyUpdate() : object

Startet yyzUpdater.exe --apply：liest update.ready → wartet auf das Ende des Hauptprozesses → ersetzt die Dateien → startet den Hauptprozess neu. Nur aufrufen, wenn getUpdateState ready liefert.

  • Eingabe：keine

  • Ausgabe

    { "error": 0, "errorMsg": "success" }

⚠️ Sicherheitshinweise #

Die Native API bietet Modulentwicklern vollständigen Zugriff auf die Systemfähigkeiten des Host-Prozesses, einschließlich Lesen/Schreiben/Löschen von Dateien, Erstellen und Beenden von Prozessen, Fenstersteuerung, Lesen/Schreiben der Zwischenablage, Änderung von Registrierung und Systemeinstellungen, Netzwerk-Downloads und Ausführung von Kommandozeilen – allesamt hochriskante Operationen.

Diese Schnittstellen haben keine Berechtigungsdialoge, keine Sandbox-Isolation und keinen Rückgängig-Mechanismus – ein Aufruf wirkt sofort mit den Rechten des aktuellen Benutzers; Missbrauch kann zu dauerhaftem Datenverlust oder Systemstörungen führen.

Beachten Sie daher unbedingt:

  • Sicherheit selbst bewerten: Prüfen Sie vor jedem Schnittstellenaufruf, ob die Parameter (insbesondere Pfade, Prozessnamen, Kommandozeilen) aus vertrauenswürdiger Quelle stammen und hinreichend validiert sind; bei unwiderruflichen Operationen wie Löschen, Überschreiben oder Beenden von Prozessen wird ein vorheriges Backup oder eine zweite Bestätigung durch den Benutzer empfohlen.
  • Vor nicht vertrauenswürdigen Eingaben auf der Hut sein: Fügen Sie niemals Benutzereingaben, Netzwerkantworten oder Drittanbieter-Daten ohne Validierung direkt in Schnittstellenparameter ein; hüten Sie sich vor Pfad-Traversal und Command Injection.
  • Prinzip der geringsten Privilegien: Fordern Sie nur die Fähigkeiten an, die Ihre Funktion wirklich benötigt; vermeiden Sie aus Bequemlichkeit Schnittstellen mit größerer Wirkbreite.
  • Verantwortung liegt beim Entwickler: Der Entwickler trägt sämtliche Folgen aus der Nutzung dieser API selbst, einschließlich, aber nicht beschränkt auf Datenverlust, Systembeschädigung und Sicherheitsrisiken.
