1. Общие соглашения #

Этот документ определяет все интерфейсы, связанные со взаимодействием с Native, и охватывает только интерфейсы, зарегистрированные главным процессом yyzTools.exe (SetupBindings() в src/yyztools/NativeApi.cpp).

Способ вызова #

  • Фронтенд вызывает функции интерфейсов через объект window.Zen; рекомендуется единообразно использовать класс-обёртку ZenAPI: web/lib/zen_api.js. Не обращайтесь к window.Zen напрямую из бизнес-кода — это удобно использовать как слой совместимости интерфейсов при их изменении при обновлениях.

  • Входные данные: передаются позиционными аргументами; конкретное количество и типы параметров см. в описании соответствующего интерфейса.

  • Выходные данные: передаются через возвращаемое значение, значением является json-объект, содержащий следующее:

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error: 0 — успех, не 0 — ошибка

    • errorMsg (необязательно): сообщение об ошибке

    • прочее (необязательно): см. конкретный интерфейс

Способ определения ошибок #

error всегда число: 0 — успех, не 0 — ошибка (при исключении вызова — -1).

Синхронная / асинхронная привязка #

Подавляющее большинство интерфейсов имеют синхронную привязку (BindSync) — вызов возвращает результат сразу. Следующие 7 интерфейсов имеют асинхронную привязку (BindAsync), выполняются в фоновом потоке, возвращают результат через Promise и не блокируют поток UI:

getAppInfo, searchFile, imageRun, ffmpegRun, pdfRun, gsRun, ocrRecognition

Ограничения на поведение асинхронных интерфейсов в каждый момент времени см. в конкретных статьях (например, медиапятёрка выполняется последовательно, отмена общая через cancelRun).

2. Общие интерфейсы #

1. Получение версии клиента #

function Zen.getVersion() : object

  • Входные данные: нет

  • Выходные данные

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion: информация о версии API клиента. При каждом обновлении интерфейсов номер версии увеличивается на 1; цифры от 0 до 9, после 9 снова с 0, например 1.0.0, 1.0.1, 1.0.2... 1.0.9, 1.1.0 и т. д.

    • appVersion: информация о версии клиента

    • usageTime: время использования (единица: с)

    • usageTimes: количество активаций

    • firstUseTime: время первого использования, формат: yyyymmdd

2. Получение конфигурации #

function Zen.getConfig(key?: string) : object

  • Входные данные

    • key (необязательно): взять только этот ключ, поддерживается точечный путь a.b. Без аргумента возвращается вся конфигурация.

      • Совпадение: возвращает {"error":0, "<key>": <значение>}, например getConfig("language") → {"error":0,"language":"zh_cn"}; getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • Нет совпадения: возвращает {"error":0} (без ошибки, вызывающая сторона сама обрабатывает запасной вариант)

  • Выходные данные (пример; поля зависят от фактической конфигурации)

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel: уровень журналирования (0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal)

    • wallpaperEnabled: включить динамические обои

    • overlayEnabled: включить эффекты рабочего стола

    • gameMode: игровой режим

    • clipboardHistoryMaxCount: максимальное количество записей в истории буфера обмена

    • autoStart: автозапуск при включении

    • shortcutKeys: глобальные горячие клавиши

      • main: главный интерфейс

        • doubleCtrlEnabled: вызов двойным нажатием Ctrl

        • doubleAltEnabled: вызов двойным нажатием Alt

        • modifier: клавиша-модификатор

        • virtualCode: основная клавиша

      • apps: приложения

        • appId: id приложения

        • modifier: клавиша-модификатор

        • virtualCode: основная клавиша

    • quickOpen: быстрый запуск

      • name: название

      • type: тип (normal: обычный поиск / spec: вертикальный поиск)

      • index: порядковый номер

      • url: шаблон url

      • enabled: включено ли

    • customApps: пользовательские приложения

      • filePath: путь к exe соответствующего приложения

      • enabled: включено ли

    • dock: док-панель (категории + содержимое)

      • Общее соглашение: отсутствие name/icon означает «использовать встроенное значение по умолчанию» (выводится во время выполнения из i18n или из .zenmod, соответствующего appId, меняется вместе с языком интерфейса); наличие поля означает, что пользователь настроил его — отображается как есть и больше не переводится.

      • categories: категории

        • id: встроенные категории — семантические id (folder/tools/ai/game/system), созданные пользователем — category_<метка времени>

        • name: необязательно, появляется только после переименования пользователем

        • icon: FontAwesome class

        • color: цвет темы

        • order: порядковый номер сортировки

      • contents: элементы содержимого

        • id: встроенные элементы каталогов — семантические id (desktop/documents/downloads/music/videos), остальные — content_<метка времени>

        • categoryId: id категории, к которой относится элемент

        • type: app | folder | url

        • appId: обязателен при type=app, соответствует id из .zenmod; имя и иконка полностью выводятся из него, не сохранять на диск

        • folderPath: обязателен при type=folder, поддерживает переменные окружения вроде %USERPROFILE%

        • url: обязателен при type=url, нормализованный полный адрес (без префикса протокола автоматически добавляется https://); открывается браузером по умолчанию системы. Имя вводит пользователь, иконка захватывается во время выполнения с favicon сайта (при неудаче запасной вариант fas fa-globe), не сохранять на диск

        • name / icon: необязательно, семантика та же (обязательны для выбранных пользователем каталогов type=folder)

        • color: тонировка иконки

        • order: порядковый номер сортировки внутри своей категории

3. Изменение конфигурации #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • Входные данные

    • config: как в getConfig

      • Передавайте только то, что меняете, весь состав передавать не нужно

      • Содержимое под одним ключом нужно передавать полностью

      {
    "logLevel": "1"
}

    • replace (необязательно, по умолчанию false): false — инкрементальное слияние с существующей конфигурацией, true — полная замена (для импорта резервной копии, позволяет очистить удалённые элементы списков). Передаётся строка "true" или "false", отсутствие эквивалентно "false".

  • Примечание: не «читайте всю конфигурацию через getConfig и не записывайте её целиком через setConfig» — возвращаемое значение getConfig содержит поле error, и полная запись сохранит его в файл конфигурации. Всегда пишите узкогранулярно, например setConfig({ dock: { categories } }).

  • Выходные данные

    {
    "error": 0,
    "errorMsg": ""
}

7. Запись кэша обратного отсчёта #

function Zen.setCountdownCache(data: string) : object

Кэшированные данные напоминаний с обратным отсчётом, записываются в память, общую для главного процесса и процесса обоев, и немедленно уведомляют процесс обоев о перечитывании (иначе обои подхватят их только при собственном 30-секундном опросе). Предназначено для связки reminder / wallpaper, обычному бизнесу полагаться на него не следует.

  • Входные данные

    • data: JSON-строка обратного отсчёта (payload, определённый модулем reminder)

  • Выходные данные

    {
    "error": 0,
    "errorMsg": ""
}

3. Получение состояния окна #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • Входные данные

    • window: Name или string-форма HWND, см. «Управление окном»

    • can_suspend (необязательно): разрешить ли приостановку WebView этого окна (переключатель экономии ресурсов, по умолчанию false)

  • Примечание: интерфейс имеет побочный эффект — после запроса состояния, если окно в состоянии show/max, рендеринг WebView возобновляется, иначе WebView приостанавливается для экономии ресурсов (приостановка разрешена только при can_suspend = true). При постоянном опросе собственного состояния страницей фронтенда передавайте true, при обычных запросах — false.

  • Выходные данные

    {
    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state: состояние (show: нормальный показ / min: свёрнуто / max: развёрнуто / close: закрыто)

    • topmost: закреплено ли поверх всех окон

2. Пакетное получение информации о приложениях по id (асинхронно) #

function Zen.getAppInfo(appIds: string[]) : object

В конфигурации хранится только appId, имя и иконка всегда выводятся во время выполнения (name в .zenmod многоязычный, снимок в конфигурации устареет после смены языка). Именно для этого сценария и предназначен этот интерфейс.

⚠️ Не заменяйте его циклом searchApp(appId, 1): каждый вызов searchApp выполняет полный скан всего индекса приложений + пиньинь-сопоставление + оценку и сортировку, дополнительно запускает два потока и возвращает несколько записей с иконками base64. В док-панели вместе с горячими клавишами десятки appId — запросы по одному заметно замедлят запуск. Этот интерфейс собирает всё за один вызов, на native-стороне — точное попадание через map::find.

Внутри дожидается готовности индекса приложений (индекс формируется фоновым потоком), поэтому привязка асинхронная: вызов в начале холодного старта не вернёт пустой результат.

  • Входные данные

    • appIds: массив appId, например ["calculator", "Microsoft.WindowsCamera"]

  • Выходные данные

    Формат полностью совпадает с searchApp (тот же BuildAppResult), но:

    • возвращаются только точно совпавшие элементы, ненайденные id молча пропускаются, поэтому apps.length может быть меньше длины входного массива (используется для выявления недействительных appId в конфигурации)

    • порядок соответствует порядку аргументов, score всегда 0 (в оценке не участвует)

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

7. Обработка медиа #

Медиапятёрка запускает сторонние CLI-инструменты из bin64\Platform\ на стороне C++. Все, кроме ffprobeRun, имеют асинхронную привязку (выполняются в фоновом потоке, не блокируют поток UI); пакетная обработка последовательная, одновременно выполняется только один подпроцесс, текущее выполнение можно прервать через Zen.cancelRun() (при отмене возвращается errorMsg: "cancelled").

1. Выполнение команды magick (асинхронно) #

function Zen.imageRun(args: string) : object

  • Выходные данные

    {
  "error": 0,
  "stdout": "..."

  • Примечание: сторона C++ не собирает аргументы, только выполняет magick.exe <args> и захватывает результат. При error ≠ 0 errorMsg прозрачно передаёт stderr magick; stdout — стандартный вывод magick (результат команд identify и т. п.)

8. Скриншоты и OCR #

1. Скриншот / закрепление на рабочем столе #

function Zen.screenCap(mode:string, wait:bool, file: string) : object

  • Входные данные

    • mode: режим

      • normal: обычный

      • long: длинный скриншот

      • fast: быстрый скриншот в буфер обмена (без аннотаций, подходит для OCR)

      • quickocr: сразу после выделения области — OCR+перевод, перевод отображается поверх экрана в месте исходного текста выделения (быстрый OCR-перевод)

      • pinClipboard: закрепить изображение из буфера обмена на рабочем столе

      • pinFile: закрепить изображение из файла на рабочем столе

      • pinArea: захватить указанную область экрана и закрепить её на рабочем столе на месте (param принимает "x,y,w,h" в физических пикселях)

9. Шифрование и расшифровка #

1. Шифрование данных #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • Входные данные

    • target: данные для шифрования

      • при type="text" — текстовая строка

      • при type="data" — двоичные данные в кодировке Base64

      • при type="hex" — шестнадцатеричная строка

      • при type="file" — путь к файлу

    • algorithm: алгоритм шифрования

      • Симметричное шифрование: "aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • Асимметричное шифрование: "rsa-pkcs1", "rsa-oaep" (RSA, шифрование открытым ключом, расшифровка закрытым), "sm2" (отечественная эллиптическая кривая sm2p256v1, шифрование открытым ключом, расшифровка закрытым; за один раз обрабатывает данные любой длины, блочное разбиение не требуется)

      • key/iv в Base64; внутри переводятся в шестнадцатеричный вид и передаются как enc -K <hex> -iv <hex>, длина ключа должна точно соответствовать алгоритму

    • type: тип входных данных (по умолчанию "text")

      • "text": текстовые данные

      • "data": двоичные данные в кодировке Base64

      • "hex": шестнадцатеричная строка

      • "file": путь к файлу

    • key: для симметричных — ключ в кодировке Base64; для асимметричных (rsa-*, sm2) — текст PEM (для шифрования передаётся открытый ключ, для расшифровки — закрытый, передаётся как есть, Base64-декодирование не выполняется)

    • iv: вектор инициализации в кодировке Base64 (необязательно, нужен для некоторых алгоритмов; для асимметричных игнорируется)

  • Выходные данные

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

function Zen.generateIv(algorithm: string) : object

5. Вычисление хеша #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • Входные данные

    • target: цель вычисления, смысл зависит от type

      • при type="file" — путь к файлу

      • при type="text" — текстовая строка (дайджест вычисляется в UTF-8)

      • при type="data" — двоичные данные в кодировке Base64

      • при type="hex" — шестнадцатеричная строка

    • algorithm: алгоритм хеширования

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3" (отечественный дайджест SM3, 256 бит / 64 шестнадцатеричных знака)

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512" (SHA-3 / Keccak, NIST FIPS 202)

      • "blake2b512" / "blake2s256" (BLAKE2, современный высокопроизводительный дайджест)

      • "crc32" (контрольная сумма CRC32, 8 шестнадцатеричных знаков)

      • "crc16" (контрольная сумма CRC16, 4 шестнадцатеричных знака)

      • "checksum" (накопительная сумма байтов, 8 шестнадцатеричных знаков)

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512" (HMAC, 4-й параметр key — ключ, вывод — шестнадцатеричный MAC)

    • type: тип входных данных (необязательно, по умолчанию "file")

      • "file": вычислить хеш файла

      • "text": вычислить хеш текста

      • "data": вычислить хеш двоичных данных (target должен быть строкой Base64)

      • "hex": вычислить хеш шестнадцатеричной строки (target — hex-строка, вычисляется побайтово после декодирования)

  • Выходные данные

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

13. Обновление #

Обновление выполняет отдельный процесс yyzUpdater.exe, главный процесс только запускает его и опрашивает состояние.

1. Проверка обновлений #

function Zen.checkUpdate() : object

Запускает yyzUpdater.exe --check-and-apply (проверка + загрузка + применение одним циклом).

  • Входные данные: нет

  • Выходные данные

    { "error": 0, "errorMsg": "success" }

    Примечание: error:0 означает только успешный запуск обновлятора, но не результат обновления. Состояние «обновление идёт / готово к применению» запрашивается через getUpdateState.

2. Получение состояния обновления #

function Zen.getUpdateState() : object

Опрашивает состояние обновления в реальном времени (для опроса из трея):

  • запущен ли updater → мьютекс единственного экземпляра Local\yyzUpdater_SingleInstance

  • загружено ли и ждёт ли применения → существует ли %APPDATA%\yyzTools\Update\update.ready (если существует, разбирается version пакета main)

  • завершилась ли ручная проверка без обновлений → маркер %APPDATA%\yyzTools\Update\update.result (считывается и удаляется)

  • Входные данные: нет

  • Выходные данные

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status: idle (нет активности обновления) / checking (обновлятор работает) / ready (загрузка завершена, можно обновиться)

    • version: значение только в состоянии ready — номер новой версии, ожидающей применения (берётся из пакета main), в остальных случаях пустая строка

    • lastResult: значение возможно только в состоянии idle — результат последней ручной проверки (--check-and-apply): uptodate (уже последняя версия) / error (проверка не удалась), при отсутствии маркера — пустая строка. Маркер пишется обновлятором и удаляется этим интерфейсом сразу после чтения, поэтому возвращается только один раз — фронтенд показывает один Toast; тихий --check маркер не пишет и не создаёт беспокойства.

    • Приоритет состояний: checking > ready > idle

3. Применение загруженного обновления #

function Zen.applyUpdate() : object

Запускает yyzUpdater.exe --apply: читает update.ready → ждёт выхода главного процесса → заменяет файлы → перезапускает главный процесс. Вызывать только когда getUpdateState возвращает ready.

  • Входные данные: нет

  • Выходные данные

    { "error": 0, "errorMsg": "success" }
