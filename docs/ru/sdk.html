Быстрый старт

Первый модуль без каких-либо инструментов сборки

Справочник API Скачать пример проекта

Документ адресован разработчикам модулей и демонстрирует, как с нуля создать веб-приложение, работающее внутри главного процесса yyzTools (на примере образцового проекта SDK SDK_Sample — сверхбыстрого файлового поисковика). Охватываются: структура каталога страницы, оконный хост, i18n, асинхронный Native API (полнодисковый поиск файлов), открытие файлов, сохранение конфигурации, а также шаблон добавления native-методов на случай расширения возможностей C++.

Образец — чистый нативный JS, нулевые сторонние зависимости, без этапа сборки: не нужны Vite / Alpine / FontAwesome; достаточно скопировать каталоги Web и Modules в каталог yyzTools.exe.

1. Каталог образца и способ развертывания #

sdk/sample/
  Web/                        ← скопировать в <каталог yyzTools.exe>\Web\        (слить с существующим каталогом Web)
    SDK_Sample/               ← самодостаточный каталог образца, вся папка — один цельный модуль
      index.html              # структура страницы (нативный DOM, места текстов помечены data-i18n)
      filefinder.js           # вся логика: поиск / открытие / история / Esc
      filefinder.css          # стили страницы (все через переменные --zen-*, автоматическая адаптация к светлой/тёмной теме)
      i18n.js                 # словарь текстов (zh_cn / en)
      lib/
        zen_api.js            # класс-обёртка ZenAPI (JS-обёртка Native API, единственная зависимость lib)
        window_controls.css   # переменные темы (--zen-*) + стили панели управления окном
  Modules/                   ← скопировать в <каталог yyzTools.exe>\Modules\    (слить с существующим каталогом Modules)
    SDK_Sample.zenmod         # объявление модуля type:"web", ModuleManager автоматически создаёт окно-хост

Развертывание:

Скопируйте/слейте sdk/sample/Web     в bin64\Web\
Скопируйте/слейте sdk/sample/Modules в bin64\Modules\
Перезапустите yyzTools.exe и найдите «SDK样例工程» в командной панели для запуска

Соглашение о месте, из которого читает главная программа:

Ресурс Расположение
Страница <exe目录>\Web\{page}\index.html
Модули <exe目录>\Modules\<分类>\*.zenmod (сканируется один уровень подкаталогов)

2. Обзор архитектуры: как работает веб-приложение #

Modules/SDK_Sample.zenmod   ← файл модуля с type:"web" (управляется данными, C++ писать не нужно)
        │  главная программа при запуске сканирует .zenmod
        ▼
WebModule окно-хост (нативное окно + WebView2)
        │  загружает Web\SDK_Sample\index.html
        ▼
Web/SDK_Sample/             ← весь ваш фронтенд-код (нативный JS, ноль зависимостей)
        │  window.Zen.xxx(...)  ←→  нативные интерфейсы, зарегистрированные главной программой
        ▼
Менеджеры C++ (файлы/процессы/окна/буфер обмена/OCR...)

Ключевые выводы:

  • Не нужно писать ни строчки кода на C++. .zenmod с type: "web" главная программа автоматически создает как окно-хост WebModule; размер окна, иконка и многоязычное имя задаются самим файлом модуля.

  • Модуль автоматически получает: поиск в командной панели (включая пиньинь-индекс), привязку глобальных горячих клавиш, подключение к док-панели, регистрацию имени в таблице windowControl.

  • Единственный канал между фронтендом и C++ — window.Zen; вызывайте всё единообразно через класс-обёртку ZenAPI (в образце уже приложен lib/zen_api.js).

  • Страница без сборки — это просто статические файлы: после правки достаточно обновить окно (windowControl('sdk_sample','hide') и затем show, либо перезапуск exe), никакой компиляции не требуется.

3. Структура страницы (нативный JS, четыре файла) #

index.html #

Не подключает никаких сторонних библиотек; три кнопки панели управления окном используют символы Unicode как иконки (− / □ / ×), стили предоставляются lib/window_controls.css. Места текстов размечены data-i18n / data-i18n-ph и заполняются JS при инициализации. Структура из четырёх блоков: строка поиска, чипы истории поиска, строка состояния (количество результатов + подсказка по синтаксису), список результатов:

<div class="search-bar">
    <input type="text" id="searchInput" class="search-input" data-i18n-ph="inputPlaceholder"
           spellcheck="false" autocomplete="off">
    <button class="search-btn" id="btnSearch" data-i18n="search"></button>
</div>
<div class="history-chips" id="historyChips"> ... </div>
<div class="status-bar">
    <span id="statusText" data-i18n="empty"></span>
    <span class="syntax-hint" data-i18n="syntaxHint"></span>
</div>
<div class="result-list" id="resultList"></div>

filefinder.js (основная логика) #

Пять обязанностей, всё можно просто скопировать из образца:

  1. Управление окном: ZenAPI.windowControl('sdk_sample', 'min'|'max'|'close'|'drag'); перетаскивание заголовка срабатывает только при смещении более 5px; клавиша Esc — если фокус в поле ввода, сначала blur, иначе закрыть окно.
  2. Тема: регистрируется window.__applyTheme для приёма обратных вызовов от C++ (data-theme на первом экране внедряется C++, JS обрабатывать не нужно).
  3. i18n: читается getConfig().language, тексты берутся из словаря, обходятся элементы с data-i18n и заполняются; предложения с заполнителем {{count}} раскрываются функцией интерполяции.
  4. Поиск: searchFile(keyword, maxResults) — интерфейс с асинхронной привязкой (выполняется в фоновом потоке, не блокирует UI); поиск сразу по Enter и автоматически с антидребезгом ввода 300 мс; возрастающий порядковый номер используется для отбрасывания приходящих не по порядку ответов — на native-стороне есть механизм слотов поиска (новый запрос сразу вытесняет незавершённый старый, старый Promise получает пустой результат), фронтендовый порядковый номер не даёт этому «пустому результату, пришедшему позже» затереть рендер новых результатов; оба механизма работают в связке.
  5. Действия с результатами: openFile(fullPath, false) открывает файл (то же по двойному щелчку; второй параметр — «запуск от администратора»); openFileLocation(fullPath) открывает содержащий каталог; полный путь собирается как path + '\\' + name; иконка берётся прямо из готового поля icon в результатах (base64); размер файла форматируется из числового поля size.

Структура возврата searchFile ({ error, files[] }) #

Поля каждого элемента files[]:

Поле Тип Описание
name / path строка Имя файла / содержащий каталог. Полный путь = path + '\\' + name
dateModified строка Время изменения (локализованный текстовый формат)
size число Размер файла в байтах, нативное число, использовать напрямую
icon строка Иконка base64, подключается прямо в <img src>, вызывать getFileIcon не нужно
score число Оценка релевантности (native уже отсортировал по ней)
isDir число Число 1/0, а не нативный булев (путь ручной сборки JSON), проверяйте через truthy или === 1, не === true

Обзор интерфейсов, вызываемых в этом образце #

Интерфейс Привязка Назначение
searchFile(keyword, maxResults) асинхронная Полнодисковый поиск по MFT-индексу, поддержка синтаксиса Everything (size:>100MB, ext:mp4, !ext:tmp)
openFile(path, admin) синхронная Открыть файл/каталог (поведение shell по умолчанию), при admin=true — от имени администратора
openFileLocation(path) синхронная Показать файл в Проводнике
getConfig(key?) синхронная Чтение конфигурации: без аргумента — вся, с key — только этот ключ (поддержка точечного пути a.b)
setConfig(patch, replace?) синхронная Узкогранулярная запись истории поиска: setConfig({ sdk_sample: { history } }); replace=true — полная замена (только для импорта резервной копии)
log(message) синхронная Лог фронтенда, пишется в журнал главного процесса, удобно для отладки
windowControl(name, action) синхронная Минимизация/максимизация/закрытие/перетаскивание окна

Правила вызова (четыре железных правила) #

import ZenAPI from './lib/zen_api.js';

// 1. 判错用 isOk()（error 恒为数字：0 成功，-1 表示调用异常）
const res = await ZenAPI.searchFile('yyztools', 200);
if (!ZenAPI.isOk(res)) { ... }

// 2. 接口返回的布尔字段是原生布尔，直接判断
//    （例外一：config 的值由前端写入决定类型，通常是字符串，比较时注意归一）
//    （例外二：searchFile 结果的 isDir 是 1/0 数字——手拼 JSON 路径，用 truthy 或 === 1）
const ex = await ZenAPI.exists(path);
if (ex.exists === true) { ... }

// 3. 配置写入必须窄粒度，禁止全量回写
await ZenAPI.setConfig({ sdk_sample: { history } });   // 只写自己的键

// 4. 按 id 批量取应用信息用 getAppInfo，禁止循环 searchApp
const infos = await ZenAPI.getAppInfo(['calculator', 'ocr']);

Асинхронные интерфейсы (getAppInfo / searchFile / медиапятёрка / ocrRecognition) выполняются в фоновом потоке; учтите, что одновременно работает только один медиа-подпроцесс, а для долгих задач нужно предусмотреть возможность отмены через cancelRun().

Краткая справка по частым интерфейсам (дополнительные возможности помимо образца) #

Сценарий Интерфейс
Чтение/запись своей конфигурации getConfig / setConfig (узкогранулярный patch) / addConfig (добавление элемента списка)
Открытие/сохранение файла browseFile / browseDir / writeFile / readFile (для >50MB — readFileChunk)
Получение системных каталогов getKnownDir('download') и т. д.
Открытие веб-страницы/внешней программы runAny('https://...', '')
Копирование в буфер обмена фронтендовый navigator.clipboard (для текстов native не нужен)
Скриншот/OCR screenCap('fast', ...) → ocrRecognition(base64) (оба асинхронные)
Вызов окна другого модуля windowControl('translate', 'show')

4. Создание файла модуля .zenmod (оконный хост) #

Создайте .zenmod в Modules/<分类>/ (файл образца: sdk/sample/Modules/SDK_Sample.zenmod):

{
    "id": "sdk_sample",
    "type": "web",
    "name": { "zh_cn": "SDK样例工程", "en": "SDK Sample Project", "...": "共 12 门语言" },
    "desc": { "zh_cn": "基于 MFT 索引的全盘急速文件搜索，支持 Everything 语法", "en": "..." },
    "icon": "fas fa-search",
    "winClassName": "yyzTools::SdkSampleWindowClass",
    "width": 760,
    "height": 540,
    "layoutType": 34,
    "url": "SDK_Sample/index.html",
    "preCreate": 0
}

Описание полей (все поля, читаемые главной программой при type:"web"):

Поле Обязательное Описание
id да Глобально уникальный. Одновременно является именем окна для windowControl/windowState, appId горячих клавиш, id подключения в dock
type да Фиксированно web
name да Объект на 12 языков; допускается и чистая строка (рекомендуется только для внутреннего тестирования); порядок возврата: текущий язык → en → чистая строка
desc нет То же
icon нет FontAwesome class (как выше) или изображение base64
winClassName нет Имя класса окна Win32, достаточно глобальной уникальности
width / height нет Начальный размер окна, по умолчанию 800x600
layoutType нет Битовая маска начального расположения, 34 = по центру горизонтали + по центру вертикали
url да Путь к странице относительно корня Web (SDK_Sample/index.html); также поддерживаются онлайн-адреса с http(s)
preCreate нет 1 = предсоздавать окно при запуске (ускоряет первое открытие), по умолчанию 0 — создавать по требованию
canSuspend нет 1 = разрешить приостанавливать WebView при скрытии окна для экономии ресурсов (по умолчанию 1)

Самопроверка после правки: JSON парсится, UTF-8 без BOM, id глобально уникален, все 12 языков непустые.

На этом приложение готово — скопируйте два каталога, как в разделе 1, найдите в командной панели «SDK样例工程» или «sdk» для запуска (пиньинь-индекс строится автоматически); вызвать его можно и через windowControl('sdk_sample', 'show').

5. Многоязычные тексты (через словарь) #

Для схемы без сборки достаточно обычного словаря-ES module (i18n.js):

const messages = {
    zh_cn: { title: 'SDK样例工程', results: '{{count}} 个结果，耗时 {{ms}} ms', ... },
    en:    { title: 'SDK Sample Project', results: '{{count}} results in {{ms}} ms', ... }
};
export function getMessages(lang) { return messages[lang] || messages.en; }
export function interpolate(dict) {
    return (key, params) => { /* {{count}} → params.count */ };
}

При инициализации читается getConfig().language для выбора языка, при отсутствии — возврат к en; предложения с заполнителями раскрываются через tf('results', { count, ms }).

Примечания:

  • Коды языков в стиле подчёркивания и нижнего регистра (zh_cn), как в .zenmod, а не BCP47.

  • name/desc в .zenmod обязаны быть полными на все 12 языков; для текстов внутри страницы жёсткого требования нет, образец даёт только zh_cn/en — расширяйте по необходимости.

  • Если модулю нужно мгновенное переключение вслед за языком интерфейса, словарь можно перевести на ленивую загрузку многоязычных файлов через import() по требованию — механизм тот же, что в этом документе.

6. Отладка и интеграция #

1. 免构建直接跑（推荐起步）：
   复制 sdk/sample/Web、sdk/sample/Modules 到 bin64\（Release exe 所在目录），重启 exe。
   改前端后 windowControl('sdk_sample','close') 再打开，或重启 exe 生效。

2. 浏览器看结构：
   直接双击 Web/SDK_Sample/index.html 用浏览器打开。
   浏览器里没有 window.Zen，ZenAPI.call 会走异常路径返回 error: -1，
   页面结构 / 样式 / 输入防抖 / 渲染逻辑均可正常调试（原生接口除外）。

Совет по производительности поиска: searchFile идёт через полнодисковый MFT-индекс на стороне C++, обычно возвращает за миллисекунды; на native есть механизм слотов поиска — новый запрос вытесняет незавершённый старый (старый возвращает пустой результат), а на фронтенде антидребезг 300 мс + возрастающий порядковый номер отбрасывают ответы не по порядку, так что быстрая печать не перегрузит фоновый поток и не заставит мигать старые результаты. Иконки результатов (base64) searchFile приносит сразу, вызывать отдельно getFileIcon не нужно.

Если возможностей интерфейсов не хватает (например, нужна новая функциональность C++), можно отправить запрос через канал обратной связи на официальном сайте — интерфейсы будут расширены в последующих версиях главной программы.

8. Замечания по безопасности #

Native API для разработчиков модулей полностью открывает системные возможности процесса-хоста, включая чтение/запись и удаление файлов, создание и завершение процессов, управление окнами, чтение/запись буфера обмена, изменение системных настроек, выполнение командной строки и другие опасные операции, причём нет диалогов запроса прав, нет песочницы, нет механизма отмены.

Перед каждым вызовом самостоятельно оценивайте безопасность операции: проверяйте все внешние входные данные, перед необратимыми действиями делайте резервную копию или запрашивайте подтверждение у пользователя, и используйте только те возможности, которые реально нужны функциональности. Вся ответственность за последствия лежит на разработчике.
