누가 디스크를 채우는가, 그리고 다음은 무엇인가

WinDirStat 2.x는 부활한 명품입니다: 멀티스레드 NTFS 스캔, 트리맵, 중복 탐지, 다크 모드. yyzTools 분석기는 다른 아키텍처로 갑니다——상시 인덱스 서비스(MFT 스냅샷 + USN 증분)에서 데이터를 읽어 어떤 폴더로의 드릴다운에도 즉시 응답하고——그림에서 끝나지 않습니다: 이동, 휴지통, 같은 파일 검색, 152개 규칙 클린업까지 하나의 설치 파일에서.

다시 스캔하지 않는 트리맵

yyzTools 분석기는 고전적 의미에서 아예 스캔하지 않습니다: 상시 Windows 서비스가 볼륨별 MFT 스냅샷을 쥐고 있고, 디스크 변화에는 USN 저널 증분을 적용합니다. C:에서 깊은 폴더로의 드릴다운은 살아 있는 인덱스 데이터에 한 번 조회하는 것——그림은 처음부터 거기 있습니다. 같은 서비스가 즉시 파일 검색도 떠받치므로, 방금 분석한 폴더를 다음 키 입력으로 이름 검색할 수 있습니다.

WinDirStat가 여전히 나은 선택일 때

WinDirStat는 무료·오픈소스(GPLv2)이고 다시 활발히 유지되며, 2.x는 실로 좋습니다: 빠른 NTFS 직접 스캔, 내용 기준 중복 탐지, 확장자 통계, 리포트 내보내기, 탐색기 통합. 순수 독립형 분석기——특히 중복 탐지가 본업이라면——여전히 훌륭한 전문가입니다.

yyzTools가 더 맞을 때

진짜 질문이 「누가 디스크를 차지하고, 프로그램을 더 설치하지 않고 어떻게 치울까」라면 yyzTools는 한 번에 둘 다 답합니다: 상시 인덱스에서 즉답하는 트리맵, 그리고 같은 파일의 휴지통 이동·검색·152개 규칙 클린업——런처, OCR, 번역까지 갖춘 무료 도구 상자에서.

자주 묻는 질문

yyzTools 분석기가 WinDirStat보다 빠른가요?

재는 방식이 달라 단순 비교는 어렵습니다: WinDirStat 2.x는 멀티스레드 NTFS 직접 읽기로 일회성 스캔이 빠릅니다. yyzTools는 수요 시 스캔을 하지 않습니다——상시 서비스가 MFT 스냅샷과 USN 증분을 유지하고, 트리맵 열람도 드릴다운도 이미 지어진 데이터를 읽어 즉답합니다. 대가는 상시 서비스가 도는 것입니다.

WinDirStat을 쓰고 있는데 왜 바꾸나요?

만족스럽다면 그대로 두세요. 분석이 첫걸음일 때 yyzTools가 빛납니다: 같은 창에서 큰 파일을 휴지통으로, 전체 디스크 검색으로 점프, 152개 규칙 클린업——게다가 이 분석기는 런처·OCR·번역이 있는 무료 도구 상자에 동봉됩니다.

상시 서비스가 PC를 느리게 하나요?

런처의 파일 검색(f␣)을 떠받치는 바로 그 인덱스 서비스입니다: MFT 스냅샷은 한 번만 만들고 이후에는 저비용 USN 저널 증분으로 유지하기에, 분석이나 검색이 전체 디스크 재스캔을 일으키지 않습니다.
