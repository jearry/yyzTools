빌드 도구 없이 첫 모듈을 만들어 보세요

API 레퍼런스 샘플 프로젝트 다운로드

이 문서는 모듈 개발자를 대상으로 하며, yyzTools 메인 프로세스 안에서 동작하는 웹 애플리케이션을 제로부터 만드는 방법을 시연합니다(SDK 샘플 프로젝트 SDK_Sample——초고속 파일 검색기——를 예로). 다음 내용을 다룹니다: 페이지 디렉터리, 윈도우 호스트, i18n, 비동기 Native API(전체 디스크 파일 검색), 파일 열기, 설정 영속화, 그리고 C++ 능력을 확장해야 할 때의 native 메서드 추가 템플릿.

샘플은 순수 네이티브 JS, 제로 서드파티 의존성, 빌드 불필요입니다: Vite / Alpine / FontAwesome 가 필요 없으며, Web 과 Modules 두 디렉터리를 yyzTools.exe 가 있는 디렉터리에 복사하기만 하면 실행됩니다.

1. 샘플 디렉터리와 배포 방식 #

sdk/sample/
  Web/                        ← <yyzTools.exe 디렉터리>\Web\ 로 복사        （기존 Web 디렉터리와 병합）
    SDK_Sample/               ← 샘플 자체 포함 디렉터리, 폴더 전체가 하나의 완전한 모듈
      index.html              # 페이지 구조 (네이티브 DOM, data-i18n 으로 텍스트 위치 표시)
      filefinder.js           # 전체 로직: 검색 / 열기 / 히스토리 / Esc
      filefinder.css          # 페이지 스타일 (모두 --zen-* 변수 사용, 다크/라이트 자동 대응)
      i18n.js                 # 텍스트 사전 (zh_cn / en)
      lib/
        zen_api.js            # ZenAPI 래퍼 클래스 (Native API 의 JS 래퍼, 유일한 lib 의존성)
        window_controls.css   # 테마 변수 (--zen-*) + 윈도우 컨트롤 바 스타일
  Modules/                   ← <yyzTools.exe 디렉터리>\Modules\ 로 복사    （기존 Modules 디렉터리와 병합）
    SDK_Sample.zenmod         # type:"web" 모듈 선언, ModuleManager 가 자동으로 호스트 윈도우 생성

배포:

sdk/sample/Web     를 bin64\Web\ 로 복사/병합
sdk/sample/Modules 를 bin64\Modules\ 로 복사/병합
yyzTools.exe 재시작 후, 명령 팔레트에서 "SDK样例工程" 검색으로 실행

메인 프로그램의 읽기 위치 규약:

리소스 위치
페이지 <exe디렉터리>\Web\{page}\index.html
모듈 <exe디렉터리>\Modules\<분류>\*.zenmod（한 층의 하위 디렉터리만 스캔）

2. 아키텍처 개요: 웹 애플리케이션은 어떻게 동작하는가 #

Modules/SDK_Sample.zenmod   ← type:"web" 을 선언하는 모듈 파일 (데이터 기반, C++ 작성 불필요)
        │  메인 프로그램 시작 시 .zenmod 스캔
        ▼
WebModule 호스트 윈도우 (네이티브 윈도우 + WebView2)
        │  Web\SDK_Sample\index.html 로드
        ▼
Web/SDK_Sample/             ← 여러분의 모든 프런트엔드 코드 (네이티브 JS, 제로 의존성)
        │  window.Zen.xxx(...)  ←→  메인 프로그램이 등록한 네이티브 인터페이스
        ▼
C++ 각 Manager (파일/프로세스/윈도우/클립보드/OCR...)

핵심 결론:

  • 어떤 C++ 코드도 작성할 필요가 없습니다. type: "web" 인 .zenmod 는 메인 프로그램이 자동으로 WebModule 호스트 윈도우로 생성하며, 윈도우 크기, 아이콘, 다국어 이름 모두 모듈 파일이 선언합니다.

  • 모듈은 자동으로 다음을 얻습니다: 명령 팔레트 검색(병음 인덱스 포함), 전역 단축키 바인딩, 도크 마운트, windowControl 이름표 등록.

  • 프런트엔드와 C++ 의 유일한 통로는 window.Zen 이며, 반드시 ZenAPI 래퍼 클래스를 통해 호출하세요(샘플에 lib/zen_api.js 가 포함되어 있음).

  • 빌드 불필요 페이지는 곧바로 정적 파일이므로, 수정 후 윈도우를 새로고침하면 바로 적용됩니다(windowControl('sdk_sample','hide') 후 다시 show, 또는 exe 재시작), 어떤 컴파일 단계도 필요 없습니다.

3. 페이지 구조 (네이티브 JS, 네 개의 파일) #

index.html #

어떤 서드파티 라이브러리도 가져오지 않습니다; 윈도우 컨트롤 바의 세 버튼은 유니코드 문자를 아이콘으로 사용(− / □ / ×)하며, 스타일은 lib/window_controls.css 가 제공합니다. 텍스트 위치는 data-i18n / data-i18n-ph 로 표시하고, JS 초기화 때 일괄 채웁니다. 구조는 네 부분: 검색 바, 검색 히스토리 chips, 상태 바(결과 수 + 문법 힌트), 결과 리스트:

<div class="search-bar">
    <input type="text" id="searchInput" class="search-input" data-i18n-ph="inputPlaceholder"
           spellcheck="false" autocomplete="off">
    <button class="search-btn" id="btnSearch" data-i18n="search"></button>
</div>
<div class="history-chips" id="historyChips"> ... </div>
<div class="status-bar">
    <span id="statusText" data-i18n="empty"></span>
    <span class="syntax-hint" data-i18n="syntaxHint"></span>
</div>
<div class="result-list" id="resultList"></div>

filefinder.js（핵심 로직） #

다섯 가지 책임, 모두 샘플 그대로 복사하면 됩니다:

  1. 윈도우 컨트롤: ZenAPI.windowControl('sdk_sample', 'min'|'max'|'close'|'drag'); 제목 표시줄 드래그는 이동 거리가 5px 를 초과해야 트리거; Esc 키——입력창에 포커스가 있으면 먼저 blur, 아니면 창 닫기.
  2. 테마: window.__applyTheme 를 등록해 C++ 푸시를 수신(첫 화면 data-theme 은 C++ 가 주입, JS 처리 불필요).
  3. i18n: getConfig().language 를 읽고, 사전에서 텍스트를 가져와 data-i18n 요소를 순회하며 채움; {{count}} 플레이스홀더가 있는 문장은 보간 함수로 전개.
  4. 검색: searchFile(keyword, maxResults) 는 비동기 바인딩 인터페이스(백그라운드 스레드 실행, UI 블록 없음); Enter 즉시 검색, 입력 디바운스 300ms 자동 검색; 증가하는 일련번호로 순서가 뒤바뀐 응답 폐기——native 측에는 검색 슬롯 메커니즘이 있어(새 요청이 미완료된 이전 요청을 바로 대체, 이전 Promise 는 빈 결과를 받음), 프런트엔드 일련번호는 이 "늦게 도착하는 빈 결과"가 새 결과의 렌더링을 덮어쓰는 것을 방지하며, 둘이 협력합니다.
  5. 결과 조작: openFile(fullPath, false) 로 파일 열기(더블클릭 동일, 두 번째 파라미터는 "관리자 권한 여부"); openFileLocation(fullPath) 로 파일이 속한 디렉터리 열기; 전체 경로는 path + '\\' + name 으로 조립; 아이콘은 결과에 이미 있는 icon 필드(base64)를 바로 사용; 파일 크기는 size 숫자 필드로 포맷 표시.

searchFile 반환 구조（{ error, files[] }） #

files[] 각 항목의 필드:

필드 타입 설명
name / path 문자열 파일명 / 파일이 속한 디렉터리. 전체 경로 = path + '\\' + name
dateModified 문자열 수정 시간 (로컬라이즈된 형식 텍스트)
size 숫자 파일 바이트 수, 네이티브 숫자 바로 사용
icon 문자열 base64 아이콘, <img src> 바로 사용, getFileIcon 재호출 불필요
score 숫자 관련도 점수 (native 가 이미 점수순 정렬)
isDir 숫자 1/0 숫자이지 네이티브 불리언이 아님(수작업 JSON 경로), 판단은 truthy 또는 === 1 사용, === true 금지

본 샘플이 호출하는 인터페이스 목록 #

인터페이스 바인딩 용도
searchFile(keyword, maxResults) 비동기 전체 디스크 MFT 인덱스 검색, Everything 문법 지원 (size:>100MB, ext:mp4, !ext:tmp)
openFile(path, admin) 동기 파일/디렉터리 열기 (shell 기본 동작), admin=true 시 관리자 권한
openFileLocation(path) 동기 파일 탐색기에서 해당 파일 위치 열기
getConfig(key?) 동기 설정 읽기: 생략 시 전체, key 전달 시 해당 키만 ( a.b 점 경로 지원)
setConfig(patch, replace?) 동기 좁은 단위 검색 히스토리 쓰기: setConfig({ sdk_sample: { history } }); replace=true 전체 교체(백업 가져오기 전용)
log(message) 동기 프런트엔드 로그, 메인 프로세스 로그에 기록, 문제 해결에 편리
windowControl(name, action) 동기 윈도우 최소화/최대화/닫기/드래그

호출 규범 (네 가지 철칙) #

import ZenAPI from './lib/zen_api.js';

// 1. 판정은 isOk() 사용（error 는 항상 숫자：0 성공, -1 은 호출 예외）
const res = await ZenAPI.searchFile('yyztools', 200);
if (!ZenAPI.isOk(res)) { ... }

// 2. 인터페이스가 반환하는 불리언 필드는 네이티브 불리언, 바로 판단
//    （예외 1：config 의 값 타입은 프런트엔드가 쓴 내용에 따라 결정, 보통 문자열, 비교 시 정규화 주의）
//    （예외 2：searchFile 결과의 isDir 는 1/0 숫자——수작업 JSON 경로, truthy 또는 === 1 사용）
const ex = await ZenAPI.exists(path);
if (ex.exists === true) { ... }

// 3. 설정 쓰기는 반드시 좁은 단위, 전체 한 번에 다시 쓰기 금지
await ZenAPI.setConfig({ sdk_sample: { history } });   // 자기 키만 쓰기

// 4. id 로 앱 정보 일괄 조회는 getAppInfo 사용, 루프 searchApp 금지
const infos = await ZenAPI.getAppInfo(['calculator', 'ocr']);

비동기 인터페이스( getAppInfo / searchFile / 미디어 다섯 가지 / ocrRecognition)는 백그라운드 스레드에서 실행되며, 동일 시점에 미디어 하위 프로세스는 하나만 실행됨에 유의하고, 장시간 작업에는 cancelRun() 취소 진입점을 제공하세요.

자주 쓰는 인터페이스 빠른 참조 (샘플 외의 더 많은 능력) #

시나리오 인터페이스

클립보드로 복사 프런트엔드 navigator.clipboard（텍스트 시나리오에서는 native 불필요）

4. .zenmod 모듈 파일 작성（윈도우 호스트） #

Modules/<분류>/ 아래에 .zenmod 를 새로 만듭니다(샘플 파일: sdk/sample/Modules/SDK_Sample.zenmod):

{
    "id": "sdk_sample",
    "type": "web",
    "name": { "zh_cn": "SDK样例工程", "en": "SDK Sample Project", "...": "共 12 门语言" },
    "desc": { "zh_cn": "基于 MFT 索引的全盘急速文件搜索，支持 Everything 语法", "en": "..." },
    "icon": "fas fa-search",
    "winClassName": "yyzTools::SdkSampleWindowClass",
    "width": 760,
    "height": 540,
    "layoutType": 34,
    "url": "SDK_Sample/index.html",
    "preCreate": 0
}

필드 설명( type:"web" 일 때 메인 프로그램이 읽는 모든 필드):

필드 필수 설명
id 예 전역 고유. 동시에 windowControl/windowState 의 윈도우 이름, 단축키 appId, dock 마운트 id
type 예 고정 web
name 예 12 언어 객체; 순수 문자열 쓰기도 허용(내부 테스트용으로만 권장), 값 조회 폴백: 현재 언어 → en → 순수 문자열
desc 아니요 동상
icon 아니요 FontAwesome class(위와 같음) 또는 base64 이미지
winClassName 아니요 Win32 윈도우 클래스명, 전역 고유만 되면 됨
width / height 아니요 초기 윈도우 크기, 기본값 800x600
layoutType 아니요 초기 위치 레이아웃 비트 마스크, 34 = 수평 중앙 + 수직 중앙
url 예 Web 루트 디렉터리 기준 페이지 경로( SDK_Sample/index.html); http(s) 로 시작하는 온라인 주소도 지원
preCreate 아니요 1 = 시작 시 윈도우 미리 생성(첫 열기 가속), 기본값 0 은 필요할 때 생성
canSuspend 아니요 1 = 윈도우 숨김 시 WebView 일시중단 허용으로 리소스 절약(기본값 1)

수정 후 자체 점검: JSON 파싱 가능, UTF-8 무 BOM, id 전역 고유, 12 언어 모두 비어 있지 않음.

이것으로 앱이 완성되었습니다——첫 절대로 두 디렉터리를 복사하고, 명령 팔레트에서 "SDK样例工程" 또는 "sdk" 검색으로 실행(병음 인덱스 자동 생성), windowControl('sdk_sample', 'show') 로도 호출할 수 있습니다.

5. 다국어 텍스트（사전 방식） #

빌드 불필요 방식은 일반 ES module 사전이면 충분합니다( i18n.js):

const messages = {
    zh_cn: { title: 'SDK样例工程', results: '{{count}} 个结果，耗时 {{ms}} ms', ... },
    en:    { title: 'SDK Sample Project', results: '{{count}} results in {{ms}} ms', ... }
};
export function getMessages(lang) { return messages[lang] || messages.en; }
export function interpolate(dict) {
    return (key, params) => { /* {{count}} → params.count */ };
}

초기화 때 getConfig().language 를 읽어 언어를 선택하고, 찾지 못하면 en 으로 폴백; 플레이스홀더가 있는 문장은 tf('results', { count, ms }) 로 전개.

주의:

  • 언어 코드는 밑줄 소문자 스타일( zh_cn)을 사용, .zenmod 와 일치, BCP47 이 아님.

  • .zenmod 의 name/desc 는 반드시 12 언어를 모두 갖춰야 함; 페이지 내 텍스트에는 강제 요구가 없으며, 샘플은 zh_cn/en 만 제공, 필요에 따라 확장.

  • 인터페이스 언어에 따라 즉시 전환되어야 하는 모듈은, 사전을 필요할 때 import() 로 다국어 파일을 지연 로드하도록 바꿀 수 있으며, 메커니즘은 본문과 동일.

6. 디버깅과 통합 #

1. 빌드 없이 바로 실행（시작으로 권장）：
   sdk/sample/Web, sdk/sample/Modules 를 bin64\（Release exe 디렉터리）로 복사, exe 재시작.
   프런트엔드 수정 후 windowControl('sdk_sample','close') 후 다시 열기, 또는 exe 재시작으로 적용.

2. 브라우저로 구조 보기：
   Web/SDK_Sample/index.html 를 더블클릭해 브라우저로 열기.
   브라우저에는 window.Zen 이 없어, ZenAPI.call 은 예외 경로로 error: -1 반환,
   페이지 구조 / 스타일 / 입력 디바운스 / 렌더링 로직은 모두 정상적으로 디버깅 가능（네이티브 인터페이스 제외）.

검색 성능 힌트: searchFile 은 C++ 측 MFT 전체 디스크 인덱스를 사용하며, 보통 밀리초 단위로 반환; native 에는 검색 슬롯 메커니즘이 있어——새 요청이 미완료된 이전 요청을 대체(이전 것은 빈 결과 반환), 프런트엔드는 300ms 디바운스 + 증가 일련번호로 순서가 뒤바뀐 응답을 폐기하며, 연속 키 입력도 백그라운드 스레드를 과부하시키거나 이전 결과를 깜빡이게 하지 않습니다. 결과 아이콘(base64)은 searchFile 이 곁들여 반환, 추가로 getFileIcon 호출 불필요.

인터페이스 능력이 부족할 때(예: 새로운 C++ 능력이 필요), 공식 웹사이트 피드백 채널을 통해 요구를 제출하면 메인 프로그램이 이후 버전에서 인터페이스를 확장합니다.

7. 완전한 최소 예제 요약 #

변경 파일 필수 여부

공용 의존성 Web/SDK_Sample/lib/（zen_api.js / window_controls.css, 샘플에 자체 포함） 예
새 모듈 작성 Modules/SDK_Sample.zenmod 예
C++ 변경 없음 —
빌드 단계 없음（빌드 불필요, 복사 후 바로 사용） —

8. 보안 유의사항 #

Native API 는 모듈 개발자에게 호스트 프로세스의 시스템 능력을 완전히 개방하며, 그중에는 파일 읽기/쓰기와 삭제, 프로세스 생성과 종료, 윈도우 제어, 클립보드 읽기/쓰기, 시스템 설정 변경, 명령줄 실행 등 고위험 작업이 포함되어 있고, 권한 팝업이 없고, 샌드박스 격리가 없으며, 실행 취소 메커니즘을 제공하지 않습니다.

호출 전에 각 작업의 안전성을 스스로 평가하세요: 모든 외부 입력을 검증하고, 되돌릴 수 없는 작업 전에 백업하거나 사용자에게 확인을 요청하며, 기능에 실제로 필요한 능력만 사용하세요. 이로 인해 발생하는 모든 결과는 개발자가 스스로 부담합니다.
