1. 공통 규약 #

본 문서는 Native 상호작용과 관련된 모든 인터페이스를 정의하며, 메인 프로세스 yyzTools.exe 가 등록한 인터페이스만 다룹니다( src/yyztools/NativeApi.cpp 의 SetupBindings()).

호출 방식 #

  • 프런트엔드는 window.Zen 객체로 인터페이스 함수를 호출하며, 통일하여 ZenAPI 래퍼 클래스( web/lib/zen_api.js)를 사용하는 것을 권장합니다. 업무 코드에서 window.Zen 을 직접 호출하지 마세요. 인터페이스 업그레이드·조정 시 인터페이스 호환 레이어로 처리하기 편리합니다.

  • 입력: 위치 파라미터 방식으로 전달, 구체적인 파라미터 개수와 타입은 각 인터페이스 참조

  • 출력: 반환값으로 전달, 값은 json 객체, 다음 내용 포함

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error: 0 정상, 0 이 아니면 오류

    • errorMsg(선택): 오류 메시지

    • 기타(선택): 각 인터페이스 참조

오류 판정 방식 #

error 는 항상 숫자: 0 정상, 0 이 아니면 오류(호출 예외 시 -1).

동기 / 비동기 바인딩 #

대부분의 인터페이스는 동기 바인딩( BindSync)이며, 호출 즉시 반환. 다음 7 개 인터페이스는 비동기 바인딩( BindAsync)으로, 백그라운드 스레드에서 실행되며 Promise 로 회신, UI 스레드를 블록하지 않습니다:

getAppInfo, searchFile, imageRun, ffmpegRun, pdfRun, gsRun, ocrRecognition

비동기 인터페이스의 동일 시점 동작 제약은 각 항목 참조(예: 미디어 다섯 가지는 직렬 실행, 공용 cancelRun 취소).

    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion: 클라이언트 API 버전 정보. 인터페이스 업데이트가 있을 때마다 버전 번호 +1; 숫자는 0~9, 9 이후 0부터, 예: 1.0.0, 1.0.1, 1.0.2... 1.0.9, 1.1.0 등

    • appVersion: 클라이언트 버전 정보

    • usageTime: 사용 시간(단위: s)

    • usageTimes: 활성 횟수

    • firstUseTime: 최초 사용 시간, 형식: yyyymmdd

2. 설정 획득 #

function Zen.getConfig(key?: string) : object

  • 입력

    • key(선택): 해당 키만 조회, a.b 점 경로 지원. 생략 시 전체 설정 반환.

      • 히트: {"error":0, "<key>": <값>} 반환, 예: getConfig("language") → {"error":0,"language":"zh_cn"}; getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • 미스: {"error":0} 반환(오류 아님, 읽는 쪽이 자체 폴백)

  • 출력(예시, 필드는 실제 설정 기준)

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel: 로그 레벨（0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal）

    • wallpaperEnabled: 동적 배경화면 사용

    • overlayEnabled: 데스크톱 특효 사용

    • gameMode: 게임 모드

    • clipboardHistoryMaxCount: 클립보드 최대 히스토리 기록 개수

    • autoStart: 시작 프로그램 자동 실행

    • shortcutKeys: 전역 단축키

      • main: 메인 화면

        • doubleCtrlEnabled: Ctrl 더블 클릭으로 깨우기

        • doubleAltEnabled: Alt 더블 클릭으로 깨우기

        • modifier: 수식키

        • virtualCode: 주 키

      • apps: 앱

        • appId: 앱 id

        • modifier: 수식키

        • virtualCode: 주 키

    • quickOpen: 빠른 열기

      • name: 이름

      • type: 타입（normal: 일반 검색 / spec: 수직 검색）

      • index: 순번

      • url: url 템플릿

      • enabled: 사용 여부

    • customApps: 사용자 정의 app

      • filePath: app 이 대응하는 exe 의 경로

      • enabled: 사용 여부

    • dock: 도크（카테고리 + 콘텐츠）

      • **공통 규약: ** name/icon **이 없으면 "내장 기본값 사용"을 의미（i18n 또는 ** appId **에 대응하는 ** .zenmod 에서 런타임 파생, 인터페이스 언어에 따라 변동）; 해당 필드가 있으면 사용자가 커스터마이즈한 것이며 원본 그대로 표시하고 다시 번역하지 않음.

      • categories: 카테고리

        • id: 내장 카테고리는 의미 id（folder/tools/ai/game/system), 사용자 신규 생성은 category_<타임스탬프>

        • name: 선택, 사용자가 이름 변경 후에만 존재

        • icon: FontAwesome class

        • color: 테마 색상

        • order: 정렬 순번

      • contents: 콘텐츠 항목

        • id: 내장 디렉터리 항목은 의미 id（desktop/documents/downloads/music/videos), 그 외는 content_<타임스탬프>

        • categoryId: 소속 카테고리 id

        • type: app | folder | url

        • appId: type=app 일 때 필수, .zenmod 의 id 에 대응; 이름과 아이콘은 모두 여기서 파생, 디스크에 저장하지 말 것

        • folderPath: type=folder 일 때 필수, %USERPROFILE% 등 환경 변수 지원

        • url: type=url 일 때 필수, 정규화된 전체 URL(프로토콜 접두사가 없으면 자동으로 https:// 보충); 클릭 시 시스템 기본 브라우저로 열기. 이름은 사용자가 작성, 아이콘은 런타임에 웹사이트 favicon 을 가져옴(실패 시 fas fa-globe 폴백), 디스크에 저장하지 말 것

        • name / icon: 선택, 의미는 상동（type=folder 의 사용자 지정 디렉터리는 필수）

        • color: 아이콘 착색

        • order: 같은 카테고리 내 정렬 순번

3. 설정 수정 #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • 입력

    • config: getConfig 와 동일

      • 수정할 것만 전달, 전체 내용 전달 불필요

      • 같은 키 값 아래의 내용은 완전하게 전달해야 함

      {
    "logLevel": "1"
}

    • replace（선택, 기본값 false）: false=기존 설정에 증분 병합, true=전체 교체(백업 가져오기용, 삭제된 리스트 항목을 정리할 수 있음). "true" 또는 "false" 문자열 전달, 생략 시 "false" 와 동일.

  • 주의: "전체 getConfig 를 읽어 그대로 setConfig 로 다시 쓰지 말 것"——getConfig 반환값에는 error 필드가 있어, 전체를 다시 쓰면 그것이 설정 파일에 저장됩니다. 반드시 setConfig({ dock: { categories } }) 처럼 좁은 단위로 쓸 것.

  • 출력

    {
    "error": 0,
    "errorMsg": ""
}

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

    • type: 입력 타입（기본값 "text"）

      • "text": 텍스트 데이터

      • "data": Base64 인코딩된 바이너리 데이터

      • "hex": 16 진수 문자열

      • "file": 파일 경로

  • 출력

    {
  "error": 0,

    • cmdArgs: 명령 파라미터

    • admin: 관리자 권한으로 실행할지 여부

  • 출력

    {
    "error": 0,
    "errorMsg": ""
}

13. 업데이트 #

업데이트는 독립 프로세스 yyzUpdater.exe 가 수행하며, 메인 프로세스는 기동과 상태 탐지만 담당합니다.

1. 업데이트 확인 #

function Zen.checkUpdate() : object

yyzUpdater.exe --check-and-apply 를 기동（확인 + 다운로드 + 적용 원스톱）.

  • 입력: 없음

  • 출력

    { "error": 0, "errorMsg": "success" }

    비고: error:0 은 업데이터 기동 성공만 의미, 업데이트 결과를 의미하지 않음. 업데이트 진행 중/준비 완료 상태는 getUpdateState 로 조회.

2. 업데이트 상태 획득 #

function Zen.getUpdateState() : object

업데이트 상태를 실시간 탐색（트레이 폴링용）:

  • updater 실행 여부 → 싱글톤 뮤텍스 Local\yyzUpdater_SingleInstance

  • 다운로드 완료 후 적용 대기 여부 → %APPDATA%\yyzTools\Update\update.ready 존재 여부（존재하면 그 안의 main 패키지 version 파싱）

  • 수동 확인이 종료되었고 업데이트가 없는지 → %APPDATA%\yyzTools\Update\update.result 마커（읽는 즉시 삭제）

  • 입력: 없음

  • 출력

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status: idle（업데이트 활동 없음）/ checking（업데이터 실행 중）/ ready（다운로드 완료, 업그레이드 가능）

    • version: ready 상태에서만 값이 있으며, 적용 대기 중인 새 버전 번호（main 패키지 기준）, 그 외는 빈 문자열

    • lastResult: idle 상태에서만 값이 있을 수 있으며, 마지막 수동 확인（--check-and-apply)의 결과: uptodate（이미 최신）/ error（확인 실패）, 마커가 없으면 빈 문자열. 이 마커는 updater 가 쓰고 본 인터페이스가 읽은 후 즉시 삭제하므로 한 번만 반환, 프런트엔드가 한 번 Toast 띄우는 용도; 자동 무음 --check 는 마커를 쓰지 않아 방해가 되지 않음.

    • 상태 우선순위: checking > ready > idle

3. 다운로드 완료된 업데이트 적용 #

function Zen.applyUpdate() : object

yyzUpdater.exe --apply 를 기동: update.ready 를 읽음 → 메인 프로세스 종료 대기 → 파일 교체 → 메인 프로세스 재시작. getUpdateState 가 ready 를 반환할 때만 호출할 것.

  • 입력: 없음

  • 출력

    { "error": 0, "errorMsg": "success" }

⚠️ 보안 유의사항 #

Native API 는 모듈 개발자에게 호스트 프로세스의 시스템 능력을 완전히 개방하며, 그중에는 파일 읽기/쓰기와 삭제, 프로세스 생성과 종료, 윈도우 제어, 클립보드 읽기/쓰기, 레지스트리 및 시스템 설정 변경, 네트워크 다운로드, 명령줄 실행 등 고위험 작업이 포함되어 있습니다.

이러한 인터페이스는 권한 팝업이 없고, 샌드박스 격리가 없으며, 실행 취소 메커니즘을 제공하지 않습니다——호출 즉시 현재 사용자 권한으로 직접 적용되며, 잘못 사용하면 데이터 영구 손실이나 시스템 이상을 초래할 수 있습니다.

따라서 반드시 다음에 유의하세요:

  • 안전성 스스로 평가: 어떤 인터페이스든 호출하기 전에, 파라미터(특히 경로, 프로세스명, 명령줄)의 출처가 신뢰할 수 있고 충분히 검증되었는지 먼저 확인; 삭제, 덮어쓰기, 프로세스 종료 등 되돌릴 수 없는 작업은 먼저 백업하거나 사용자에게 재확인을 권장.
  • 신뢰할 수 없는 입력 경계: 사용자 입력, 네트워크 응답 또는 서드파티 데이터를 검증 없이 인터페이스 파라미터에 직접 연결하지 마세요. 경로 탐색과 명령 주입을 조심.
  • 최소 권한 원칙: 업무에 실제로 필요한 능력만 요청하고, 편의를 위해 영향 범위가 더 큰 인터페이스를 사용하는 것을 피하세요.
  • 책임 자부: 개발자는 본 API 사용으로 인해 발생하는 모든 결과(데이터 손실, 시스템 손상, 보안 위험 등을 포함하되 이에 국한되지 않음)를 스스로 부담해야 합니다.
