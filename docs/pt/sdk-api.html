1. Convenções gerais #

Este documento define todas as interfaces relacionadas à interação com a camada nativa, cobrindo apenas as interfaces registradas pelo processo principal yyzTools.exe (SetupBindings() em src/yyztools/NativeApi.cpp).

Forma de chamada #

  • O front-end chama as funções de interface pelo objeto window.Zen; recomenda-se sempre usar a classe de encapsulamento ZenAPI: web/lib/zen_api.js, e não chamar window.Zen diretamente no código de negócio, para facilitar ajustes de upgrade tratando essa camada como camada de compatibilidade de interfaces.

  • Entrada: passada por parâmetros posicionais; consulte a interface específica para a quantidade e os tipos dos parâmetros

  • Saída: passada pelo valor de retorno, que é um objeto json com o seguinte conteúdo

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error: 0 correto, diferente de 0 erro

    • errorMsg (opcional): mensagem de erro

    • Outros (opcional): consulte a interface específica

Forma de verificar erros #

error é sempre número: 0 sucesso, diferente de 0 erro (-1 em caso de exceção na chamada).

Vinculação síncrona / assíncrona #

A grande maioria das interfaces é de vinculação síncrona (BindSync), retornando na hora. As 7 interfaces a seguir são de vinculação assíncrona (BindAsync), executam em thread em segundo plano e retornam via Promise, sem bloquear a thread de UI:

getAppInfo, searchFile, imageRun, ffmpegRun, pdfRun, gsRun, ocrRecognition

As restrições de comportamento das interfaces assíncronas em um mesmo instante estão descritas nos itens específicos (por exemplo, o quinteto de mídia executa em série e compartilha o cancelRun para cancelamento).

2. Interfaces comuns #

1. Obter a versão do cliente #

function Zen.getVersion() : object

  • Entrada: nenhuma

  • Saída

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion: informações da versão da API do cliente. A cada atualização que envolve interfaces, o número da versão aumenta em 1; os dígitos vão de 0 a 9, voltando a 0 depois do 9, por exemplo 1.0.0, 1.0.1, 1.0.2... 1.0.9, 1.1.0 etc.

    • appVersion: informações da versão do cliente

    • usageTime: tempo de uso (unidade: s)

    • usageTimes: número de ativações

    • firstUseTime: data do primeiro uso, formato: yyyymmdd

2. Obter a configuração #

function Zen.getConfig(key?: string) : object

  • Entrada

    • key (opcional): retorna apenas essa chave; suporta caminho com pontos a.b. Sem parâmetro, retorna a configuração completa.

      • Encontrado: retorna {"error":0, "<key>": <valor>}, ex.: getConfig("language") → {"error":0,"language":"zh_cn"}; getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • Não encontrado: retorna {"error":0} (não dá erro; quem lê trata o fallback)

  • Saída (exemplo; os campos dependem da configuração real)

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel: nível de log (0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal)

    • wallpaperEnabled: habilita o papel de parede dinâmico

    • overlayEnabled: habilita os efeitos da área de trabalho

    • gameMode: modo de jogo

    • clipboardHistoryMaxCount: número máximo de registros no histórico da área de transferência

    • autoStart: iniciar com o sistema

    • shortcutKeys: atalhos globais de teclado

      • main: interface principal

        • doubleCtrlEnabled: ativar com Ctrl duplo

        • doubleAltEnabled: ativar com Alt duplo

        • modifier: tecla modificadora

        • virtualCode: tecla principal

      • apps: aplicativos

        • appId: id do aplicativo

        • modifier: tecla modificadora

        • virtualCode: tecla principal

    • quickOpen: abertura rápida

      • name: nome

      • type: tipo (normal: busca geral / spec: busca vertical)

      • index: número de ordem

      • url: modelo de url

      • enabled: habilitado ou não

    • customApps: apps personalizados

      • filePath: caminho do exe correspondente ao app

      • enabled: habilitado ou não

    • dock: dock (categorias + itens)

      • Convenção geral: a ausência de name/icon significa "usar o valor interno padrão" (derivado em tempo de execução do i18n ou do .zenmod correspondente ao appId, variando com o idioma da interface); a presença do campo significa personalização do usuário, exibido como está, sem nova tradução.**

      • categories: categorias

        • id: categorias internas usam id semântico (folder/tools/ai/game/system); as criadas pelo usuário usam category_<timestamp>

        • name: opcional, existe apenas após o usuário renomear

        • icon: classe FontAwesome

        • color: cor do tema

        • order: número de ordem da classificação

      • contents: itens de conteúdo

        • id: itens de diretório internos usam id semântico (desktop/documents/downloads/music/videos); os demais usam content_<timestamp>

        • categoryId: id da categoria à qual pertence

        • type: app | folder | url

        • appId: obrigatório quando type=app, corresponde ao id do .zenmod; nome e ícone são todos derivados dele, não persistir no disco

        • folderPath: obrigatório quando type=folder; aceita variáveis de ambiente como %USERPROFILE%

        • url: obrigatório quando type=url; endereço completo normalizado (prefixo https:// adicionado automaticamente se ausente); ao clicar, abre no navegador padrão do sistema. O nome é preenchido pelo usuário; o ícone é obtido em tempo de execução do favicon do site (fallback fas fa-globe em caso de falha), não persistir no disco

        • name / icon: opcional, mesma semântica acima (obrigatório para diretórios escolhidos pelo usuário quando type=folder)

        • color: cor do ícone

        • order: número de ordem dentro da mesma categoria

3. Modificar a configuração #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • Entrada

    • config: igual ao getConfig

      • Passe apenas o que deseja modificar; não é preciso enviar tudo

      • O conteúdo sob a mesma chave deve ser enviado completo

      {
    "logLevel": "1"
}

    • replace (opcional, padrão false): false = mescla incremental na configuração existente; true = substituição completa (para importar backup, permite limpar itens de lista já removidos). Passe a string "true" ou "false"; quando ausente equivale a "false".

  • Atenção: não "ler tudo com getConfig e regravar tudo com setConfig" — o retorno do getConfig traz o campo error, e regravar o objeto inteiro o gravaria no arquivo de configuração. Escreva sempre com granularidade estreita, ex.: setConfig({ dock: { categories } }).

  • Saída

    {
    "error": 0,
    "errorMsg": ""
}

3. Obter o estado da janela #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • Entrada

    • window: Name ou HWND em forma de string; veja Controle de janelas

    • can_suspend (opcional): permite suspender o WebView dessa janela (interruptor de gestão de recursos; padrão false)

  • Observação: esta interface tem efeito colateral — após consultar o estado, se a janela estiver em show/max, a renderização do WebView é retomada; caso contrário, o WebView é suspenso para poupar recursos (a suspensão só é permitida quando can_suspend é true). Páginas de front-end permanentes que consultam o próprio estado em polling devem passar true; consultas comuns, false.

  • Saída

    {
    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state: estado (show: exibição normal / min: minimizada / max: maximizada / close: fechada)

    • topmost: sempre no topo ou não

2. Obter informações de aplicativos em lote por id (assíncrono) #

function Zen.getAppInfo(appIds: string[]) : object

Na configuração só é gravado o appId; nome e ícone são sempre derivados em tempo de execução (o name do .zenmod é multilíngue; um snapshot na configuração ficaria desatualizado após a troca de idioma). Esta interface existe exatamente para esse cenário.

⚠️ Não o substitua por um loop de searchApp(appId, 1): cada chamada de searchApp faz uma varredura completa do índice de aplicativos + correspondência pinyin + pontuação e ordenação, além de disparar duas threads e retornar múltiplos resultados com ícones em base64. O dock mais os atalhos somam dezenas de appId; consultar um a um atrasa visivelmente a inicialização. Esta interface traz tudo de uma vez; no lado nativo usa map::find, com acerto exato.

Internamente ela aguarda o índice de aplicativos ficar pronto (o índice é gerado por uma thread em segundo plano), por isso é vinculação assíncrona; chamadas no início de um arranque a frio não recebem resultado vazio.

  • Entrada

    • appIds: array de appId, ex.: ["calculator", "Microsoft.WindowsCamera"]

  • Saída

    Formato idêntico ao searchApp (mesmo BuildAppResult), exceto:

    • retorna apenas os itens com acerto exato; ids não encontrados são silenciosamente ignorados, de modo que apps.length pode ser menor que o comprimento da entrada (serve para detectar appId inválidos na configuração)

    • a ordem segue a ordem da entrada; score é sempre 0 (não participou da pontuação)

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

6. Operações com arquivos #

1. Buscar arquivos (assíncrono) #

function Zen.searchFile(keyword: string, maxResults : number) : object

  • Observação: a busca é executada pelo serviço próprio yyzFileSearch (índice MFT + IPC por pipe nomeado), com suporte à sintaxe de consulta estilo Everything (ex.: size:>100MB, !ext:mp4); os resultados são ordenados por relevância. A busca roda em thread em segundo plano e é vinculação assíncrona.

  • Entrada

    • keyword: palavra-chave de busca

    • maxResults: número máximo de registros

  • Saída

    {
  "error": 0,
  "files": [
    {

7. Processamento de mídia #

O quinteto de mídia é executado pelo lado C++ por meio de ferramentas CLI de terceiros em bin64\Platform\. Exceto ffprobeRun, todas são vinculações assíncronas (executam em thread em segundo plano, sem bloquear a thread de UI); o processamento em lote é serial, com apenas um subprocesso em execução por vez; use Zen.cancelRun() para interromper a execução atual (quando cancelada, retorna errorMsg: "cancelled").

1. Executar comando magick (assíncrono) #

function Zen.imageRun(args: string) : object

  • Entrada

    • args: parâmetros completos da linha de comando do magick (sem o magick.exe em si), montados pelo front-end. Coloque os caminhos entre aspas duplas, ex.: "D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • Saída

    {
  "error": 0,
  "stdout": "..."
}

  • Nota: o lado C++ não monta parâmetros; apenas executa magick.exe <args> e captura o resultado. Quando error é diferente de 0, o errorMsg transmite o stderr do magick; o stdout é a saída padrão do magick (resultado de comandos como identify)

9. Criptografia e descriptografia #

1. Criptografar dados #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • Entrada

    • target: dados a criptografar

      • com type="text", é uma string de texto

      • com type="data", são dados binários codificados em Base64

      • com type="hex", é uma string hexadecimal

      • com type="file", é um caminho de arquivo

    • algorithm: algoritmo de criptografia

      • criptografia simétrica: "aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • criptografia assimétrica: "rsa-pkcs1", "rsa-oaep" (RSA; cifra com a chave pública, decifra com a privada), "sm2" (curva elíptica nacional chinesa sm2p256v1; cifra com a chave pública, decifra com a privada; processa qualquer comprimento em uma única passada, sem necessidade de blocos)

      • key/iv em Base64; internamente convertidos para hexadecimal e passados como enc -K <hex> -iv <hex>; o comprimento da chave deve corresponder exatamente ao algoritmo

    • type: tipo de entrada (padrão "text")

      • "text": dados de texto

      • "data": dados binários codificados em Base64

      • "hex": string hexadecimal

      • "file": caminho de arquivo

    • key: para simétricos, chave codificada em Base64; para assimétricos (rsa-*, sm2), texto PEM (na criptografia passe a chave pública, na descriptografia a privada; transmitido como está, sem decodificação Base64)

    • iv: vetor de inicialização codificado em Base64 (opcional; alguns algoritmos exigem; ignorado nos assimétricos)

  • Saída

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

5. Calcular hash #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • Entrada

    • target: alvo do cálculo; o significado varia conforme o type

      • com type="file", é um caminho de arquivo

      • com type="text", é uma string de texto (o resumo é calculado em UTF-8)

      • com type="data", são dados binários codificados em Base64

      • com type="hex", é uma string hexadecimal

    • algorithm: algoritmo de hash

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3" (resumo SM3 nacional chinês, 256 bits / 64 dígitos hexadecimais)

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512" (SHA-3 / Keccak, NIST FIPS 202)

      • "blake2b512" / "blake2s256" (BLAKE2, resumos modernos de alto desempenho)

      • "crc32" (soma de verificação CRC32, 8 dígitos hexadecimais)

      • "crc16" (soma de verificação CRC16, 4 dígitos hexadecimais)

      • "checksum" (soma acumulada dos bytes, 8 dígitos hexadecimais)

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512" (HMAC; o 4º parâmetro key é a chave, a saída é o MAC em hexadecimal)

    • type: tipo de entrada (opcional, padrão "file")

      • "file": calcula o hash do arquivo

      • "text": calcula o hash do texto

      • "data": calcula o hash dos dados binários (target deve ser string Base64)

      • "hex": calcula o hash da string hexadecimal (target é string hex, decodificada e calculada por bytes)

  • Saída

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

13. Atualização #

A atualização é feita pelo processo independente yyzUpdater.exe; o processo principal apenas o invoca e sonda seu estado.

1. Verificar atualizações #

function Zen.checkUpdate() : object

Invoca yyzUpdater.exe --check-and-apply (detectar + baixar + aplicar, tudo em um).

  • Entrada: nenhuma

  • Saída

    { "error": 0, "errorMsg": "success" }

    Nota: error:0 significa apenas que o atualizador foi invocado com sucesso, não representa o resultado da atualização. O estado em andamento/pronto é consultado com getUpdateState.

2. Obter o estado da atualização #

function Zen.getUpdateState() : object

Sonda em tempo real o estado da atualização (para polling da bandeja):

  • se o updater está em execução → mutex de instância única Local\yyzUpdater_SingleInstance

  • se já foi baixado e aguarda aplicação → existência de %APPDATA%\yyzTools\Update\update.ready (se existir, lê dele a version do pacote main)

  • se a verificação manual terminou sem atualizações → marcador %APPDATA%\yyzTools\Update\update.result (lido e apagado na hora)

  • Entrada: nenhuma

  • Saída

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status: idle (nenhuma atividade de atualização) / checking (atualizador em execução) / ready (baixado e pronto para atualizar)

    • version: só tem valor no estado ready; é o número da nova versão a aplicar (do pacote main); nos demais, string vazia

    • lastResult: só pode ter valor no estado idle; é o resultado da última verificação manual (--check-and-apply): uptodate (já está atualizado) / error (falha na verificação); string vazia se não houver marcador. O marcador é gravado pelo updater e apagado imediatamente após a leitura por esta interface, portanto é retornado apenas uma vez, para o front-end exibir um Toast; a verificação silenciosa --check não grava o marcador e não gera interrupções.

    • prioridade de estados: checking > ready > idle

3. Aplicar a atualização já baixada #

function Zen.applyUpdate() : object

Invoca yyzUpdater.exe --apply: lê update.ready → aguarda a saída do processo principal → substitui os arquivos → reinicia o processo principal. Chame apenas quando getUpdateState retornar ready.

  • Entrada: nenhuma

  • Saída

    { "error": 0, "errorMsg": "success" }

⚠️ Avisos de segurança #

A Native API está totalmente aberta aos desenvolvedores de módulos quanto às capacidades do sistema do processo hospedeiro, incluindo leitura/gravação e exclusão de arquivos, criação e término de processos, controle de janelas, leitura/gravação da área de transferência, alteração de registro e configurações do sistema, downloads pela rede e execução de linha de comando — operações de alto risco.

Essas interfaces não têm diálogos de permissão, não têm isolamento por sandbox e não oferecem mecanismo de desfazer — a chamada surte efeito imediatamente com os privilégios do usuário atual; o uso indevido pode causar perda permanente de dados ou instabilidade do sistema.

Portanto, atenção redobrada:

  • Avalie a segurança por conta própria: antes de chamar qualquer interface, confirme que os parâmetros (especialmente caminhos, nomes de processos, linha de comando) vêm de fonte confiável e foram devidamente validados; para operações irreversíveis como exclusão, sobrescrita ou término de processos, recomenda-se fazer backup antes ou pedir confirmação ao usuário.
  • Desconfie de entradas não confiáveis: nunca insira entrada do usuário, respostas de rede ou dados de terceiros diretamente nos parâmetros das interfaces sem validação; cuidado com path traversal e injeção de comandos.
  • Princípio do menor privilégio: solicite apenas as capacidades de que o negócio realmente precisa; evite, por comodidade, usar interfaces de impacto mais amplo.
  • Responsabilidade do desenvolvedor: o desenvolvedor assume todas as consequências decorrentes do uso desta API, incluindo, sem se limitar a, perda de dados, danos ao sistema e riscos de segurança.
