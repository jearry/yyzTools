مرجع الواجهات تنزيل المشروع النموذجي

هذا المستند موجَّه لمطوّري الوحدات، ويوضح كيفية إنشاء تطبيق ويب يعمل داخل العملية الرئيسية yyzTools من الصفر (باستخدام مشروع عيّنة SDK SDK_Sample — أداة بحث سريع عن الملفات — كمثال)، ويغطي: بنية صفحة الوحدة، نافذة الاستضافة، i18n، واجهة Native غير المتزامنة (البحث في كامل الأقراص)، فتح الملفات، حفظ الإعدادات (config)، بالإضافة إلى قالب إضافة طريقة native جديدة عند الحاجة لتوسيع قدرات C++.

العيّنة هي JavaScript أصلية خالصة، بدون أي اعتماديات طرف ثالث، وبدون بناء (build): لا حاجة إلى Vite / Alpine / FontAwesome؛ فقط انسخ المجلدين Web وModules إلى المجلد الذي يحتوي على yyzTools.exe ليشتغل.

1. بنية عيّنة الوحدات وطريقة النشر #

sdk/sample/
  Web/                        ← انسخ إلى <مجلد yyzTools.exe>\Web\        (دمج مع مجلد Web الموجود)
    SDK_Sample/               ← مجلد العيّنة ذاتي الاحتواء؛ المجلد بأكمله هو وحدة كاملة
      index.html              # بنية الصفحة (DOM أصلي، data-i18n لتحديد مواضع النصوص)
      filefinder.js           # كل المنطق: البحث / الفتح / السجل / Esc
      filefinder.css          # أنماط الصفحة (كلها بمتغيرات --zen-*، تتكيف تلقائيًا مع الوضع الفاتح والداكن)
      i18n.js                 # قاموس النصوص (zh_cn / en)
      lib/
        zen_api.js            # فئة التغليف ZenAPI (غلاف JS لـ Native API، الاعتمادية الوحيدة في lib)
        window_controls.css   # متغيرات الثيم (--zen-) + أنماط شريط التحكم بالنافذة
  Modules/                   ← انسخ إلى <مجلد yyzTools.exe>\Modules\    (دمج مع مجلد Modules الموجود)
    SDK_Sample.zenmod         # إعلان وحدة type:"web"، ينشئ ModuleManager نافذة الاستضافة تلقائيًا

النشر:

انسخ sdk/sample/Web     إلى  bin64\Web\  (نسخ/دمج)
انسخ sdk/sample/Modules إلى  bin64\Modules\  (نسخ/دمج)
أعد تشغيل yyzTools.exe، وابحث عن "SDK样例工程" في لوحة الأوامر لتشغيلها

اصطلاحات مواقع القراءة في البرنامج الرئيسي:

المورد الموقع
الصفحة <exe目录>\Web\{page}\index.html
الوحدة <exe目录>\Modules\<分类>\*.zenmod（只扫一层子目录）

2. نظرة معمارية عامة: كيف يعمل تطبيق الويب #

Modules/SDK_Sample.zenmod   ← ملف وحدة يعلن type:"web" (موجّه بالبيانات، دون كتابة C++)
        │  الموقع الرئيسي يمسح .zenmod عند الإقلاع
        ▼
نافذة استضافة WebModule (نافذة أصلية + WebView2)
        │  تحمّل Web\SDK_Sample\index.html
        ▼
Web/SDK_Sample/             ← كل شيفرة الواجهة الأمامية (JS أصلي، بدون اعتماديات)
        │  window.Zen.xxx(...)  ←→  الواجهات الأصلية المسجلة لدى البرنامج الرئيسي
        ▼
مديرات C++ المختلفة (ملفات/عمليات/نوافذ/الحافظة/OCR...)

خلاصات أساسية:

  • لا حاجة لكتابة أي شيفرة C++. ملف .zenmod من نوع type: "web" يُنشَّأ تلقائيًا كنافذة استضافة WebModule بواسطة البرنامج الرئيسي، وتُعلن الوحدةُ حجمَ النافذة والأيقونة والاسم متعدد اللغات.

  • تحصل الوحدة تلقائيًا على: البحث في لوحة الأوامر (مع فهرس البينيين)، ربط الاختصارات العامة، التحم في شريط التطبيقات (dock)، والتسجيل في جدول أسماء windowControl.

  • القناة الوحيدة بين الواجهة الأمامية و C++ هي window.Zen؛ يُنصح بالاستدعاء الموحّد عبر فئة التغليف ZenAPI (العيّنة تتضمن lib/zen_api.js).

  • الصفحات بدون بناء هي ملفات ثابتة مباشرة؛ بعد التعديل يكفي تحديث النافذة (windowControl('sdk_sample','hide') ثم show، أو إعادة تشغيل exe) — دون أي خطوة تصريف.

3. بنية الصفحة (JS أصلي، أربعة ملفات) #

index.html #

لا تستورد أي مكتبة طرف ثالث؛ الأزرار الثلاثة لشريط التحكم بالنافذة تستخدم رموز Unicode كأيقونات (− / □ / ×)، وتوفر lib/window_controls.css الأنماط. تُعلَّم مواضع النصوص بـ data-i18n / data-i18n-ph وتُملأ دفعةً واحدة عند تهيئة JS. البنية مقسمة إلى أربعة أجزاء: شريط البحث، شرائح سجل البحث، شريط الحالة (عدد النتائج + تلميح الصياغة)، قائمة النتائج:

<div class="search-bar">
    <input type="text" id="searchInput" class="search-input" data-i18n-ph="inputPlaceholder"
           spellcheck="false" autocomplete="off">
    <button class="search-btn" id="btnSearch" data-i18n="search"></button>
</div>
<div class="history-chips" id="historyChips"> ... </div>
<div class="status-bar">
    <span id="statusText" data-i18n="empty"></span>
    <span class="syntax-hint" data-i18n="syntaxHint"></span>
</div>
<div class="result-list" id="resultList"></div>

filefinder.js (المنطق الأساسي) #

خمس مسؤوليات، كلها يمكن نسخها من العيّنة كما هي:

  1. التحكم بالنافذة: ZenAPI.windowControl('sdk_sample', 'min'|'max'|'close'|'drag')؛ سحب شريط العنوان لا يُفعَّل إلا إذا تجاوز الإزاحة 5px؛ مفتاح Esc — إذا كان حقل الإدخال مركَّزًا يتم blur أولًا، وإلا تُغلق النافذة.
  2. الثيم: تسجيل window.__applyTheme لاستقبال الإرجاع من C++ (data-theme للشاشة الأولى يُحقن من C++، دون معالجة من JS).
  3. i18n: قراءة getConfig().language، أخذ النصوص من القاموس، وملء عناصر data-i18n بالمرور عليها؛ الجمل ذات العناصر النائبة مثل {{count}} تُفكّ بدالة استيفاء.
  4. البحث: searchFile(keyword, maxResults) واجهة ربط غير متزامن (تعمل في خيط خلفي دون حجب الواجهة)؛ Enter للبحث الفوري، وتثبيت الإدخال (debounce) بمقدار 300ms للبحث التلقائي؛ استخدام رقم تسلسلي متزايد لتجاهل الردود غير المرتبة — يمتلك الجانب الأصلي آلية "فتحة بحث" (الطلب الجديد يستبدل الطلب القديم غير المكتمل مباشرةً، ويحصل الـ Promise القديم على نتيجة فارغة)، والرقم التسلسلي في الواجهة يمنع هذه "النتيجة الفارغة المتأخرة" من الكتابة فوق عرض النتيجة الجديدة؛ الاثنان يعملان معًا.
  5. التعامل مع النتائج: openFile(fullPath, false) لفتح الملف (النقر المزدوج بالمثل؛ المعامل الثاني هو "بصلاحيات المدير")؛ openFileLocation(fullPath) لفتح المجلد الحاوي؛ يُبنى المسار الكامل من path + '\\' + name؛ الأيقونة تؤخذ مباشرة من حقل icon الجاهز في النتيجة (base64)؛ حجم الملف يُعرض منسقًا من الحقل الرقمي size.

بنية إرجاع searchFile ({ error, files[] }) #

حقول كل عنصر في files[]:

الحقل النوع الوصف
name / path سلسلة اسم الملف / المجلد الحاوي. المسار الكامل = path + '\\' + name
dateModified سلسلة وقت التعديل (نص بتنسيق محلّي)
size رقم حجم الملف بالبايت، رقم أصلي يُستخدم مباشرة
icon سلسلة أيقونة base64، تُستخدم مباشرة في <img src> دون الحاجة لاستدعاء getFileIcon
score رقم درجة الصلة (الجانب الأصلي رتّبها حسب الدرجة)
isDir رقم 1/0 رقم وليس قيمة منطقية أصلية (مسار JSON مبني يدويًا)؛ احكم بـ truthy أو === 1، لا تستخدم === true

الواجهات التي تستدعيها هذه العيّنة #

الواجهة الربط الوصف
searchFile(keyword, maxResults) غير متزامن بحث بفهرس MFT في كامل الأقراص، يدعم صياغة Everything (size:>100MB、ext:mp4、!ext:tmp)
openFile(path, admin) متزامن فتح ملف/مجلد (سلوك shell الافتراضي)، وبصلاحيات المدير عند admin=true
openFileLocation(path) متزامن تحديد الملف في مستكشف الملفات
getConfig(key?) متزامن قراءة الإعدادات: الكل عند الإغفال، أو المفتاح المحدد فقط عند تمرير key (يدعم المسار النقطي a.b)
setConfig(patch, replace?) متزامن كتابة سجل البحث بدقة ناعمة (granular): setConfig({ sdk_sample: { history } })؛ replace=true استبدال كامل (لاستيراد نسخة احتياطية فقط)
log(message) متزامن سجل الواجهة الأمامية، يُكتب في سجل العملية الرئيسية لسهولة التشخيص
windowControl(name, action) متزامن تصغير/تكبير/إغلاق/سحب النافذة

قواعد الاستدعاء (القواعد الأربع الذهبية) #

import ZenAPI from './lib/zen_api.js';

// 1. 判错用 isOk()（error 恒为数字：0 成功，-1 表示调用异常）
const res = await ZenAPI.searchFile('yyztools', 200);
if (!ZenAPI.isOk(res)) { ... }

// 2. 接口返回的布尔字段是原生布尔，直接判断
//    （例外一：config 的值由前端写入决定类型，通常是字符串，比较时注意归一）
//    （例外二：searchFile 结果的 isDir 是 1/0 数字——手拼 JSON 路径，用 truthy 或 === 1）
const ex = await ZenAPI.exists(path);
if (ex.exists === true) { ... }

// 3. 配置写入必须窄粒度，禁止全量回写
await ZenAPI.setConfig({ sdk_sample: { history } });   // 只写自己的键

// 4. 按 id 批量取应用信息用 getAppInfo，禁止循环 searchApp
const infos = await ZenAPI.getAppInfo(['calculator', 'ocr']);

الواجهات غير المتزامنة (getAppInfo / searchFile / حزمة الوسائط الخمسة / ocrRecognition) تُنفَّذ في خيط الخلفي؛ انتبه إلى أن عملية وسيط وسائط واحدة فقط تعمل في نفس اللحظة، والمهام الطويلة يجب أن توفر مدخل إلغاء عبر cancelRun().

مرجع سريع للواجهات الشائعة (قدرات إضافية غير العيّنة) #

السيناريو الواجهة
قراءة/كتابة إعداداتك getConfig / setConfig（patch ناعم）/ addConfig（إضافة عنصر لقائمة）
فتح/حفظ ملف browseFile / browseDir / writeFile / readFile（>50MB استخدم readFileChunk）
الحصول على مجلدات النظام getKnownDir('download') 等
فتح صفحة ويب/برنامج خارجي runAny('https://...', '')
النسخ إلى الحافظة الواجهة الأمامية navigator.clipboard（حالات النص لا تحتاج native）
لقطة شاشة/OCR screenCap('fast', ...) → ocrRecognition(base64)（كلاهما غير متزامن）
استدعاء نافذة وحدة أخرى windowControl('translate', 'show')

4. إنشاء ملف وحدة .zenmod (مستضيف النافذة) #

أنشئ ملف .zenmod جديدًا في Modules/<分类>/ (ملف العيّنة: sdk/sample/Modules/SDK_Sample.zenmod):

{
    "id": "sdk_sample",
    "type": "web",
    "name": { "zh_cn": "SDK样例工程", "en": "SDK Sample Project", "...": "共 12 门语言" },
    "desc": { "zh_cn": "基于 MFT 索引的全盘急速文件搜索，支持 Everything 语法", "en": "..." },
    "icon": "fas fa-search",
    "winClassName": "yyzTools::SdkSampleWindowClass",
    "width": 760,
    "height": 540,
    "layoutType": 34,
    "url": "SDK_Sample/index.html",
    "preCreate": 0
}

شرح الحقول (كل الحقول التي يقرأها البرنامج الرئيسي عند type:"web"):

الحقل إلزامي الوصف
id نعم فريد عالميًا. وهو في الوقت نفسه اسم النافذة في windowControl/windowState، وappId للاختصارات، ومعرّف التحم في dock
type نعم ثابت web
name نعم كائن بـ 12 لغة؛ يُسمح أيضًا بصيغة سلسلة نصية خالصة (تُنصح للاختبار الداخلي فقط)؛ ترتيب القيم: اللغة الحالية → en → السلسلة
desc لا كما أعلاه
icon لا FontAwesome class (كما أعلاه) أو صورة base64
winClassName لا اسم فئة نافذة Win32، يكفي أن يكون فريدًا عالميًا
width / height لا حجم النافذة الأولي، الافتراضي 800x600
layoutType لا قناع بتات تخطيط الموضع الأولي، 34 = توسيط أفقي + توسيط رأسي
url نعم مسار الصفحة نسبةً إلى جذر Web (SDK_Sample/index.html)؛ يدعم أيضًا العناوين الإلكترونية التي تبدأ بـ http(s)
preCreate لا 1 = إنشاء النافذة مسبقًا عند الإقلاع (تسريع الفتح الأول)، الافتراضي 0 أي عند الحاجة
canSuspend لا 1 = السماح بتعليق WebView عند إخفاء النافذة لتوفير الموارد (الافتراضي 1)

قائمة تحقق بعد التعديل: JSON قابل للتحليل، UTF-8 بدون BOM، id فريد عالميًا، اللغات الـ 12 كلها غير فارغة.

عند هذه النقطة اكتمل التطبيق — انسخ المجلدين كما في القسم الأول، وابحث في لوحة الأوامر عن "SDK样例工程" أو "sdk" لتشغيله (فهرس البينيين يُنشأ تلقائيًا)، كما يمكن استدعاؤه عبر windowControl('sdk_sample', 'show').

5. النصوص متعددة اللغات (بأسلوب القاموس) #

الحل بدون بناء يكفيه قاموس ES module عادي (i18n.js):

const messages = {
    zh_cn: { title: 'SDK样例工程', results: '{{count}} 个结果，耗时 {{ms}} ms', ... },
    en:    { title: 'SDK Sample Project', results: '{{count}} results in {{ms}} ms', ... }
};
export function getMessages(lang) { return messages[lang] || messages.en; }
export function interpolate(dict) {
    return (key, params) => { /* {{count}} → params.count */ };
}

عند التهيئة اقرأ getConfig().language لاختيار اللغة، مع الرجوع إلى en عند عدم العثور؛ الجمل ذات العناصر النائبة تُفكّ عبر tf('results', { count, ms }).

ملاحظات:

  • رموز اللغات بأسلوب الشرطة السفلية الصغيرة (zh_cn)، متوافقة مع .zenmod، وليست BCP47.

  • name/desc في .zenmod يجب أن تتضمن اللغات الـ 12 كاملة؛ نصوص الصفحة لا يوجد إلزام بها، والعيّنة تعطي zh_cn/en فقط، ويمكن توسيعها حسب الحاجة.

  • للوحدات التي يجب أن تتبع لغة الواجهة فورًا، يمكن تحويل القاموس إلى ملفات لغات تُحمَّل بـ import() كسولًا عند الحاجة؛ الآلية نفسها الموضحة في هذا المستند.

6. التصحيح والدمج #

1. 免构建直接跑（推荐起步）：
   复制 sdk/sample/Web、sdk/sample/Modules 到 bin64\（Release exe 所在目录），重启 exe。
   改前端后 windowControl('sdk_sample','close') 再打开，或重启 exe 生效。

2. 浏览器看结构：
   直接双击 Web/SDK_Sample/index.html 用浏览器打开。
   浏览器里没有 window.Zen，ZenAPI.call 会走异常路径返回 error: -1，
   页面结构 / 样式 / 输入防抖 / 渲染逻辑均可正常调试（原生接口除外）。

نصيحة أداء البحث: searchFile تعتمد فهرس MFT الشامل في الجانب C++ وتعيد النتائج عادة خلال أجزاء من الثانية؛ يمتلك الجانب الأصلي آلية فتحة البحث — الطلب الجديد يستبدل الطلب القديم غير المكتمل (والقديم يعيد نتيجة فارغة)، والواجهة تستخدم تثبيتًا 300ms + رقمًا تسلسليًا متزايدًا لتجاهل الردود غير المرتبة، فلا تطوف ضغطات المفاتيح المتتالية خيط الخلفي ولا تُظهر نتائج قديمة وميضًا. أيقونات النتائج (base64) يعيدها searchFile جاهزة، دون استدعاء getFileIcon إضافي.

عندما لا تكفي قدرات الواجهات (مثلًا حاجة لقدرة C++ جديدة)، يمكن تقديم الطلب عبر قنوات الملاحظات في الموقع الرسمي، وسيوسّع البرنامج الرئيسي الواجهات في إصدارات لاحقة.

8. إرشادات الأمان #

تمنح واجهة Native API مطوّري الوحدات وصولًا كاملًا ومفتوحًا لقدرات النظام في العملية المضيفة، بما في ذلك قراءة الملفات وكتابتها وحذفها، إنشاء العمليات وإنهاؤها، التحكم بالنوافذ، قراءة الحافظة وكتابتها، تعديل إعدادات النظام، تنفيذ أسطر الأوامر وغيرها من العمليات عالية الخطورة، وبدون نوافذ أذونات، وبدون عزل في صندوق حماية (sandbox)، وبدون آلية تراجع.

قيّم بنفسك أمان كل عملية قبل الاستدعاء: تحقّق من كل مدخلات خارجية، وخذ نسخة احتياطية أو اطلب تأكيد المستخدم قبل العمليات غير القابلة للتراجع، ولا تستخدم إلا القدرات التي يحتاجها التطبيق فعلًا. ويتحمل المطوّر بنفسه كل العواقب المترتبة عن ذلك.
