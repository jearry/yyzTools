1. الاصطلاحات العامة #

يحدد هذا المستند جميع الواجهات المتعلقة بالتفاعل مع Native، ويقتصر على الواجهات المسجلة لدى العملية الرئيسية yyzTools.exe (SetupBindings() في src/yyztools/NativeApi.cpp).

طريقة الاستدعاء #

  • تستدعي الواجهة الأمامية دوال الواجهات عبر الكائن window.Zen، ويُنصح بالاستدعاء الموحّد عبر فئة التغليف ZenAPI: web/lib/zen_api.js، ولا تستدعِ window.Zen مباشرة في شيفرة العمل، لتسهيل التعامل معها كطبقة توافق للواجهات عند الترقية والتعديل.

  • المدخلات: تُمرَّر بأسلوب المعاملات الموضعية؛ راجع عدد المعاملات وأنواعها في كل واجهة بعينها

  • المخرجات: تُمرَّر عبر القيمة المُرجعة، وهي كائن json يتضمن ما يلي

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error: 0 يعني النجاح، وغير 0 يعني الخطأ

    • errorMsg (اختياري): رسالة الخطأ

    • غير ذلك (اختياري): راجع كل واجهة بعينها

طريقة كشف الأخطاء #

error دائمًا رقم: 0 يعني النجاح، وغير 0 يعني الخطأ (وفي حالة استثناء الاستدعاء تكون -1).

الربط المتزامن / غير المتزامن #

الغالبية العظمى من الواجهات ربط متزامن (BindSync)، تعيد النتيجة فور الاستدعاء. الواجهات السبع التالية ربط غير متزامن (BindAsync)، تعمل في خيط خلفي وتعيد النتيجة عبر Promise دون حجب خيط الواجهة:

getAppInfo、searchFile、imageRun、ffmpegRun、pdfRun、gsRun、ocrRecognition

لمعرفة قيود سلوك الواجهات غير المتزامنة في نفس اللحظة راجع البنود المعنية (مثلًا حزمة الوسائط الخمسة تعمل تسلسليًا وتتشارك cancelRun للإلغاء).

2. قراءة الإعدادات #

function Zen.getConfig(key?: string) : object

  • المدخلات

    • key (اختياري): يقرأ هذا المفتاح فقط، ويدعم المسار النقطي a.b. عند الإغفال يعيد الإعدادات كاملة.

  • المخرجات (مثال، والحقول وفق الإعدادات الفعلية)

    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel: مستوى السجل (0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal)

    • wallpaperEnabled: تفعيل الخلفية الحيوية

    • overlayEnabled: تفعيل مؤثرات سطح المكتب

    • gameMode: وضع الألعاب

    • clipboardHistoryMaxCount: العدد الأقصى لسجلات تاريخ الحافظة

    • autoStart: التشغيل التلقائي عند إقلاع النظام

    • shortcutKeys: الاختصارات العامة

      • main: الواجهة الرئيسية

        • doubleCtrlEnabled: الاستدعاء بنقرة Ctrl مزدوجة

        • doubleAltEnabled: الاستدعاء بنقرة Alt مزدوجة

        • modifier: مفتاح التعديل

        • virtualCode: المفتاح الرئيسي

      • apps: التطبيقات

        • appId: معرّف التطبيق

        • modifier: مفتاح التعديل

        • virtualCode: المفتاح الرئيسي

    • quickOpen: الفتح السريع

      • name: الاسم

      • type: النوع (normal: بحث عام / spec: بحث رأسي)

      • index: الرقم التسلسلي

      • url: قالب url

      • enabled: هل هو مفعّل

    • customApps: تطبيقات app مخصصة

      • filePath: مسار exe الخاص بالتطبيق

      • enabled: هل هو مفعّل

    • dock: شريط التطبيقات (الفئات + المحتويات)

      • الاصطلاح العام: غياب name/icon يعني "استخدام القيم المدمجة الافتراضية" (تُشتق وقت التشغيل من i18n أو من .zenmod المقابل لـ appId ، وتتغير مع لغة الواجهة)؛ وجود الحقل يعني أن المستخدم خصّصه، فيُعرض كما هو دون ترجمة.

      • categories: الفئات

        • id: الفئات المدمجة معرّفاتها دلالية (folder/tools/ai/game/system)، وما ينشئه المستخدم يكون category_<时间戳>

        • name: اختياري، يوجد فقط بعد إعادة تسمية من المستخدم

        • icon: FontAwesome class

        • color: لون الثيم

        • order: رقم الترتيب

      • contents: عناصر المحتوى

        • id: عناصر المجلدات المدمجة معرّفاتها دلالية (desktop/documents/downloads/music/videos)، والبقية content_<时间戳>

        • categoryId: معرّف الفئة التابع لها

        • type: app | folder | url

        • appId: إلزامي عند type=app، ويقابل id في .zenmod؛ الاسم والأيقونة كلاهما مشتق منه، لا يُحفظ على القرص

        • folderPath: إلزامي عند type=folder، ويدعم متغيرات البيئة مثل %USERPROFILE%

        • url: إلزامي عند type=url، والعنوان الكامل بعد التطبيع (تُضاف https:// تلقائيًا إذا غاب البروتوكول)؛ النقر يفتحه بالمتصفح الافتراضي للنظام. الاسم يملؤه المستخدم، والأيقونة تُجلب وقت التشغيل من favicon للموقع (وعند الفشل تُستخدم fas fa-globe احتياطًا)، لا تُحفظ على القرص

        • name / icon: اختياريان، بنفس الدلالة أعلاه (إلزاميان للمجلدات التي يختارها المستخدم عند type=folder)

        • color: تلوين الأيقونة

        • order: رقم الترتيب داخل الفئة الواحدة

3. تعديل الإعدادات #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • المدخلات

    • config: بنفس بنية getConfig

      • مرّر ما تريد تعديله فقط، دون حاجة لتمرير كل المحتوى

      • المحتوى تحت نفس المفتاح يجب تمريره كاملًا

      {
    "logLevel": "1"
}

    • replace (اختياري، الافتراضي false): false = دمج تزايدي مع الإعدادات الحالية، true = استبدال كامل (لاستيراد نسخة احتياطية، ويمحو عناصر القوائم المحذوفة). مرّر السلسلة "true" أو "false"، والإغفال يعادل "false".

  • ملاحظة: لا تقم بـ "قراءة كل الإعدادات عبر getConfig ثم إعادة كتابتها كاملة عبر setConfig" — القيمة المرجعة من getConfig تتضمن حقل error، وإعادة كتابتها كاملة ستحفظه في ملف الإعدادات. اكتب دائمًا بدقة ناعمة (granular)، مثل setConfig({ dock: { categories } }).

  • المخرجات

    {
    "error": 0,
    "errorMsg": ""
}

3. الحصول على حالة النافذة #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • المدخلات

    • window: الـ Name أو الـ HWND بصيغة string، راجع التحكم بالنافذة

  • المخرجات

    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state: الحالة (show: عرض طبيعي / min: مصغّرة / max: مكبّرة / close: مغلقة)

    • topmost: هل هي مثبتة في الأعلى

2. الحصول على حالة التحديث #

function Zen.getUpdateState() : object

يستقصي حالة التحديث في الزمن الحقيقي (للتسويق الدوري من علبة النظام):

  • هل يعمل المحدّث → عبر كائن الحصر المفرد Local\yyzUpdater_SingleInstance

  • هل دُنّز التحديث بانتظار التطبيق → هل يوجد %APPDATA%\yyzTools\Update\update.ready (وإن وُجد يُحلَّل فيه إصدار حزمة main)

  • ما إذا كان الفحص اليدوي قد انتهى دون تحديث → علامة %APPDATA%\yyzTools\Update\update.result (تُحذف فور قراءتها)

  • المدخلات: لا شيء

  • المخرجات

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status: idle (لا نشاط تحديث) / checking (المحدّث قيد التشغيل) / ready (اكتمل التنزيل ويمكن الترقية)

    • version: له قيمة فقط في حالة ready، وهو رقم الإصدار الجديد بانتظار التطبيق (من حزمة main)، وفي غير ذلك سلسلة فارغة

    • lastResult: قد تكون له قيمة فقط في حالة idle، وهي نتيجة آخر فحص يدوي (--check-and-apply): uptodate (أنت على أحدث إصدار) / error (فشل الفحص)، وسلسلة فارغة عند غياب العلامة. يكتب المحدّث هذه العلامة وتحذفها هذه الواجهة فور قراءتها، لذا تُعاد مرة واحدة فقط، لتُظهر الواجهة الأمامية Toast مرة واحدة؛ أما الفحص الصامت --check فلا يكتب علامة ولا يسبب إزعاجًا.

    • أولوية الحالة: checking > ready > idle

تمنح واجهة Native API مطوّري الوحدات وصولًا كاملًا ومفتوحًا لقدرات النظام في العملية المضيفة، بما في ذلك قراءة الملفات وكتابتها وحذفها، إنشاء العمليات وإنهاؤها، التحكم بالنوافذ، قراءة الحافظة وكتابتها، تعديل السجل (Registry) وإعدادات النظام، التنزيل عبر الشبكة وتنفيذ أسطر الأوامر وغيرها من العمليات عالية الخطورة.

هذه الواجهات بدون نوافذ أذونات، وبدون عزل في صندوق حماية (sandbox)، وبدون آلية تراجع — الاستدعاء يسري فورًا بصلاحيات المستخدم الحالي، وسوء الاستخدام قد يؤدي إلى فقدان دائم للبيانات أو خلل في النظام.

لذا يرجى الانتباه حتمًا إلى ما يلي:

  • قيّم الأمان بنفسك: قبل استدعاء أي واجهة، تأكد أولًا أن مصدر المعاملات (خاصة المسارات وأسماء العمليات وأسطر الأوامر) موثوق ومتحقق منه إроверًا كافية؛ بالنسبة للعمليات غير القابلة للتراجع مثل الحذف والاستبدال وإنهاء العمليات، يُنصح بأخذ نسخة احتياطية أو طلب تأكيد ثانٍ من المستخدم.
  • احذر المدخلات غير الموثوقة: لا تدمج أبدًا مدخلات المستخدم أو استجابات الشبكة أو بيانات الأطراف الثالثة في معاملات الواجهات دون تحقق؛ احذر من تجاوز المسار (path traversal) وحقن الأوامر.
  • مبدأ أقل الصلاحيات: لا تطلب إلا القدرات التي يحتاجها التطبيق فعلًا، وتجنب استخدام واجهات ذات نطاق تأثير أوسع طلبًا للراحة.
  • المسؤولية على عاتق المطوّر: يتحمل المطوّر بنفسه كل العواقب المترتبة عن استخدام هذه الواجهة البرمجية، بما في ذلك على سبيل المثال لا الحصر فقدان البيانات وتلف النظام والمخاطر الأمنية.
