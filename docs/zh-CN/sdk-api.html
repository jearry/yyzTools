一、通用约定 #

本文档定义所有和 Native 交互相关的接口，仅覆盖主进程 yyzTools.exe 注册的接口（src/yyztools/NativeApi.cpp 的 SetupBindings()）。

调用方式 #

  • 前端通过 window.Zen 对象调用接口函数，建议统一走 ZenAPI 封装类：web/lib/zen_api.js，不要在业务代码里直连 window.Zen，方便升级调整接口时作为接口兼容层处理。

  • 输入：采用位置参数方式传递，具体参数个数和类型参考具体接口

  • 输出：通过返回值传递，值为 json 对象，包含以下内容

    {
    "error": 0,
    "errorMsg": "",
    ...
}

    • error：0 正确，非 0 错误

    • errorMsg（可选）：错误信息

    • 其他（可选）：参考具体接口

判错方式 #

error 恒为数字：0 正确，非 0 错误（调用异常时为 -1）。

同步 / 异步绑定 #

绝大多数接口为同步绑定（BindSync），调用即返回。以下 7 个接口为异步绑定（BindAsync），在后台线程执行，通过 Promise 回扑，不阻塞 UI 线程：

getAppInfo、searchFile、imageRun、ffmpegRun、pdfRun、gsRun、ocrRecognition

异步接口同一时刻的行为约束参考具体条目（如媒体五件套为串行执行，共用 cancelRun 取消）。

二、公用接口 #

1、获取客户端版本 #

function Zen.getVersion() : object

  • 输入：无

  • 输出

    {
    "error": 0,
    "errorMsg": "",
    "apiVersion": "1.0.1",
    "appVersion": "1.0.1",
    "usageTime": 90,
    "usageTimes": 3602,
    "firstUseTime": "20250910"
}

    • apiVersion：客户端API版本信息。每一次涉及到接口更新，版本号都加1；数字从0到9，9以后从0开始，比如1.0.0，1.0.1，1.0.2... 1.0.9，1.1.0等

    • appVersion：客户端版本信息

    • usageTime：使用时间（单位：s）

    • usageTimes：激活次数

    • firstUseTime：首次使用时间，格式：yyyymmdd

2、获取配置 #

function Zen.getConfig(key?: string) : object

  • 输入

    • key（可选）：只取该键，支持 a.b 点路径。缺省返回全量配置。

      • 命中：返回 {"error":0, "<key>": <值>}，如 getConfig("language") → {"error":0,"language":"zh_cn"}；getConfig("dock.categories") → {"error":0,"dock":{"categories":[...]}}

      • 未命中：返回 {"error":0}（不报错，读取方自行兜底）

  • 输出（示例，字段以实际配置为准）

    {
    "error": 0,
    "errorMsg": "",
    "logLevel": "1",
    "wallpaperEnabled": "1",
    "overlayEnabled": "0",
    "gameMode": "0",
    "clipboardHistoryMaxCount": "500",
    "autoStart": "1",
    "shortcutKeys": {
        "main": {
            "doubleCtrlEnabled": "1",
            "doubleAltEnabled": "1",
            "modifier": 1,
            "virtualCode": 32
        },
        "apps": [
            {
                "appId": "translate",
                "modifier": 1,
                "virtualCode": 49
            },
            {
                "appId": "ocr",
                "modifier": 1,
                "virtualCode": 50
            }
        ]
    },
    "quickOpen": [
        {
            "name": "谷歌搜索",
            "type": "normal",
            "index": "0",
            "url": "https://www.google.com/search?q={query}",
            "enabled": "1"
        }
    ],
    "customApps": [
        {
            "filePath": "d:\test\test1.exe",
            "enabled": "1"
        }
    ]
}

    • logLevel：日志等级（0: Trace / 1: Debug / 2: Info / 3: Warning / 4: Error / 5: Fatal）

    • wallpaperEnabled：启用动态壁纸

    • overlayEnabled：启用桌面特效

    • gameMode：游戏模式

    • clipboardHistoryMaxCount：剪贴板最大历史记录个数

    • autoStart：开机自启动

    • shortcutKeys：全局快捷键

      • main：主界面

        • doubleCtrlEnabled：双击Ctrl唤醒

        • doubleAltEnabled：双击Alt唤醒

        • modifier：修饰键

        • virtualCode：主键

      • apps：应用

        • appId：应用id

        • modifier：修饰键

        • virtualCode：主键

    • quickOpen：快开

      • name：名称

      • type：类型（normal：通用搜索 / spec：垂直搜索）

      • index：序号

      • url：url模板

      • enabled：是否启用

    • customApps：自定义app

      • filePath：app对应exe的所在路径

      • enabled：是否启用

    • dock：程序坞（类目 + 内容）

      • 通用约定：缺 name/icon 表示"用内置默认值"（由 i18n 或 appId 对应的 .zenmod 运行时派生，随界面语言变化）；有该字段表示用户自定义过，原样显示不再翻译。

      • categories：类目

        • id：内置类目为语义 id（folder/tools/ai/game/system），用户新建为 category_<时间戳>

        • name：可选，用户改名后才有

        • icon：FontAwesome class

        • color：主题色

        • order：排序序号

      • contents：内容项

        • id：内置目录项为语义 id（desktop/documents/downloads/music/videos），其余为 content_<时间戳>

        • categoryId：所属类目 id

        • type：app | folder | url

        • appId：type=app 时必填，对应 .zenmod 的 id；名称与图标全部由它派生，不要落盘

        • folderPath：type=folder 时必填，支持 %USERPROFILE% 等环境变量

        • url：type=url 时必填，规范化后的完整网址（无协议前缀自动补 https://）；点击用系统默认浏览器打开。名称由用户填写，图标运行时抓取网站 favicon（失败兜底 fas fa-globe），不落盘

        • name / icon：可选，语义同上（type=folder 的用户自选目录必填）

        • color：图标着色

        • order：同类目内的排序序号

3、修改配置 #

function Zen.setConfig(config: json_obj, replace?: boolean) : object

  • 输入

    • config：同getConfig

      • 修改什么就传什么，无需传全部内容

      • 同一键值下的内容需要传完整

      {
    "logLevel": "1"
}

    • replace（可选，默认 false）：false=增量合并到现有配置，true=整体替换（导入备份用，能清掉已删除的列表项）。传入 "true" 或 "false" 字符串，缺省等同 "false"。

  • 注意：不要"读全量 getConfig 再整份 setConfig 回写"——getConfig 返回值带 error 字段，整份回写会把它存进配置文件。一律窄粒度写，如 setConfig({ dock: { categories } })。

  • 输出

    {
    "error": 0,
    "errorMsg": ""
}

3、窗口状态获取 #

function Zen.windowState(window: string, can_suspend?: boolean) : object

  • 输入

    • window：Name或HWND的string形式，参见窗口控制

    • can_suspend（可选）：是否允许挂起该窗口的 WebView（资源管理开关，缺省 false）

  • 说明：本接口带副作用——查询状态后，若窗口处于 show/max 状态则恢复 WebView 渲染，否则挂起 WebView 以省资源（仅当 can_suspend 为 true 时允许挂起）。前端常驻页面轮询自身状态时传 true，一般查询传 false。

  • 输出

    {
    "error": 0,
    "errorMsg": "",
    "state": "show",
    "topmost": "0"
}

    • state：状态（show：正常显示 / min：最小化 / max：最大化 / close：关闭）

    • topmost：是否置顶

2、按 id 批量取应用信息（异步） #

function Zen.getAppInfo(appIds: string[]) : object

配置里只存 appId，名称与图标一律运行时派生（.zenmod 的 name 是多语言的，快照进配置会在切语言后过期）。这个接口就是给这个场景用的。

⚠️ 不要用循环 searchApp(appId, 1) 代替它：searchApp 每次都是对整个应用索引做全表扫描 + 拼音匹配 + 打分排序，还会并发起两个线程、返回多条带 base64 图标的结果。程序坞加上快捷键有几十个 appId，逐个查会明显拖慢启动。本接口一次收全，native 侧走 map::find 精确命中。

内部会等应用索引就绪（索引由后台线程生成），故是异步绑定，冷启动早期调用不会拿到空结果。

  • 输入

    • appIds：appId 数组，如 ["calculator", "Microsoft.WindowsCamera"]

  • 输出

    格式与 searchApp 完全一致（同一个 BuildAppResult），但：

    • 只返回精确命中的项，查不到的 id 会被静默跳过，故 apps.length 可能小于入参长度（用来检出配置里的失效 appId）

    • 顺序按入参顺序，score 恒为 0（未参与打分）

    {
    "error": 0,
    "apps": [
        {
            "id": "calculator",
            "name": "超级计算器",
            "path": "calculator",
            "desc": "",
            "icon": "data:image/png;base64,",
            "appType": 4,
            "score": 0
        }
    ]
}

七、媒体处理 #

媒体五件套由 C++ 侧调起 bin64\Platform\ 下的第三方 CLI 工具执行。除 ffprobeRun 外均为异步绑定（后台线程执行，不阻塞 UI 线程）；批量处理为串行，同一时刻仅有一个子进程在执行，可用 Zen.cancelRun() 终止当前执行（被取消时返回 errorMsg: "cancelled"）。

1、执行 magick 命令（异步） #

function Zen.imageRun(args: string) : object

  • 输入

    • args：完整的 magick 命令行参数（不含 magick.exe 本身），由前端拼接。路径需自行加双引号，例如 "D:\\in.jpg" -resize 800x600 "D:\\out.jpg"

  • 输出

    {
  "error": 0,
  "stdout": "..."
}

  • 注：C++ 端不拼接参数，只执行 magick.exe <args> 并捕获结果。error 非 0 时 errorMsg 透传 magick stderr；stdout 为 magick 标准输出（identify 等命令的结果）

2、执行 ffmpeg 命令（异步） #

function Zen.ffmpegRun(args: string) : object

  • 输入

    • args：完整的 ffmpeg 命令行参数（不含 ffmpeg.exe 本身），由前端拼接。路径需自行加双引号，例如 -i "D:\in.mp4" -vf "scale=1280:720" -c:v libx264 -crf 23 "D:\out.mp4"

  • 输出

    {
  "error": 0,
  "stdout": "..."
}

  • 注：C++ 端不拼接参数，只执行 ffmpeg.exe <args> 并捕获结果。error 非 0 时 errorMsg 透传 ffmpeg stderr；stdout 为 ffmpeg 标准输出。视频处理耗时较长，C++ 默认超时 1800s

3、执行 ffprobe 命令（探测元数据，同步） #

function Zen.ffprobeRun(args: string) : object

  • 输入

九、加密解密 #

1、加密数据 #

function Zen.encrypt(target: string, algorithm: string, type: string, key: string, iv: string) : object

  • 输入

    • target：要加密的数据

      • type="text" 时为文本字符串

      • type="data" 时为 Base64 编码的二进制数据

      • type="hex" 时为十六进制字符串

      • type="file" 时为文件路径

    • algorithm：加密算法

      • 对称加密："aes-128-cbc", "aes-192-cbc", "aes-256-cbc", "aes-128-ecb", "aes-256-ecb", "aes-128-ctr", "aes-256-ctr", "des-cbc", "des-ecb", "des-ede3-cbc" (3DES), "des-ede3-ecb", "rc4", "bf-ecb" (Blowfish), "rc2-cbc", "sm4-cbc", "sm4-ecb", "sm4-ctr"

      • 非对称加密："rsa-pkcs1", "rsa-oaep"（RSA，公钥加密、私钥解密）、"sm2"（国密椭圆曲线 sm2p256v1，公钥加密、私钥解密；单次可处理任意长度，无需分块）

      • key/iv 为 Base64；内部转十六进制后以 enc -K <hex> -iv <hex> 形式传递，密钥长度需精确匹配算法

    • type：输入类型（默认 "text"）

      • "text"：文本数据

      • "data"：Base64 编码的二进制数据

      • "hex"：十六进制字符串

      • "file"：文件路径

    • key：对称为 Base64 编码的密钥；非对称(rsa-*、sm2)为 PEM 文本（加密传公钥、解密传私钥，原样透传不 Base64 解码）

    • iv：Base64 编码的初始化向量（可选，某些算法需要；非对称忽略）

  • 输出

    {
  "error": 0,
  "result": "Base64编码的加密数据",
  "algorithm": "aes-256-cbc",
  "type": "text",
  "inputSize": 1024,
  "outputSize": 1040
}

3、生成密钥 #

function Zen.generateKey(algorithm: string, bits: string = '') : object

统一密钥生成入口（由内置 openssl.exe 生成，前端无需依赖浏览器 WebCrypto）。

  • 输入

    • algorithm：算法名

      • 对称：aes-128-cbc / aes-256-cbc / des-cbc / des-ede3-cbc / sm4-cbc / sm4-ecb / sm4-ctr / rc2-cbc / rc4 / bf-ecb 等（密钥长度由算法名解析）

      • 非对称："rsa"（bits 生效）/ "sm2"（固定曲线 sm2p256v1）

    • bits：RSA 密钥位数（"2048"/"4096"，默认 2048）；对称算法与 SM2 忽略

  • 输出

    // 对称算法
{ "error": 0, "algorithm": "aes-256-cbc", "key": "Base64编码的密钥" }
// 非对称算法
{ "error": 0, "algorithm": "sm2", "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n", "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n" }

4、生成IV #

function Zen.generateIv(algorithm: string) : object

按对称算法块大小生成随机 IV（由内置 openssl.exe 生成）。

  • 输入

    • algorithm：对称算法名（同 encrypt 的对称算法清单）

  • 输出

    { "error": 0, "algorithm": "aes-256-cbc", "iv": "Base64编码的IV" }

    注：AES/SM4 块大小 16 字节；DES/3DES/RC2 为 8 字节；ECB 模式与流密码(rc4)无需 IV，iv 返回空串。

5、计算哈希 #

function Zen.calcHash(target: string, algorithm: string, type?: string, key?: string) : object

  • 输入

    • target：计算目标，含义随 type 变化

      • type="file" 时为文件路径

      • type="text" 时为文本字符串（按 UTF-8 计算摘要）

      • type="data" 时为 Base64 编码的二进制数据

      • type="hex" 时为十六进制字符串

    • algorithm：哈希算法

      • "md5"

      • "sha1"

      • "sha224"

      • "sha256"

      • "sha384"

      • "sha512"

      • "ripemd160"

      • "sm3"（国密 SM3 摘要，256 位 / 64 位十六进制）

      • "sha3-224" / "sha3-256" / "sha3-384" / "sha3-512"（SHA-3 / Keccak，NIST FIPS 202）

      • "blake2b512" / "blake2s256"（BLAKE2，现代高性能摘要）

      • "crc32"（CRC32 校验和，8 位十六进制）

      • "crc16"（CRC16 校验和，4 位十六进制）

      • "checksum"（字节累加和，8 位十六进制）

      • "hmac-md5" / "hmac-sha1" / "hmac-sha256" / "hmac-sha512" / "hmac-sm3" / "hmac-sha3-256" / "hmac-sha3-512"（HMAC，第 4 参 key 为密钥，输出十六进制 MAC）

    • type：输入类型（可选，默认 "file"）

      • "file"：计算文件哈希

      • "text"：计算文本哈希

      • "data"：计算二进制数据哈希（target 需为 Base64 字符串）

      • "hex"：计算十六进制字符串哈希（target 为 hex 字符串，解码后按字节计算）

  • 输出

    {
  "error": 0,
  "hash": "D41D8CD98F00B204E9800998ECF8427E",
  "algorithm": "md5",
  "type": "file"
}

十三、更新 #

更新由独立进程 yyzUpdater.exe 完成，主进程仅负责拉起与状态探测。

1、检查更新 #

function Zen.checkUpdate() : object

拉起 yyzUpdater.exe --check-and-apply（检测 + 下载 + 应用一条龙）。

  • 输入：无

  • 输出

    { "error": 0, "errorMsg": "success" }

    注：error:0 仅表示成功拉起更新器，不代表更新结果。更新进行中/已就绪的状态用 getUpdateState 查询。

2、获取更新状态 #

function Zen.getUpdateState() : object

实时探测更新状态（供托盘轮询）：

  • updater 是否在运行 → 单例互斥体 Local\yyzUpdater_SingleInstance

  • 是否已下载待应用 → %APPDATA%\yyzTools\Update\update.ready 是否存在（存在则解析其中 main 包 version）

  • 手动检查是否已结束且无更新 → %APPDATA%\yyzTools\Update\update.result 标记（读到即删）

  • 输入：无

  • 输出

    { "error": 0, "status": "idle", "version": "", "lastResult": "" }

    • status：idle（无更新活动）/ checking（更新器运行中）/ ready（已下载完毕可升级）

    • version：仅 ready 态有值，为待应用的新版本号（取 main 包），其余为空串

    • lastResult：仅 idle 态可能有值，为上一次手动检查（--check-and-apply）的结果：uptodate（已是最新）/ error（检查失败），无标记时为空串。该标记由 updater 写入、本接口读取后立即删除，因此只会返回一次，供前端弹一次 Toast；静默的 --check 不写标记，不会产生打扰。

    • 状态优先级：checking > ready > idle

3、应用已下载完毕的更新 #

function Zen.applyUpdate() : object

拉起 yyzUpdater.exe --apply：读 update.ready → 等主进程退出 → 替换文件 → 重启主进程。仅在 getUpdateState 返回 ready 时调用。

  • 输入：无

  • 输出

    { "error": 0, "errorMsg": "success" }

⚠️ 安全须知 #

Native API 面向模块开发者完整开放宿主进程的系统能力，其中包含文件读写与删除、进程创建与终止、窗口控制、剪贴板读写、注册表与系统设置修改、网络下载及命令行执行等高危操作。

这些接口不设权限弹窗、不做沙箱隔离、不提供撤销机制——调用即以当前用户权限直接生效，误用可能导致数据永久丢失或系统异常。

因此请务必注意：

  • 自行评估安全性：调用任何接口前，先确认参数（尤其是路径、进程名、命令行）来源可信且已充分校验；对删除、覆盖、结束进程等不可逆操作，建议先行备份或向用户二次确认。
  • 警惕不可信输入：切勿将用户输入、网络响应或第三方数据未经校验地直接拼入接口参数，谨防路径穿越与命令注入。
  • 最小权限原则：只申请业务真正需要的能力，避免为图省事使用影响面更大的接口。
  • 责任自负：开发者须自行承担因使用本 API 而造成的一切后果，包括但不限于数据丢失、系统损坏与安全风险。
