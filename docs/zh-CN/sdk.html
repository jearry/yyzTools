快速入门指南

从零写出你的第一个模块，无需任何构建工具

接口参考手册 下载样例工程

本文面向模块开发者，演示如何从零创建一个运行在 yyzTools 主进程内的 Web 应用（以 SDK 样例工程 SDK_Sample——一个急速文件查询器——为例），覆盖：页面目录、窗口宿主、i18n、异步 Native API（全盘文件搜索）、文件打开、配置持久化，以及需要扩展 C++ 能力时的 native 方法新增模板。

样例是纯原生 JS、零第三方依赖、免构建的：不需要 Vite / Alpine / FontAwesome，复制 Web 与 Modules 两个目录到 yyzTools.exe 所在目录即可运行。

一、样例目录与部署方式 #

sdk/sample/
  Web/                        ← 复制到 <yyzTools.exe 所在目录>\Web\        （与现有 Web 目录合并）
    SDK_Sample/               ← 样例自包含目录，整个文件夹即一个完整模块
      index.html              # 页面结构（原生 DOM，data-i18n 标注文案位）
      filefinder.js           # 全部逻辑：搜索 / 打开 / 历史 / Esc
      filefinder.css          # 页面样式（全部用 --zen-* 变量，自动适配深浅色）
      i18n.js                 # 文案字典（zh_cn / en）
      lib/
        zen_api.js            # ZenAPI 封装类（Native API 的 JS 包装，唯一 lib 依赖）
        window_controls.css   # 主题变量（--zen-*）+ 窗口控制栏样式
  Modules/                   ← 复制到 <yyzTools.exe 所在目录>\Modules\    （与现有 Modules 目录合并）
    SDK_Sample.zenmod         # type:"web" 模块声明，ModuleManager 自动创建宿主窗口

部署：

把 sdk/sample/Web     复制/合并到  bin64\Web\
把 sdk/sample/Modules 复制/合并到  bin64\Modules\
重启 yyzTools.exe，命令面板搜"SDK样例工程"即可启动

主程序读取位置的约定：

资源 位置
页面 <exe目录>\Web\{page}\index.html
模块 <exe目录>\Modules\<分类>\*.zenmod（只扫一层子目录）

二、架构总览：一个 Web 应用是如何跑起来的 #

Modules/SDK_Sample.zenmod   ← 声明 type:"web" 的模块文件（数据驱动，无需写 C++）
        │  主程序启动时扫描 .zenmod
        ▼
WebModule 宿主窗口（原生窗口 + WebView2）
        │  加载 Web\SDK_Sample\index.html
        ▼
Web/SDK_Sample/             ← 你的全部前端代码（原生 JS，零依赖）
        │  window.Zen.xxx(...)  ←→  主程序注册的原生接口
        ▼
C++ 各 Manager（文件/进程/窗口/剪贴板/OCR...）

关键结论：

  • 不需要写任何 C++ 代码。type: "web" 的 .zenmod 会被主程序自动创建为 WebModule 宿主窗口，窗口尺寸、图标、多语言名称都由模块文件声明。

  • 模块自动获得：命令面板搜索（含拼音索引）、全局快捷键绑定、程序坞挂载、windowControl 名称表注册。

  • 前端与 C++ 的唯一通道是 window.Zen，请统一通过 ZenAPI 封装类调用（样例已附带 lib/zen_api.js）。

  • 免构建页面直接是静态文件，改完刷新窗口即生效（windowControl('sdk_sample','hide') 再 show，或重启 exe），无需任何编译步骤。

三、页面结构（原生 JS，四个文件） #

index.html #

不引任何第三方库；窗口控制栏的三个按钮用 Unicode 字符当图标（− / □ / ×），样式由 lib/window_controls.css 提供。文案位用 data-i18n / data-i18n-ph 标注，JS 初始化时统一填充。结构分四块：搜索栏、搜索历史 chips、状态栏（结果数 + 语法提示）、结果列表：

<div class="search-bar">
    <input type="text" id="searchInput" class="search-input" data-i18n-ph="inputPlaceholder"
           spellcheck="false" autocomplete="off">
    <button class="search-btn" id="btnSearch" data-i18n="search"></button>
</div>
<div class="history-chips" id="historyChips"> ... </div>
<div class="status-bar">
    <span id="statusText" data-i18n="empty"></span>
    <span class="syntax-hint" data-i18n="syntaxHint"></span>
</div>
<div class="result-list" id="resultList"></div>

filefinder.js（核心逻辑） #

五个职责，全部照抄样例即可：

  1. 窗口控制：ZenAPI.windowControl('sdk_sample', 'min'|'max'|'close'|'drag')；标题栏拖动判定位移超过 5px 才触发；Esc 键——输入框有焦点先 blur，否则关窗。
  2. 主题：注册 window.__applyTheme 接收 C++ 回推（首屏 data-theme 由 C++ 注入，无需 JS 处理）。
  3. i18n：读 getConfig().language，从字典取文案，遍历 data-i18n 元素填充；带 {{count}} 占位的句子用插值函数展开。
  4. 搜索：searchFile(keyword, maxResults) 是异步绑定接口（后台线程执行，不阻塞 UI）；回车立即搜、输入防抖 300ms 自动搜；用递增序号丢弃乱序回包——native 侧有搜索槽机制（新请求直接顶掉未完成的旧请求，旧 Promise 拿到的是空结果），前端序号防止这个"空结果晚到"覆盖掉新结果的渲染，二者配合。
  5. 结果操作：openFile(fullPath, false) 打开文件（双击同，第二参数是"是否管理员权限"）；openFileLocation(fullPath) 打开所在目录；完整路径由 path + '\\' + name 拼出；图标直接用结果里现成的 icon 字段（base64）；文件大小用 size 数字字段格式化展示。

searchFile 返回结构（{ error, files[] }） #

files[] 每项的字段：

字段 类型 说明
name / path 字符串 文件名 / 所在目录。完整路径 = path + '\\' + name
dateModified 字符串 修改时间（本地化格式文本）
size 数字 文件字节数，原生数字直接用
icon 字符串 base64 图标，<img src> 直饮，无需再调 getFileIcon
score 数字 相关度打分（native 已按分排序）
isDir 数字 1/0 数字而非原生布尔（手拼 JSON 路径），判断用 truthy 或 === 1，不要 === true

本样例调用的接口一览 #

接口 绑定 用途
searchFile(keyword, maxResults) 异步 全盘 MFT 索引搜索，支持 Everything 语法（size:>100MB、ext:mp4、!ext:tmp）
openFile(path, admin) 同步 打开文件/目录（shell 默认行为），admin=true 时以管理员权限
openFileLocation(path) 同步 在资源管理器中定位到该文件
getConfig(key?) 同步 读配置：缺省全量、传 key 只取该键（支持 a.b 点路径）
setConfig(patch, replace?) 同步 窄粒度写搜索历史：setConfig({ sdk_sample: { history } })；replace=true 整体替换（仅导入备份用）
log(message) 同步 前端日志，写入主进程日志，便于排查
windowControl(name, action) 同步 窗口最小化/最大化/关闭/拖动

调用规范（四条铁律） #

import ZenAPI from './lib/zen_api.js';

// 1. 判错用 isOk()（error 恒为数字：0 成功，-1 表示调用异常）
const res = await ZenAPI.searchFile('yyztools', 200);
if (!ZenAPI.isOk(res)) { ... }

// 2. 接口返回的布尔字段是原生布尔，直接判断
//    （例外一：config 的值由前端写入决定类型，通常是字符串，比较时注意归一）
//    （例外二：searchFile 结果的 isDir 是 1/0 数字——手拼 JSON 路径，用 truthy 或 === 1）
const ex = await ZenAPI.exists(path);
if (ex.exists === true) { ... }

// 3. 配置写入必须窄粒度，禁止全量回写
await ZenAPI.setConfig({ sdk_sample: { history } });   // 只写自己的键

// 4. 按 id 批量取应用信息用 getAppInfo，禁止循环 searchApp
const infos = await ZenAPI.getAppInfo(['calculator', 'ocr']);

异步接口（getAppInfo / searchFile / 媒体五件套 / ocrRecognition）在后台线程执行，注意同一时刻仅有一个媒体子进程在跑，长时间任务要提供 cancelRun() 取消入口。

常用接口速查（样例之外的更多能力） #

场景 接口
读/写自己的配置 getConfig / setConfig（窄粒度 patch）/ addConfig（追加列表项）
打开/另存文件 browseFile / browseDir / writeFile / readFile（>50MB 用 readFileChunk）
获取系统目录 getKnownDir('download') 等
打开网页/外部程序 runAny('https://...', '')
复制到剪贴板 前端 navigator.clipboard（文本场景无需 native）
截图/OCR screenCap('fast', ...) → ocrRecognition(base64)（均异步）
调起其他模块窗口 windowControl('translate', 'show')

四、创建 .zenmod 模块文件（窗口宿主） #

在 Modules/<分类>/ 下新建 .zenmod（样例文件：sdk/sample/Modules/SDK_Sample.zenmod）：

{
    "id": "sdk_sample",
    "type": "web",
    "name": { "zh_cn": "SDK样例工程", "en": "SDK Sample Project", "...": "共 12 门语言" },
    "desc": { "zh_cn": "基于 MFT 索引的全盘急速文件搜索，支持 Everything 语法", "en": "..." },
    "icon": "fas fa-search",
    "winClassName": "yyzTools::SdkSampleWindowClass",
    "width": 760,
    "height": 540,
    "layoutType": 34,
    "url": "SDK_Sample/index.html",
    "preCreate": 0
}

字段说明（type:"web" 时主程序读取的全部字段）：

字段 必填 说明
id 是 全局唯一。同时是 windowControl/windowState 的窗口名、快捷键 appId、dock 挂载 id
type 是 固定 web
name 是 12 语言对象；也允许纯字符串写法（仅建议内部测试用），取值回落：当前语言 → en → 纯字符串
desc 否 同上
icon 否 FontAwesome class（如上）或 base64 图片
winClassName 否 Win32 窗口类名，全局唯一即可
width / height 否 初始窗口尺寸，默认 800x600
layoutType 否 初始位置布局位掩码，34 = 水平居中 + 垂直居中
url 是 相对 Web 根目录的页面路径（SDK_Sample/index.html）；也支持 http(s) 开头的在线地址
preCreate 否 1 = 启动时预创建窗口（加快首次打开），默认 0 按需创建
canSuspend 否 1 = 允许窗口隐藏时挂起 WebView 省资源（默认 1）

改完自查：JSON 可解析、UTF-8 无 BOM、id 全局唯一、12 门语言均非空。

至此应用已完成——按第一节复制两个目录，命令面板搜索"SDK样例工程"或"sdk"即可启动（拼音索引自动生成），windowControl('sdk_sample', 'show') 也能唤起它。

五、多语言文案（字典方式） #

免构建方案用普通 ES module 字典即可（i18n.js）：

const messages = {
    zh_cn: { title: 'SDK样例工程', results: '{{count}} 个结果，耗时 {{ms}} ms', ... },
    en:    { title: 'SDK Sample Project', results: '{{count}} results in {{ms}} ms', ... }
};
export function getMessages(lang) { return messages[lang] || messages.en; }
export function interpolate(dict) {
    return (key, params) => { /* {{count}} → params.count */ };
}

初始化时读 getConfig().language 选语言，查不到回落 en；带占位符的句子用 tf('results', { count, ms }) 展开。

注意：

  • 语言码用下划线小写风格（zh_cn），与 .zenmod 一致，不是 BCP47。

  • .zenmod 的 name/desc 必须 12 门语言齐全；页面内文案没有强制要求，样例只给 zh_cn/en，按需扩展。

  • 需要跟随界面语言即时切换的模块，可把字典改为按需 import() 懒加载多语言文件，机制与本文相同。

六、调试与集成 #

1. 免构建直接跑（推荐起步）：
   复制 sdk/sample/Web、sdk/sample/Modules 到 bin64\（Release exe 所在目录），重启 exe。
   改前端后 windowControl('sdk_sample','close') 再打开，或重启 exe 生效。

2. 浏览器看结构：
   直接双击 Web/SDK_Sample/index.html 用浏览器打开。
   浏览器里没有 window.Zen，ZenAPI.call 会走异常路径返回 error: -1，
   页面结构 / 样式 / 输入防抖 / 渲染逻辑均可正常调试（原生接口除外）。

搜索性能提示：searchFile 走 C++ 侧 MFT 全盘索引，通常毫秒级返回；native 有搜索槽机制——新请求会顶掉未完成的旧请求（旧的返回空结果），前端配 300ms 防抖 + 递增序号丢弃乱序回包，连续击键也不会打爆后台线程或闪烁旧结果。结果图标（base64）由 searchFile 顺手带回，无需额外调 getFileIcon。

接口能力不够用时（例如需要新的 C++ 能力），可通过官网反馈渠道提出需求，由主程序在后续版本扩展接口。

八、安全须知 #

Native API 面向模块开发者完整开放宿主进程的系统能力，其中包含文件读写与删除、进程创建与终止、窗口控制、剪贴板读写、系统设置修改、命令行执行等高危操作，且不设权限弹窗、不做沙箱隔离、不提供撤销机制。

调用前请自行评估每一次操作的安全性：校验一切外部输入，涉及不可逆操作前先备份或请用户确认，并只使用功能真正需要的能力。由此造成的一切后果由开发者自行承担。
